## 用户目标与变更

产品从 Chat+Agent 收敛为纯 Agent 桌面端。Windows 当前必须原生运行；macOS 每阶段同步草案但无真机时保持 `UNPROVEN`。前端继承 Viniper 的安静、直观和功能入口，可做克制优化；后端继续使用项目自建 Runtime，不接入 Claude Code、Codex 或其他 Agent 框架。

当前产品版本固定为 `0.0.1`，阶段固定为 `Preview / 预览版`。它尚未进入 Beta、公测、RC 或正式发布；本轮只能描述为预览版内部更新。

所有生产功能必须按 `DESIGN.md` 的 Feature Folder Contract 分类，并通过 Git 逻辑提交保持可追溯。分类以稳定功能域为粒度，不做机械化的一函数一目录。

## 本轮结果目标

1. 删除 Chat 模式、模式切换和隐藏 Chat 状态机；窗口打开即为 Agent 工作区。
2. 原生窗口具备 Agent 会话侧栏、主对话、Composer、模型/权限入口、状态轨道、按需活动检查器和设置中心。
3. 自建 TypeScript Agent Runtime 只通过 preload/IPC 被界面调用；Demo Provider 走正式 `ModelProvider` 接口并产生流式事件及一个只读 Demo 工具事件。
4. 会话创建、切换、重命名、置顶、删除和重启恢复可用；发送、排队、取消形成最小闭环。
5. Provider Registry 和 CachePlan 保持正式接口；设置页展示 OpenAI、Anthropic、Gemini、DeepSeek、OpenAI-compatible 的配置占位与能力状态，但不真实调用、不保存密钥。
6. 生产源码重组为 `core / features / platform / renderer`，功能与测试按稳定域分组；不保留承担多类业务规则的巨大入口文件。
7. Windows Electron 原生启动，在常见大窗与 960×720 窄窗观察；更新 macOS 差异草案并保持 `UNPROVEN`。
8. 在本地 Git 形成可读的逻辑提交，分别追踪需求基线、版本阶段、纯 Agent 实现和验证交付。不得上传远端，不写或报告哈希/SHA256。
9. `package.json` 使用版本 `0.0.1`；应用标题与设置/关于信息显示 `v0.0.1 · Preview（预览版）`，报告不得使用公测或正式发布措辞。

因版本阶段决策发生在首个提交之后，Git 调整为四个可读逻辑提交：`需求与目录基线`、`固定 v0.0.1 Preview 阶段`、`纯 Agent 纵切`、`验证与交付文档`。保留既有首个提交，不改写历史。

## 目录与依赖边界

```text
src/core
src/features/{sessions,runs,queue,permissions,tools,providers,cache,settings}
src/platform/{desktop,persistence}
src/renderer/{shell,sessions,conversation,composer,activity,settings,styles}
tests/{sessions,runs,providers,cache,persistence,ui-contract}
```

- `core` 不依赖 Electron、DOM 或具体 Provider。
- 功能域通过明确入口或 core 合同协作，不跨目录读取内部实现。
- renderer 只消费 canonical snapshot/event，不直接调 Provider 或复制权限、队列、工具状态机。
- desktop/preload 只暴露窄 IPC API；persistence 不决定产品语义。
- 第一阶段工具仅为项目内只读 Demo 工具；禁止任意 shell、写文件、真实密钥和付费 API。

## A/B 验收矩阵

- A1 纯 Agent：界面、领域类型、IPC 和持久化中均不存在 Chat 模式或模式切换。
- A2 核心壳：会话、Composer、模型、权限、设置、置顶和活动检查入口可达。
- A3 会话隔离：两个 Agent 会话的消息、运行状态和队列不串线。
- A4 目录边界：生产文件位于规定功能域；跨域依赖没有反向穿透或 UI 业务真源。
- B1 Demo 链路：发送 -> IPC -> Runtime -> Provider stream -> canonical events -> Conversation/Inspector。
- B2 队列与取消：运行中第二条输入排队；取消后当前 run 终止并可继续后续输入。
- B3 恢复：重启或重载后会话和消息从项目自有数据目录恢复。
- B4 缓存计划：system/tool/project 稳定段位于可复用前缀，当前轮追加；界面显示复用/新增上下文 Demo 指标。
