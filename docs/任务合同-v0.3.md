## 结果目标

### R1 多会话真实并行与隔离

- 同一会话仍串行执行自身队列；不同会话可同时运行，各自可取消、排队、失败和完成。
- 不允许一个会话的消息、活动、Token、队列、AbortSignal、Provider 错误或 Skill 快照污染另一个会话。
- UI 的“协作星图”显示会话节点、`idle/running/queued/waiting/failed`、未读和最近协作方向；这只是 canonical state 的消费者。

### R2 跨会话消息、委派与等待

- 建立追加式 `CoordinationEnvelope`，至少支持 `message/delegation/result`，以及 `sent/delivered/read/completed` 状态。
- 用户可从 A 向 B 发消息；B 收件箱可读，A/B 普通对话历史仍不互通。
- 用户可从 A 向 B 委派一条任务；B 使用自己的模型、权限、工作目录、Skills 和队列执行，完成后结果信封回到 A。
- A 可显式“等待消息/委派结果”，显示等待对象与可取消入口；等待不能占用 Provider 并发，也不能冻结其他会话。
- 公开窄 API 至少覆盖 sendMessage、delegateTask、waitForMessage/cancelWait、markRead。禁止 renderer 直接改信封状态。

### R3 Token 脉搏与缓存对账

- 定义 Provider-neutral usage：input、cacheHitInput、cacheMissInput、output、reasoning、total、source(`estimated/provider`)。
- 流式阶段以节流方式显示明确标注的“约”输出 Token；完成时用 Provider usage 原位对账。没有 Provider usage 时保留估算并显示“未对账”。
- 支持 current run、session cumulative、app cumulative；每个会话完全隔离。
- Demo Provider 发出确定性 usage 事件供真实 UI/测试；DeepSeek 适配器解析最终 usage 和缓存命中字段。
- CachePlan 使用稳定 `ContextProfile`：system -> tool schemas -> project -> enabled Skills -> conversation -> current turn。会话运行中改变 Provider/模型/工具/Skill 必须被拒绝或明确排队到下一代 profile。

### R4 自动任务

- 支持 `once / interval / daily / weekly`，字段最少包含名称、prompt、schedule、target、enabled、nextRunAt、lastRunAt。
- target 支持投递到现有会话，或每次新建隔离会话；所有触发仍走 AgentRuntime。
- UI 支持新建、暂停/恢复、立即运行、删除和查看最近历史；简单表单优先，高级频率折叠。
- 使用可注入 clock/timer 测试：到点只执行一次、暂停不触发、重启定义恢复、错过触发不产生补偿风暴、失败可见。
- 本阶段明确显示“应用运行时执行”；不得伪装为退出应用后仍工作的系统服务。

### R5 Skills 与插件底座

- Skill 包包含必需 `SKILL.md`，可有 scripts/references/assets；目录扫描只读取名称/描述/元数据，启用时再读取完整正文。
- 至少提供一个项目内置 Skill，使 Demo Provider 的响应能证明该 Skill 的完整正文已按需进入 ContextProfile；UI 可搜索、查看、启用/停用。
- Plugin manifest v1 声明 id/name/version/capabilities/skills/tools/providers；严格区分 built-in、external-declarative、invalid。
- 至少提供一个内置 coordination plugin，把会话消息/委派能力注册进 ToolRegistry，并有可执行的本地 Demo 合同。
- 外部声明式插件可发现和校验，但未知 JS/Python/二进制代码不得执行；UI 必须清楚显示该边界。
- Skill/插件变更在会话运行中不得偷偷改变 tool schema；默认下一次运行或新会话生效。

### R6 DeepSeek 接入位与安全密钥

- 新增 `SecretVault` 端口与 `platform/security` 实现，使用 Electron `safeStorage` 加密保存。秘密文件位于 Preview 专用 userData，不进入项目仓库。
- Renderer 的 SecretField 只能提交新值、删除和查询 configured 状态；任何 snapshot、IPC 返回、日志、错误和 UI 均不得回显明文或部分明文。
- Provider 设置允许保存/删除 DeepSeek Key、选择 base URL、执行 `/models` 无生成连接测试；本轮只用本地 fake HTTP/SSE 验证接口，不访问公网。
- DeepSeekProvider 支持 SSE、keep-alive 注释、文本/思考增量、函数工具调用的边界、最终 usage、取消与 401/402/429/5xx 分层。默认模型来自连接后 `/models`，不以历史别名作为唯一选项。
- 在 Key 未通过应用 UI 配置时，真实 Provider 不可选，发送按钮给出简单说明；Demo 始终明确标注本地。

### R7 属于自己的桌面前端

- 保留 Phase 1 安静三栏和初学者主路径；新增品牌特征“协作星图 + Token 脉搏条”，不做赛博大屏。
- 大窗右侧在“活动/协作”切换；窄窗星图压缩成会话状态条，协作/自动任务/扩展进入抽屉或全宽 dialog。
- 设置拆分为 Provider、自动任务、自定义与关于；首次使用仍可三步完成。
- 所有状态有文字与 ARIA，不只依赖颜色；流式 Token 不逐字播报，动效支持 reduced-motion。

## 数据、迁移与 Git

- Phase 1 `sessions.json + events.ndjson` 必须向前迁移；旧 Preview 数据可恢复，新增数据有 schema 版本和最小迁移测试。
- 协作信封、usage ledger、schedule definitions/history、extension metadata 与 secret references 分开持久化；秘密本体不进入普通 snapshot/event journal。
- 所有临时日志、截图、本地假服务输出进入 `D:\Agent\codex\运行残留` 或 `codex\审查报告`；不得散落项目根。
- 使用可读逻辑提交，至少区分“架构合同”“协作与遥测”“调度与扩展”“DeepSeek安全接入”“Windows验证交付”。不上传远端，不报告哈希/SHA256。

## A/B 验收矩阵

- A1 Phase 1 回归：纯 Agent、会话 CRUD、同会话队列/取消、恢复、Demo 工具、版本阶段和设置入口继续通过。
- A2 并行隔离：两个不同会话的延迟 Provider 同时处于 running，总耗时证明非全局串行；取消 A 不影响 B。
- A3 协作闭环：A -> B 消息、委派、B 执行、B -> A 结果、A 等待解除；双方普通历史不互通。
- A4 秘密边界：静态扫描和测试证明 Key 不在 Git、snapshot、journal、IPC 返回、UI DOM、错误或日志；safeStorage 不可用时 fail closed 并给用户说明。
- B1 Token：流式估算可见，最终 usage 对账准确，cache hit/miss 和 reasoning 不丢失，会话累计不串线。
- B2 Scheduler：一次/重复、暂停、立即运行、恢复和历史通过 fake clock；Windows 真窗口观察一次近未来触发。
- B3 Extensions：Skill 渐进加载前后有可观察差异；内置 coordination plugin 可执行；无效/未知插件不进入工具注册表。
- B4 DeepSeek local contract：本地 fake `/models` + SSE 覆盖成功、keep-alive、usage、工具调用边界、取消和代表性错误；真实 API 保持 `UNPROVEN`。
- B5 UI：Windows 原生窗口在约 1440×900 和 960×720 观察星图、Token、协作、自动任务、Skills/插件与 Provider SecretField；无横向溢出和关键入口丢失。
- B6 macOS：更新差异草案，检查无 Windows 路径/PowerShell/DPAPI 语义泄漏到 core；无真机仍为 `UNPROVEN`。
