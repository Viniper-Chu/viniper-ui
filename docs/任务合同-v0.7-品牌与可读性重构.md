# 任务合同：Viniper Harness 品牌与可读性重构 v0.7

发布方：Codex 管理层  
发布对象：Codex 执行层  
状态：PARTIAL_ACCEPTED / BLOCKED_LOCAL_OPENAI_KEY
版本边界：产品仍为 `v0.0.1 · Preview（预览版）`，本轮只是预览版内部更新，不是 Beta、公测、RC 或正式版。

## 1. 任务目标

在不改变独立 Harness 架构、Provider/CLI 协议和既有功能闭环的前提下，完成一次明确的视觉重构：提高所有常用文字的可读性，重新安排 Token 用量入口和左侧历史记录，压缩过大的按钮，并把桌面端与 CLI 的可见品牌统一为 **Viniper Harness**。

本轮视觉只借鉴 Codex 与 Claude Code 的信息密度、会话侧栏和按需 usage 入口；不复制其商标、插画或逐像素外观。色彩只借鉴“巳月仙人模式”给人的冷青、冰薄荷与深蓝黑氛围，不出现动漫角色、蛇、官方符号或其他受保护图形。

## 2. 权威参考与事实边界

- 用户 2026-08-12 的五项新要求是本轮最高视觉方向，取代 `docs/视觉参考/平静指挥台-批准稿-1440x900.png` 作为当前目标；旧图只作为改版前证据。
- OpenAI 官方 Codex App 说明把桌面端定位为多 Agent 的 command center，并以独立任务/会话承载并行工作。
- Anthropic 官方 Claude Code Desktop 说明使用会话侧栏管理并行任务，并把 usage ring 放在模型选择器旁；点击后查看当前会话的 context window 用量。
- 官方资料不规定可直接照搬的 CSS 像素值。下列字号是结合 Windows 桌面可读性和用户反馈制定的 Viniper Harness 自有设计令牌，不冒充厂商规范。
- `gpt-image-2` 品牌图标当前状态为 `BLOCKED_LOCAL_OPENAI_KEY`：本机没有 `OPENAI_API_KEY`，不得用 DeepSeek Key 替代，也不得把其他图像模型生成结果冒充为 image2。界面先接入可替换的代码原生 V 标记和正式资产槽位。

## 3. 必须交付

### R1 品牌统一

- 桌面标题、侧栏、关于卡片、CLI 欢迎语/帮助标题/锁提示等用户可见名称统一为 `Viniper Harness`。
- 版本始终显示 `v0.0.1 · Preview（预览版）`。
- 内部数据目录 `Agent Desktop/Preview-0.0.1` 可作为兼容路径保留，避免静默丢失既有预览数据；若保留，代码必须注明是兼容别名，不向用户显示旧品牌。
- 品牌位使用独立的 V 图标容器。没有 gpt-image-2 资产前，以简洁的代码原生 V 单字标记作为 `PENDING_IMAGE2_ASSET` 占位；不得伪造“已由 image2 生成”。

### R2 桌面端字体与密度

- 常用正文与执行内容：`15px`，行高约 `1.55–1.7`。
- 会话标题、导航、按钮、表单标签：`13–14px`。
- 次要元数据、时间、badge：通常 `12px`；生产可见文字不得低于 `11px`。
- 主标题建议 `20px`，页面/空态标题 `24–28px`；Token 核心数字 `22–28px`。
- Windows 首选 `Segoe UI Variable`；中文使用系统无衬线回退；Token 和数值启用等宽数字特性。
- 清除当前大量 `7–10px` 的正文、导航、按钮和设置页文字。只有纯装饰性、非必要微标签允许 `11px`。

### R3 原创冷青配色

统一使用下列语义色，桌面和 ANSI CLI 共用含义：

- 画布：`#F4FAF9`
- 表面：`#FFFFFF`
- 浅冰青：`#E6F5F7`
- 浅薄荷：`#DDF5EF`
- 主青：`#168A91`
- 亮青：`#22B8B5`
- 深青：`#116B73`
- 深蓝黑文字：`#15343B`
- 次级文字：`#5E7478`
- 分隔线：`#D7E7E5`
- 等待状态可用低饱和冰蓝紫；错误仍使用独立红色，不能把所有状态都染成青色。

主按钮必须以深青保证白字对比；大面积背景只用浅冰青/白，不做霓虹、发光赛博大屏或动漫主题皮肤。CLI 彩色模式用 cyan/bright-cyan/teal 近似；`--plain` 不输出 ANSI，`--jsonl` 内容和字段完全不受配色与品牌装饰影响。

### R4 左侧历史记录

- 会话历史每行使用一个**等宽短横杠**作为状态标记，不再使用圆点、圆形头像或不同宽度图形。
- 所有短横杠视觉宽度一致，建议 `18px × 3px`，以颜色/透明度表达 running、waiting、failed、idle；同时保留文字状态，不能只靠颜色。
- 会话行高度建议 `48–54px`，标题 `14px`、元数据 `12px`，行间距均匀。
- 侧栏按“正在进行 / 最近”或等价简单分组，不增加复杂筛选器；当前会话用浅冰青底或细边框突出。

### R5 Token 用量入口与页面

- 移除把 Token 作为常驻密集仪表盘的视觉做法。
- 在 Composer 的模型选择器旁增加紧凑 usage ring/pill；点击后打开独立的 Token 用量 popover、抽屉或对话层。
- 用量层必须清楚分成：
  1. 当前会话 context 使用量/容量（容量未知时写“上限未知”，不伪造百分比）；
  2. 当前运行的实时估算；
  3. Provider 最终返回的实际 input/output/total；
  4. cache read/write/miss 或“Provider 未返回”；
  5. 当前会话累计。
- “约/估算”和“实际/Provider 返回”必须在同一视图中明确区分；未知值显示“未提供”，不能当 0。
- 不提供订阅周期/账户套餐 usage，除非对应 Provider 明确返回；当前写“此 Provider 未提供账户周期用量”。
- Token 层关闭后焦点回到 usage 触发器，支持 Escape，ARIA 标签为人话。

### R6 按钮重构

- 移除视觉上笨重的整栏大色块按钮。主要操作高度 `36–40px`，普通/图标按钮 `32–36px`。
- “新建 Agent”可保留为主要操作，但使用紧凑圆角矩形、细描边或克制填充，不使用厚重阴影和过宽渐变。
- 次要操作采用 ghost/outline；每个区域最多一个强调按钮。
- 输入框发送按钮保持明显但不抢过输入内容；禁用、悬停、键盘焦点均可辨认。

### R7 桌面与 CLI 一致而不互相套壳

- 桌面端仍是独立 Harness UI，不嵌入终端壳。
- CLI 继续使用同一 Harness application port，不允许启动或驱动桌面 DOM。
- CLI 只调整品牌、青色语义和可读的标题/提示；命令语法、plain/jsonl 协议和退出码保持兼容。

## 5. 验收门槛

1. `npm run typecheck`、clean build、完整测试全部通过；既有 72 项不得回退。
2. Windows 真窗口至少观察 `1440×900` 与 `960×720`：无遮挡、无水平溢出、常用文字清楚、按钮不笨重、Token 层可打开/关闭。
3. 计算样式抽查：常用正文 `>=14px`、导航/按钮 `>=13px`、元数据 `>=11px`；若例外必须在报告逐项说明。
4. 左侧至少两个会话可见，短横杠等宽；运行/等待/失败状态同时有文字或可读标签。
5. Token 视图分别验证估算态、Provider 实际态、缓存未知态；不把未知值渲染为 0。
6. `--plain` 无 ANSI；`--jsonl` 每行仍可解析；默认 CLI 可见品牌为 Viniper Harness 且主色为 cyan/teal。
7. 全项目搜索用户可见旧品牌；允许的内部兼容路径和历史文档必须列入报告，不能笼统宣称“全部消失”。
8. 使用 Visual Ralph 对新方向做 Windows 大窗/窄窗审查；目标是字体层级、会话短横杠、usage 入口、按钮密度和青色语义与本合同一致。旧 92 分不继承。
9. 最终 Electron/CLI 进程为 0，Git CLEAN；提交使用可读中文标题，不上传、不改写历史。

## 6. 明确不做

- 不更改 Provider 请求协议、缓存算法、会话隔离和调度语义。
- 不接触真实公网 API，不使用用户曾在聊天中粘贴的密钥。
- 不宣称 macOS 已运行；仅同步更新 macOS 视觉草案。
- 不在缺少本机 OpenAI Key 时生成或伪造 gpt-image-2 图标。
