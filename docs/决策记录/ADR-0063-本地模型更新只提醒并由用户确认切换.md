# ADR-0063：本地模型更新只提醒，并由用户确认下载与切换

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

完全不检查更新最稳定，却容易长期使用过时模型；自动替换最省步骤，但会改变输出、工具能力、磁盘占用和任务复现条件。用户选择方案 B：Viniper 可以发现并提醒本地模型的新版本，但下载、安装和切换都必须由用户明确确认，原版本保留到用户主动删除。

## 决策

### 更新只发现和提醒

- 只有来源提供可比较的版本/修订元数据时才检查更新；本地文件或无法确认版本的自定义来源显示“无法自动检查”，不猜测更新状态。
- 更新检查可以随本地模型目录的用户刷新或常规目录刷新执行，但不得在后台自动下载、替换或切换模型权重。
- 提醒必须显示当前版本、新版本、来源、预计新增体积、许可变化和已知能力变化；信息缺失时明确标为未知。

### 下载与切换是两个确认动作

- 用户确认下载后，新版本作为独立安装项进入受管模型库，不覆盖正在使用的文件。
- 下载完成后继续使用当前版本，直到用户明确选择“切换到新版本”；切换只影响未来 run，活动 run 始终使用冻结的模型、运行器和量化版本。
- 用户可以切回仍保留的旧版本。删除任何版本都是独立手动动作，不因切换成功或磁盘压力自动发生。
- 如果新版本探测失败或不兼容，当前版本保持不变，界面给出失败原因和清理新下载的入口。

### 与智能分配和桌面/CLI一致

- 智能分配只把用户当前启用的具体本地版本作为候选，不因发现更新自动改变候选集。
- 桌面端与 CLI 通过同一 Runtime 所有者看到相同的更新、下载、版本选择和活动 run 快照。
- 更新提醒不读取模型价格，也不把本地模型标记为“免费”；用量仍只记录 Token、缓存、请求和耗时。

## 产品表现

- 模型卡片显示“有更新”，但主按钮为“查看更新”，不是自动安装。
- 更新详情按“下载新版本 → 验证可运行 → 用户切换”展示，当前版本始终可见。
- 磁盘不足时只提示所需空间和可手动删除的版本，不代替用户清理权重。

## 收益

- 用户可以获知更新，同时保持任务复现和输出稳定。
- 新旧版本并存使切换和回退清楚可控。
- 更新失败不会破坏当前可用模型。

## 代价

- 新旧版本并存会暂时增加磁盘占用。
- 用户需要完成查看、下载和切换操作。
- 部分本地文件或自定义来源无法提供可靠更新提醒。

## 与既有决策的关系

- 复用 ADR-0047 的“能力更新需用户确认”精神，但本 ADR 专门管理模型权重与具体版本，不把模型伪装成扩展。
- 细化 ADR-0058/0062 的本地模型生命周期，并保持 ADR-0028 的 run 固定模型合同。
- 本 ADR 是后续目标设计；更新发现、双版本并存、确认切换和失败保留当前版本均为 `UNPROVEN`。
