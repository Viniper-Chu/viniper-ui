# ADR-0036：开放公共扩展市场与直接安装

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

只提供官方整理目录最容易控制体验，但会把生态入口锁在单一发布方；仅支持手工导入又不利于普通用户发现和更新扩展。用户选择方案 B：允许从公开扩展市场直接安装，不要求扩展先进入 Viniper 官方整理目录。

## 决策

### 不设官方目录准入门槛

- 扩展中心可以搜索和浏览多个公开市场或注册表，并支持从公开包地址、公开仓库发布页和本地包直接安装。
- 用户可添加自定义公开市场源；Viniper Harness 不以“是否进入官方精选目录”作为唯一安装资格。
- 市场适配器只负责获取名称、版本、作者/发布者声明、说明、包地址和能力摘要，不把某市场的评分、热门度或上架状态冒充 Viniper 的安全背书。
- 官方精选、社区来源和自定义来源可以作为清楚标签共存，但搜索、排序和安装能力不能只开放给官方精选。

### 直接安装仍分为获取、检查、信任和启用

- 用户点击安装后，包先进入数据根的受管暂存区；Harness 读取清单、类型、入口、版本和声明能力，在任何可执行代码加载前显示安装信任页。
- 公开市场页面、搜索结果、说明文件和下载动作本身不能注册工具或执行脚本。只有用户确认安装与信任后，Skill、MCP 或可执行插件才按 ADR-0029 进入对应层。
- 清单缺失、类型无法识别或入口与声明不一致时停止安装并说明原因；不为追求“一键安装”猜测执行入口。
- 市场安装、公开直链和本地包使用同一信任页、权限注册、受管进程与审计合同，没有隐藏的“市场包自动可信”通道。

### 来源与更新

- 每个扩展记录实际来源类型、市场/地址、发布者声明、安装版本、安装时间和当前信任状态；来源无法独立确认时明确标为“公开来源，未经 Viniper 核验”。
- v0.0.1 按 ADR-0047 禁止所有 Skill、MCP 和插件静默更新。发现新版本时先展示变更并等待用户确认；入口、可执行内容、权限或外部目标变化时还必须重新确认信任。
- 用户可以固定版本、停用来源或移除某个市场；移除市场不自动卸载已安装扩展，卸载也不顺带删除用户成果或扩展数据。
- 市场不可用不影响已经安装且仍满足信任合同的扩展；离线时不得把旧目录缓存伪装成当前最新状态。

### 运行边界不因开放市场降低

- Skill 脚本仍按可执行工具处理，MCP 仍需显式配置连接，可执行插件仍在受管子进程中运行。
- 项目完全访问和电脑完全访问可以影响已信任工具的逐次批准，但都不能自动安装、信任或启用一个仅在公开市场被发现的扩展。
- 扩展获得的文件、网络、进程和外部服务能力继续由清单、统一权限状态机和运行回执表达；开放来源不等于无限权限。

## 产品表现

- 扩展中心统一提供“精选 / 公共市场 / 自定义来源 / 本地包”，默认搜索可以覆盖用户已启用的全部来源。
- 列表卡显示来源和是否经 Viniper 核验；安装页用人话说明“它会读取什么、是否联网、是否启动进程、连接哪个账号”。
- 安装完成只表示扩展已注册；首次实际工具调用仍按当前任务权限执行。

## 收益

- 用户不必等待 Viniper 官方收录，就能使用公开生态中的 Skills、MCP 和插件。
- 普通用户获得搜索与一键获取体验，高级用户仍可使用直链、自定义市场和本地包。
- 开放发现与显式信任分开，保留 ADR-0029 已确定的运行边界。

## 代价

- 不同市场的包格式、元数据质量和可用性差异需要适配。
- 公开市场上架不能保证扩展可靠，用户需要看一次来源和能力说明。
- 多来源更新、版本固定和失效处理比单一官方目录复杂。

## 与既有决策的关系

- 解决 ADR-0029 留下的分发来源问题，并完整保留其分层信任、受管子进程和完全访问不能自动信任未知插件的规则。
- ADR-0047 决定全部扩展更新均需用户确认；开放来源和版本发现不会产生自动安装授权。
- 包和下载缓存属于 ADR-0032 的受管文件，安装、版本和信任状态属于结构化真源。
- 本 ADR 是后续目标设计，当前公共市场搜索、直接安装和真实第三方插件运行均为 `UNPROVEN`。
