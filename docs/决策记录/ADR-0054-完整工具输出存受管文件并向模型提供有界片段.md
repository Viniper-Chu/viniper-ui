# ADR-0054：完整工具输出存入受管文件并向模型提供有界片段

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

把完整工具输出全部放进数据库和模型上下文会迅速放大存储、Token 和缓存抖动；截断后丢弃剩余内容又无法排错或复核。用户选择方案 C：完整输出保存为受管文件，SQLite 保存结构化摘要，模型只接收完成任务所需的有界片段。

## 决策

### 完整输出进入受管文件

- 工具执行时把允许持久化的 stdout、stderr、结构化结果或二进制产物流式写入该 run 的受管输出目录，避免先在内存中累积整个结果。
- SQLite 保存工具、run、输出类型、受管相对路径、大小、行数或记录数、开始/完成时间、完整性状态和面向 UI/模型的结构化摘要。
- stdout 与 stderr 保持可区分；结构化 JSON 等结果保留原格式，图片、PDF、压缩包等二进制只作为文件引用，不编码成数据库大字段。
- 写入中断或磁盘失败时标记 `incomplete`，UI 与模型都不能把摘要冒充完整输出。

### 模型只接收有界投影

- `ToolResultProjector` 根据模型上下文容量、当前 run 预算、工具类型和结果结构选择必要片段，不使用一个对所有模型固定的字符上限。
- 默认优先提供错误摘要、关键结构化字段、匹配行及适量开头/结尾；不相关重复行留在文件中，不进入稳定缓存前缀。
- 模型需要更多内容时，只能通过受控只读工具按行、记录或字节范围继续读取；每次读取仍作为独立工具结果和 usage 事件记录。
- 工具适配器可以提供领域摘要，但不能用摘要替换或删除已经保存的完整允许输出。

### 用户可以查看完整证据

- 时间线默认显示摘要、大小和“查看完整输出”；完整查看器支持搜索、换行、stdout/stderr 筛选和大文件虚拟加载。
- 导出会话或项目时，ADR-0044 的产物清单明确列出是否包含完整工具输出及其体积。
- 完整工具输出按 ADR-0052 归类为运行证据，不进入可再生成缓存的自动清理；用户明确删除所属会话或证据时才处理。

### 秘密与日志边界不变

- “完整”只指经过工具合同允许持久化的完整输出；API Key、访问令牌、私钥、凭据头和 SecretVault 内容不得因为原始工具打印过就写入普通证据文件。
- 既有字段级秘密过滤在持久化前执行，并记录“已移除秘密字段”而不保存明文；renderer、模型上下文、诊断报告和跨会话消息使用同一非秘密边界。

## 产品表现

- 工具卡显示“已向模型提供 42 行 / 完整输出 18,420 行”等真实范围，不把摘要标成完整内容。
- 普通用户只看结果和关键错误；需要排错时可打开完整查看器或让 Agent 读取下一段。
- CLI 人类模式显示摘要与文件入口，JSONL 输出结构化引用，不把超长原文直接冲刷终端。

## 收益

- 保留完整可追溯证据，同时控制模型 Token 和数据库体积。
- 大输出不必一次进入内存或上下文，桌面与 CLI 更稳定。
- 后续排错可以按范围读取，而不是重新执行可能有副作用的工具。

## 代价

- 需要受管流文件、范围读取、摘要和大文件查看器。
- 如果初次投影遗漏关键片段，模型需要额外一次只读工具调用。
- 完整输出作为审计证据会占用磁盘，需由用户明确管理而非自动清理。

## 与既有决策的关系

- 细化 ADR-0032 的大型工具输出文件化设计，并保持 SQLite 只存结构化真源与引用。
- 使用 ADR-0052 的正式/审计保留规则；上下文投影继续遵守 ADR-0040 的压缩和稳定缓存原则。
- ADR-0061 的诊断日志只引用工具输出状态和投影范围，不复制完整工具正文；完整查看继续走本 ADR 的受管文件边界。
- 本 ADR 是后续目标设计；流式落盘、投影准确性、大文件查看和秘密过滤均为 `UNPROVEN`。
