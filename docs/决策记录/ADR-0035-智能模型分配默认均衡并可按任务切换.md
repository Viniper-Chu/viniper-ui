# ADR-0035：智能模型分配默认均衡并可按任务切换偏好

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`
- 修订：ADR-0059 取消价格信号，并将“节省”改为“轻量优先”。

## 背景

ADR-0028 已确定会话固定模型和可选智能分配，但尚未决定开启智能分配后的默认取向。永远质量优先可能增加延迟和资源消耗，永远轻量又可能牺牲复杂任务成功率。用户选择方案 C：智能分配默认使用“均衡”，并允许每个任务改为“质量优先”或“轻量优先”。

## 决策

### 开启智能分配后默认使用均衡

- 智能分配本身继续按 ADR-0028 默认关闭；用户启用后，默认偏好为 `balanced`，界面写“均衡”。
- 用户可在会话默认值、委派任务或单次新 run 开始前选择 `quality | balanced | lightweight`，界面分别写“质量优先 / 均衡 / 轻量优先”。单次任务覆盖不会静默改写会话默认值。
- 偏好只影响尚未开始的 run；模型一旦固定，运行中、Provider 重试和自动审查都不得因为档位变化偷偷换模型。

### 先满足硬能力，再比较偏好

- 路由器先按上下文长度、输入类型、工具调用、结构化输出、推理档位、地区/endpoint 和用户允许的 Provider 等硬条件淘汰不满足的候选；三种偏好都不能选择能力不合格的模型。
- “质量优先”在合格候选中更看重任务匹配能力、已验证质量和稳定性。
- “均衡”综合任务匹配、已知质量、缓存身份、延迟、上下文和当前可用状态；没有一项可以在界面中被伪装成唯一决定因素。
- “轻量优先”在满足任务硬条件的前提下，更看重用户标记的轻量模型、较短推理、较低 Token 消耗和更低资源占用，但不承诺价格更低。
- 能力、质量或状态未知时显示“证据不足”，未知质量不得凭厂商名气自动给高分。

### 本地、透明、可覆盖

- 候选过滤和排序在本地完成，不把完整任务广播给多个模型试跑，也不为路由额外产生隐藏 Provider 请求。
- 路由回执至少显示实际模型、当前偏好、两项主要选择原因，以及被排除候选的关键硬条件。
- 满足能力且差距不明显时，均衡模式优先保持会话模型或相同 Provider/profile/cache 身份，减少缓存重建和数据跨厂商流动。
- 用户可以在 run 开始前固定任意已配置且能力合格的模型；手动固定优先于智能偏好。

## 产品表现

- 模型控制显示“固定：模型名”或“智能分配：均衡”；展开后可选择质量优先、均衡、轻量优先。
- 委派和自动任务卡在排队阶段显示偏好，开始时生成不可变的路由回执。
- 能力或质量资料未知时显示“未提供 / 证据不足”，不展示虚构的小数评分给普通用户。

## 收益

- 默认不会把每个子任务都推向最重或最轻的极端。
- 用户可以按某个任务的复杂度和本机/网络条件快速改变取向，而不必逐个研究模型参数。
- 路由仍保持本地、可解释，并保护固定模型和缓存边界。

## 代价

- 需要持续维护第一方能力、上下文和可用状态元数据。
- 均衡不是绝对最优，信息不足时必须诚实显示不确定性。
- 不广播试跑意味着路由依据的是已知元数据和历史证据，而不是每次让多个模型现场竞争。

## 与既有决策的关系

- 细化 ADR-0028 的“质量 / 均衡 / 轻量”偏好；不改变会话固定模型、run 锁定和禁止静默换模。
- ADR-0053 要求成功刷新中消失的模型立即退出智能候选；目录刷新失败不能把候选误判为空或触发换模。
- ADR-0059 禁止路由抓取或显示模型价格；路由产生的 Token 与缓存影响仍由统一账本记录。
- 本地模型只有在用户允许其进入候选且实际能力满足时才参与；ADR-0064 的实验工具模拟默认不作为原生能力，ADR-0065 的本地推理名额不足只进入可见排队。
- 本 ADR 是后续目标设计，当前三档路由和真实多 Provider 选择证据均为 `UNPROVEN`。
