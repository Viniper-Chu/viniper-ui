# ADR-0023：Provider 临时错误最多尝试五次

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

模型 Provider 可能出现限流、短暂服务错误、超时或网络波动。立即失败会让可恢复问题频繁打断任务，对所有错误快速重试又可能加重限流、重复计费或重放外部操作。用户选择方案 C，并把上限从建议的 3 调整为 5。

为避免“最多 5 次”在实现中变成首次请求外再重试 5 次，本决策统一定义为：每个逻辑 Provider 请求总尝试最多 5 次，包含首次请求，即最多自动重试 4 次。

## 决策

### 可自动重试的情况

只有在尚未收到首个语义响应事件时，以下规范化错误可以自动重试：

- Provider 明确标为可重试的限流或临时不可用；
- 临时服务端错误；
- 请求超时、连接中断、DNS 或网络暂时不可用；
- Provider 明确给出重试等待提示的其他临时错误。

HTTP 状态码只是适配器判断依据之一；同为限流状态也可能代表硬配额或余额不足，必须先映射成统一错误类别，不能只看数字盲目重试。

### 不自动重试的情况

- 认证或权限失败；
- 无效请求、上下文过长、不支持的参数或模型不可用；
- 余额不足、硬配额耗尽或账号被限制；
- 用户主动取消；
- 已经收到文本、推理片段、结构化输出或工具调用等首个语义事件；
- 已经执行本地/远程工具，或外部动作结果未知。

流式响应已经开始后中断，当前活动 Runtime 内保留现有内容并标记“结果不完整”，不得把整个请求作为在线传输重试自动重放。若进程随后崩溃且该轮没有完整持久化结果，下次 Runtime 按 ADR-0042 的崩溃恢复规则重放中断步骤；这是新的恢复尝试，不计入本次在线 5 次上限。

### 尝试次数与等待

- 尝试编号统一显示为“第 1/5 次”到“第 5/5 次”。
- Provider 提供明确等待时间时优先遵循，并显示倒计时。
- 未提供等待时间时，在四次重试前依次等待约 2、4、8、16 秒，并加入少量随机错峰。
- 等待期间状态为“等待 Provider”，用户可以取消。
- 第 5 次仍失败后停止，不开始第 6 次，也不静默切换 Provider 或模型。

### 保持同一个逻辑请求

- 所有尝试使用同一冻结的 Provider、profile、model、系统/项目/Skill 前缀、对话、当前输入和工具 schema。
- 重试只改变传输尝试编号以及 Provider 支持的重试/幂等元数据，不改变任务目标或偷偷追加提示词。
- 固定前缀保持稳定以保留可能的缓存收益；是否命中仍以 Provider 实际 usage 为准。
- Provider 支持幂等键时复用同一个逻辑请求标识；不支持时不伪造能力。

### 计费、Token 与审查

- 每次真实尝试都单独记录开始时间、错误、等待、Token、缓存、耗时和 Provider 请求结果。
- Provider 未返回失败尝试的 Token/缓存 usage 时显示“未提供”，不得写成零。
- 重试可能产生额外 Token 和延迟；总览聚合所有尝试，不只展示最后一次成功请求。ADR-0059 后不记录金额。
- 一次重试不增加 Agent 工具轮次，也不形成新的自动审查轮次。
- 自动审查仍最多两轮逻辑审查；每轮的同一逻辑请求可在本规则内总尝试最多 5 次，界面同时显示“审查 1/2 · 尝试 2/5”。

### 并发与自动任务

- 等待重试不占 ADR-0021 的全局运行名额，恢复请求前重新竞争空闲名额和 Provider 容量。
- 等待仍保留原会话顺序；需要保护项目一致性时继续遵循 ADR-0020 的项目互斥。
- 已知 Provider 并发上限造成的本地预排队不算一次失败尝试；真正收到限流响应才计入尝试并进入退避。
- 自动任务达到第 5 次后按失败结束，不额外生成一个隐形补跑或第六次请求；后续正常周期仍按原计划运行。

## 产品表现

- 桌面端和 CLI 使用相同状态：“等待 Provider · 第 2/5 次尝试将在 4 秒后开始”。
- 用户能展开查看每次尝试，不需要阅读原始错误 JSON。
- 结果不完整、永久失败、重试耗尽和用户取消使用不同文案。
- 达到上限时给出可执行下一步，例如“检查余额”“更换模型”或“创建新的重试任务”，但不自动替用户改 Provider。

## 收益

- 短暂限流和网络波动通常能自动恢复。
- 有明确总上限，不会无限请求或无限等待。
- 同一活动 Runtime 内已有输出、工具调用和外部动作不会被在线传输重试盲目重放；崩溃后的结果未知步骤按 ADR-0042 例外处理并明确标记风险。
- 每次尝试的 Token、缓存和耗时可追溯。

## 代价

- 极端情况下一个逻辑请求可能产生最多 5 次 Provider 请求及相应 Token 与延迟。
- 长 `Retry-After` 会延长任务完成时间，但等待期间不占全局运行名额。
- 流式输出中途断开但 Runtime 仍存活时不会自动续写；进程崩溃后则按 ADR-0042 在下次 Runtime 自动恢复。
- 不自动切换备用模型，恢复能力受当前 Provider 状态限制。
