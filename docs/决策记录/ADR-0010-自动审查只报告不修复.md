# ADR-0010：自动审查只报告不修复

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

ADR-0006 已确定 Viniper Harness 必须提供类似 Claude Code 的可选自动审查，但尚未决定发现问题后是只报告，还是自动修改直到通过。用户选择方案 A：自动审查只报告，绝不自动修复。

## 决策

1. 自动审查可以在主执行完成后自动启动，但审查阶段只输出结论、问题、证据和建议。
2. 审查层只获得读取任务目标、最终结果、文件差异、测试结果、工具日志和外部操作回执所需的能力。
3. 审查层不得：
   - 编辑、创建、移动或删除正式文件；
   - 修改代码、配置、数据库或 Git 状态；
   - 发送消息、付款、发布、部署、修改远程权限或执行远程删除；
   - 因发现问题而自动执行补救动作；
   - 继承执行层的项目完全访问或电脑完全访问修改能力。
4. 审查优先使用适用的构建、测试、类型检查、lint、差异检查和任务验收证据，再由本次执行模型在全新只读上下文中补充语义审查。
5. 检查必须产生临时输出时，只能写入项目规定的 `codex/运行残留`，不能改变正式工作成果。
6. 用户希望修复时，可从审查结果点击“创建修复任务”。这会生成一项新的执行 run，继承问题和证据，但必须由用户显式启动。

## 审查结果

结果采用简单的人话状态：

- `通过`：适用检查已完成，未发现明确问题。
- `发现问题`：列出问题、影响、证据和建议。
- `无法验证`：缺少环境、权限、输入或可观察证据，不能冒充通过。
- `审查停止`：审查被取消，或受到模型、Provider、全局账户限制或工具失败影响。

结果必须同时区分确定性检查和模型判断，不能只显示一个绿色标记。

## 与完全访问的关系

- 完全访问只属于执行阶段；不会把审查阶段变成第二个隐形执行 Agent。
- 即使主任务使用电脑完全访问并包含所有外部操作，审查仍然只读、只报告。
- 审查可以指出已发送、已付款、已发布或已删除的结果存在问题，但不能再次执行、撤销或补偿这些动作。

## 收益

- 避免审查模型为了“修好”结果而引入新问题。
- 避免自动审查重复发送、付款、发布或删除等不可逆外部动作。
- 用户能清楚区分“执行结果”和“独立审查意见”。
- 修复是新的可追溯任务，便于比较问题、方案和实际改动。

## 代价

- 发现简单问题后也需要用户启动一次修复任务，闭环速度较慢。
- 自动审查仍会消耗时间与 Token，但不会直接交付修复后的结果。
- 任务感知触发、使用本次执行模型、自适应最多两轮以及不设审查专用预算均已确定。
