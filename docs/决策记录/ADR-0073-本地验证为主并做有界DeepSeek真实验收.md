# ADR-0073：本地验证为主，并在阶段末做有界 DeepSeek 真实验收

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

只做静态检查和 fake 无法证明真实模型会发起正确工具调用；一边开发一边反复请求真实 API 又会把产品问题、测试问题与公网波动混在一起。用户选择方案 C，并要求使用此前提供的真实 DeepSeek 凭据完成真实测试。

## 决策

- 开发和回归以确定性测试、本地 fake、真实 Windows 消费者和最终便携包为主；这些门全部通过前不得消耗新的真实生成调用。
- 阶段末使用用户此前提供且已安全落在本机凭据来源中的 DeepSeek Key，走生产 Provider、ToolRegistry、PermissionPolicy、历史和 Token ledger 完成一次最小真实纵向闭环。
- 凭据只能通过既有安全来源进入测试进程或隔离 `safeStorage`，不得从聊天文本复制到命令、源码、普通文件、日志、报告、截图、Git 或协调消息，也不得回显。
- 每个任务合同必须单独写清本轮真实调用上限、停止条件与证据目录；测试上限只是本次验收授权，不是产品面向用户的 Token 预算功能。
- 不查询或展示价格、金额、费用估算或余额；只记录实际请求、Token、缓存、耗时、状态和错误分类。
- 真实 usage 冻结后，报告、截图、清理或 harness 故障不得触发重复付费调用。

## 收益

- 既能用真实 DeepSeek 证明产品链，也能把调用控制在可解释范围内。
- 失败能区分为产品、测试入口、凭据/Provider 或物理 UI 问题。

## 代价

- 真实验收依赖网络、凭据状态和当前模型可用性。
- 其他 Provider 仍需要各自凭据和独立真实验收，DeepSeek 通过不能代表全部厂商通过。

## 与既有决策的关系

- 延续 Phase 5 的凭据隔离与真实 usage 对账经验，并取代其已经冻结的旧调用授权；新任务只能使用新合同规定的额度。
- 不改变 ADR-0041/0059 的产品用量设计：产品仍只统计 Token/缓存，不维护金额或 Harness 预算。
