# ADR-0045：长期记忆使用软容量提醒且永不自动删除

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

完全不限量且不提示会让用户难以判断长期记忆为何占用空间或拖慢检索；到达上限后自动删除或拒绝保存又可能丢失重要约定。用户选择方案 C：达到软阈值时提醒，由用户查看和处理，系统不自动删除长期记忆。

## 决策

### 软阈值只提醒，不阻断

- 项目记忆与个人记忆分别统计有效、可能过时和已停用条目的数量与正文占用；会话原始历史、运行日志和大型受管产物不混入长期记忆容量数字。
- 达到配置的软阈值后显示非阻断提醒，新的用户确认记忆仍可保存，现有记忆仍可搜索、编辑和使用。
- 软阈值不充当硬配额，不让 Agent 因“容量已满”自行丢弃、覆盖、压缩或拒绝用户明确保存的长期记忆。
- 初始 Preview 阈值必须基于真实数据规模与检索性能测试写入后续实现合同，并允许用户调整或关闭提醒；在取得该证据前不在产品中伪造一个“安全容量”。

### 提醒帮助用户判断

- 提醒展示当前条目数、正文占用、增长趋势，以及占用最大的项目或作用域；不只显示抽象百分比。
- 用户可进入记忆中心按项目、状态、最后使用时间和占用排序，并自行选择确认仍有效、编辑、停用、导出或删除。
- “可能过时”继续按 ADR-0037 暂停自动注入；容量提醒不会把条目自动改为过时，也不会因为条目过时就自动删除。
- 同一阈值区间只显示聚合提醒，不在每次 run 或每条记忆保存时重复弹窗；用户处理或阈值调整后重新计算状态。

### 永不以容量为由自动删除

- 达到阈值、磁盘空间下降、项目解绑、应用更新、导出成功或长期未使用，都不能触发自动删除项目/个人记忆正文。
- 用户明确删除仍遵守 ADR-0030 的来源与审计边界；删除界面不能把“建议清理”预选成批量删除。
- 如果物理磁盘已无法完成持久化，Runtime 如实报告写入失败并保留当前已落盘数据，不能用删除旧记忆来伪装保存成功。

## 产品表现

- 记忆中心顶部使用一条平静的容量提示，提供“查看占用”和“调整提醒”，不使用危险红色制造强制清理感。
- 桌面与 CLI 读取同一个容量状态；CLI 默认只在状态变化或用户查询时显示，不在每条输出后重复提醒。
- 设置页明确写出“这是提醒，不是上限；Viniper Harness 不会自动删除你的长期记忆”。

## 收益

- 用户能在检索和存储问题出现前看到增长情况。
- 重要长期记忆不会被机械阈值或清理算法无声删除。
- 条目数量、正文体积和实际作用域分开，后续优化有可观察依据。

## 代价

- 长期忽略提醒仍可能持续占用空间，并降低某些管理查询的速度。
- 初始阈值需要实现阶段的真实性能数据，不能只凭设计文档宣称合理。
- 用户需要自己决定停用、导出或删除哪些内容。

## 与既有决策的关系

- 细化 ADR-0030 留下的长期记忆容量问题；不改变显式保存、作用域和用户控制。
- 延续 ADR-0037 的“永不自动删除”，并保持过时复核与容量管理是两个不同状态。
- 可使用 ADR-0044 的选择性导出帮助用户迁移记忆，但导出完成也不会自动删除原条目。
- 本 ADR 是后续目标设计；容量统计、真实阈值、提醒与大规模检索表现均为 `UNPROVEN`。
