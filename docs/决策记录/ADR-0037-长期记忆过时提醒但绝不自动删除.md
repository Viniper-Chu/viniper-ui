# ADR-0037：长期记忆标记可能过时，但绝不自动删除

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

长期记忆永久自动生效容易把旧偏好和旧项目事实带进新任务；按时间自动删除又可能丢失仍有价值的约定。用户选择方案 C：长期不用的记忆标为“可能过时”并提醒检查，但系统绝不自动删除。

## 决策

### “可能过时”是可逆状态，不是删除

- 项目记忆和个人记忆新增 `possibly_stale` 状态；正文、来源、作用域和历史仍保留，用户可以确认继续使用、编辑、停用或明确删除。
- v0.0.1 初始检查周期为 90 天：一条长期记忆连续 90 天没有被使用、确认或修改时标为“可能过时”。用户可以在设置中调整检查周期或关闭时间提醒。
- 如果规范项目事实、`AGENTS.md`、当前用户指令或用户确认的新记忆与旧记忆直接冲突，不等待 90 天，立即标为“可能过时”并记录冲突来源。
- 会话历史是恢复记录，按 ADR-0038 永久留在主列表，不因久未打开而标记过时、归档或自动删除；本规则只作用于 ADR-0030 的项目/个人长期记忆。

### 过时条目暂停自动注入

- `possibly_stale` 条目不再自动进入新 run 的稳定缓存前缀，避免旧信息在用户未察觉时继续影响决策。
- 只读记忆检索仍可找到它，但结果必须带“可能过时”、来源和时间；Agent 需要使用时先引用当前事实或请用户确认，不能把它当成权威指令。
- 用户点击“仍然有效”后恢复 `active`，更新最后确认时间，并从后续 run 开始重新允许装载；活动 run 的记忆快照不在中途变化。

### 提醒集中而不打断执行

- 记忆中心用一个聚合入口显示待检查数量，项目打开或设置页可出现非阻断提醒；不为每条记忆、每个 run 反复弹窗。
- 复核列表按“发现冲突”优先于“长期未使用”排序，并提供“仍然有效 / 编辑 / 停用 / 删除”。批量确认只允许同一作用域内明确选中的条目。
- 提醒被忽略不会删除条目，也不会自行恢复自动注入；它保持可搜索、可复核的“可能过时”状态。

### 删除始终由用户决定

- 时间、容量、项目解绑、应用升级或智能清理都不能自动删除项目/个人记忆正文。
- 用户明确删除后遵守 ADR-0030：不再用于未来 run，审计只保留不含正文的历史引用，且如实说明无法撤回已经发送给第三方 Provider 的旧请求。
- 存储空间不足时可以建议导出、停用或删除，但不得把“清理空间”默认等同于删除长期记忆。

## 产品表现

- 记忆中心按“有效 / 可能过时 / 已停用”筛选；每条过时记忆显示原因“90 天未确认”或“与当前项目事实冲突”。
- ContextPanel 不把过时记忆列为本次已使用；显式搜索命中时展示警告和确认入口。
- CLI 提供相同状态与复核动作，默认列表不会用技术字段名要求普通用户理解。

## 收益

- 旧记忆不会长期无声影响新任务，也不会因机械时间规则永久丢失。
- 用户能集中复核，提醒不会频繁打断执行。
- 来源冲突与单纯长期未用分开显示，容易判断该确认还是修改。

## 代价

- 需要记录最后使用、最后确认和冲突来源，并维护复核界面。
- 被标记过时的有效记忆在确认前不会自动提供便利。
- 长期不删除意味着存储容量仍需另行用统计、导出和用户清理管理。

## 与既有决策的关系

- 细化 ADR-0030 的记忆冲突与过期提醒；不改变三层作用域、显式保存和用户删除权。
- ADR-0038 的会话历史永久保留独立于本 ADR；会话只有用户明确手动删除才移除。
- ADR-0045 另行规定软容量提醒：容量达到阈值也只提醒，不改变过时状态或触发自动删除。
- ADR-0044 可以手动导出记忆；导出完成不等于授权删除原条目。
- 过时状态和时间保存在 ADR-0032 的结构化真源中，不把长期记忆正文写入普通运行日志。
- 本 ADR 是后续目标设计，当前过时标记、提醒和停止自动注入的真实实现证据均为 `UNPROVEN`。
