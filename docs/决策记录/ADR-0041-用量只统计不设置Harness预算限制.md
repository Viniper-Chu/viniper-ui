# ADR-0041：用量只统计，不设置 Harness 预算限制

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`
- 修订：ADR-0059 将统计范围收敛为 Token/缓存，不再维护价格、金额或费用。

## 背景

任务级或账户级用量硬预算可以限制运行，但本地估算与 Provider 最终 usage 可能不同，达到上限时也可能在交付前机械中断。用户选择方案 A：只统计用量，不由 Viniper Harness 设置预算限制；ADR-0059 后续明确产品只统计 Token/缓存，不处理金额。

## 决策

### 不提供 Harness 预算阈值

- 产品不提供每个 run、会话、自动任务、日、月或 Provider profile 的 Token 提醒线和硬停止线，也没有金额预算功能。
- Runtime 不因本地 Token 估算达到某个数值自动暂停、取消、降级模型、跳过审查或停止上下文压缩。
- 自动任务、委派任务、Provider 重试、自动审查和 ADR-0040 的上下文压缩都遵守同一规则；只要任务仍在正常执行且外部服务允许，就不会因 Harness 预算判断停止。
- 智能模型分配的“质量优先 / 均衡 / 轻量优先”是选择偏好，不是 Token 预算承诺。

### 继续完整统计和对账

- 流式阶段显示输入、输出、推理和缓存用量估算；Provider 返回最终 usage 后原位对账，并保留每次尝试、审查、压缩和工具相关模型请求的来源。
- 产品不获取公开价格，不计算金额；Provider 返回金额或余额字段时也不进入 canonical usage 与 UI。
- 桌面端与 CLI 共用同一 Token/缓存账本，可以按 run、会话、自动任务、模型和 Provider 查看累计，但没有“剩余预算”字段。
- 用户可以随时取消活动 run、暂停自动任务、换用其他模型或关闭智能分配；这些是显式控制，不是系统预算策略。

### 外部硬限制仍然有效

- Provider 余额、硬配额、速率限制、模型上下文/输出上限和账号权限仍可能让请求失败；Harness 必须如实映射这些外部结果。
- ADR-0023 的每个逻辑请求最多 5 次传输尝试、ADR-0013 的最多两轮审查、全局并发上限和工具循环上限属于可靠性/调度边界，不是用量预算，也不因本 ADR 取消。
- 操作系统、用户取消、权限失效和禁止自修改等系统边界继续生效。

## 产品表现

- Token 面板显示估算/实际 Token、缓存、请求和耗时，不出现价格、金额、预算输入、进度条或“还可使用多少”的虚构数字。
- 自动任务编辑页不要求填写预算；历史仍列出每次真实消耗，便于用户自行判断是否继续启用。
- 用量快速增长时界面可以继续实时更新，但不弹预算警告或擅自停止任务。

## 收益

- 不会因为不准确的本地 Token 估算在任务即将完成时机械中断。
- 产品设置更简单，普通用户无需先理解 Token 预算。
- 所有用量仍有来源和 Provider 对账，用户可自行决定是否取消或换模型。

## 代价

- 长任务、自动重试、上下文压缩和无人值守自动任务可能消耗大量 Token。
- 用户必须主动观察统计，并在 Provider 官网查看价格、余额和账单。
- Harness 不预测或承诺任何任务金额。

## 与既有决策的关系

- 扩展 ADR-0014 的“自动审查不设独立预算”为整个 Harness 的统一用量策略，但仍保留其两轮审查硬停止。
- 不改变 ADR-0023 的重试次数、ADR-0021 的并发限制或 ADR-0028/0035 的模型选择规则。
- ADR-0059 是当前价格边界：不维护单价、余额或金额，只对账 Provider 提供的 Token/缓存 usage。
- 本 ADR 是后续目标设计，当前跨 Provider Token 对账仍保持证据边界。
