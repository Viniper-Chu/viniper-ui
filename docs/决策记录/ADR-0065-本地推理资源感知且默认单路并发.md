# ADR-0065：本地推理资源感知，且默认单路并发

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

固定单路本地推理最稳但可能浪费高性能设备；直接套用全局并发上限又可能耗尽内存或显存。用户选择方案 C：Viniper 根据本机资源、模型体积和上下文给出并发估算，默认只运行一个本地推理请求，用户可以在看到估算后主动提高。

## 决策

### 双层并发边界

- ADR-0021 的全局 run 并发上限继续适用于云端与本地任务；本 ADR 另增加共享的“本地推理并发上限”，两者同时满足后才能开始本地生成。
- 本地推理并发默认值为 1。高级设置允许用户提高，但不能超过全局并发上限 8；桌面端和 CLI 通过同一 Runtime 所有者共享真实名额。
- 等待本地推理名额显示为“等待本地模型资源”，不冒充正在生成，也不被算作 Provider 失败或重试。

### 资源估算是建议而非承诺

- 本地模型中心根据可用内存/显存、模型格式与量化、已知运行器开销、上下文设置和当前已加载模型给出“建议并发”和预计资源区间。
- 用户提高上限前看到简短影响说明；估算不能保证驱动、运行器或其他程序不会改变可用资源。
- 运行中降低上限不强制中断已有生成，只阻止新的本地请求进入；资源不足时停止受影响请求并给出可理解原因，不自动换模型、量化版本或云端 Provider。
- 模型加载、卸载和切换由 Runtime 所有者串行协调，避免桌面端与 CLI 各自重复占用同一模型资源。

### 与任务调度一致

- 本地资源排队继续服从手动、委派、自动任务的柔性优先级和等待提升规则，不新建第二套任务队列。
- Token、缓存、请求次数、排队与生成耗时照常记录；不估算电费、硬件成本或模型价格。
- 活动 run 仍冻结具体模型和运行器版本；排队期间的更新提醒不会改变它的执行快照。

## 产品表现

- 状态区同时显示“任务运行 2/3”和“本地推理 1/1”，让用户知道真正等待的资源。
- 本地模型设置显示默认值、建议值、当前资源和手动调整入口，不要求新手理解显存术语才能开始。
- 资源不足错误优先给出“关闭其他本地任务、降低并发或选择更轻模型”等可行动建议。

## 收益

- 默认设置适合更多设备，同时允许高性能设备主动利用并发。
- 本地推理不会绕过全局调度或在桌面/CLI 之间重复占用。
- 资源等待、Provider 失败和任务排队能够清楚区分。

## 代价

- 硬件与运行器差异使资源估算只能作为建议。
- 需要维护本地推理名额、模型加载状态和排队可视化。
- 用户提高并发后仍可能遇到系统资源竞争。

## 与既有决策的关系

- 细化 ADR-0021/0025/0031 的并发与单 Runtime 调度，并扩展 ADR-0058 的本机资源状态。
- 不改变 ADR-0023 的云端 Provider 重试上限，也不引入 ADR-0041 已排除的金额预算。
- 本 ADR 是后续目标设计；Windows 资源检测、GPU/CPU 后端、共享队列和 macOS 真机表现均为 `UNPROVEN`。
