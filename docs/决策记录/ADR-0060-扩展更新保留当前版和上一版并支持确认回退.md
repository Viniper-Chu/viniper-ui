# ADR-0060：扩展更新保留当前版和上一版并支持确认回退

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

扩展只保留最新版最省空间，但更新后出现行为变化时无法快速恢复；永久保存全部历史版本又会增加磁盘占用和管理复杂度。用户选择方案 B：每个 Skill、MCP 或插件保留当前版本与上一个可用版本，并提供明确确认后的回退。

## 决策

### 正常只保留两个可用版本

- 每个已安装扩展维护 `current` 和最多一个 `previous`。用户按 ADR-0047 确认更新后，新包先进入暂存区完成清单、入口和能力检查，激活成功后原 current 才成为 previous。
- 新版本验证或激活失败时继续使用原 current，不生成一次“成功更新”记录，也不破坏已有 previous。
- 下一次更新成功后，旧 previous 只有在没有活动 run 引用时才删除；活动 run 的冻结扩展快照可以暂时使磁盘上超过两个版本，run 结束后再收口。
- 来源消失或网络离线不影响使用本机 previous 回退。

### 回退也是显式变更

- 扩展中心提供“回退到上一版”，显示目标版本、来源、能力/权限差异和可能的数据兼容说明；用户确认后才切换。
- 回退只影响之后开始的 run，正在运行的任务继续使用自己的冻结版本。
- 回退成功后，被替换的新版本成为 previous，便于用户再次切回；产品不在两个版本之间自动反复切换。
- 权限、工具入口或外部目标发生变化时，回退同样遵守 ADR-0029 的信任检查，不能因为版本较旧就自动获得权限。

### 数据与失败边界

- 扩展包、扩展配置和扩展运行数据分开；包回退不能删除用户配置、秘密或正式产物。
- 可执行插件若需要数据 schema 迁移，必须声明 previous 是否仍可读取，并提供可恢复迁移；无法保证回退的数据变更在 Preview 中不得以“一键可回退”方式安装。
- 旧包属于扩展恢复材料，不进入普通 30 天可再生成清理；超出 current/previous 且无活动引用的包才按本 ADR 移除。

## 产品表现

- 扩展详情显示当前版本、上一版本、更新时间和“可回退/不可回退”状态。
- 更新失败显示“仍在使用原版本”，而不是要求用户重新安装。
- 没有 previous 时不展示虚假的回退按钮。

## 收益

- 更新出现兼容或行为问题时可以快速恢复。
- 磁盘占用比永久保存全部版本可控。
- 活动任务不会因更新或回退中途改变能力。

## 代价

- 每个扩展通常需要额外保存一个包。
- 数据 schema 兼容和活动 run 引用会增加生命周期管理复杂度。
- 只能直接回到上一版，不能在产品内任意选择全部历史版本。

## 与既有决策的关系

- 细化 ADR-0047 的“所有扩展更新均需确认”和失败保留旧版；不改变 ADR-0029/0036 的信任与来源边界。
- previous 属于专用恢复材料，生命周期优先于 ADR-0052 的通用可再生成清理。
- 本 ADR 是后续目标设计；双版本存储、激活失败保持、数据兼容和真实回退均为 `UNPROVEN`。
