# ADR-0070：本地模型实现排在云端主路径完成之后

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

本地模型已经有完整目标设计，但下载、运行器、硬件探测、许可、版本与工具兼容会显著扩大首个可用切片。用户选择方案 B：先完成云端 Provider 主路径，再实施本地模型；本地能力不取消。

## 决策

- 当前实施优先完成云端会话、工具、权限、历史和 Windows 交付，DeepSeek 为首个真实主路径。
- ADR-0058、0062–0065 的本地模型来源、更新、工具能力和资源并发合同全部保留，不降级为非目标。
- 在云端纵向闭环和第一批编程能力形成稳定验收前，不下载模型权重、不引入本地推理运行器、不增加硬件探测依赖，也不把兼容 localhost fake 宣称为本地模型支持。
- 当前代码继续保持 ProviderAdapter、ToolRegistry、权限、Token 和取消接口可供未来本地实现复用；不得为了赶进度另建本地专用 Agent 循环。

## 收益

- 首个可用版本范围更清楚，避免云端与本地两条复杂链同时不稳定。
- 本地模型未来仍能沿同一 Runtime 接入，既不推倒重来，也不影响当前用户使用 DeepSeek。

## 代价

- 预览期暂时不能离线运行模型。
- 本地模型 UI、运行器、硬件建议和真实工具成功率继续为 `UNPROVEN`。

## 与既有决策的关系

- 本 ADR 只调整 ADR-0058、0062–0065 的实施顺序，不修改它们的最终产品承诺。
