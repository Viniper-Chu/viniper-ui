# ADR-0011：任务感知自动审查触发

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

ADR-0010 已确定自动审查只报告、不修复。下一步需要决定它是所有任务默认运行、默认关闭，还是按任务类型触发。用户选择方案 C：代码、文件、数据、系统和外部操作默认审查，简单查询与纯只读操作默认跳过，同时允许用户覆盖。

## 决策

### 三种选择

自动审查控件提供：

- `智能（默认）`：Runtime 按本次任务实际发生的工具事件和交付物决定。
- `本次总是审查`：无论任务类型，主执行结束后都启动只报告审查。
- `本次不审查`：本次 run 不启动审查，即使发生状态变化。

用户的 `on/off` 覆盖只作用于当前 run；下一次任务恢复会话的默认“智能”策略，除非后续另行设计会话级偏好。

### “智能”默认开启审查

出现以下任一事实时，主执行结束后启动审查：

- 创建、编辑、移动或删除代码、文件、配置或项目内容；
- 修改数据库、Git 状态、依赖、构建产物或操作系统状态；
- 执行发布、部署、发送、上传、付款、远程权限修改或远程删除；
- 生成用户要保存或交付的正式文档、报告、表格、演示文稿、图像、音视频、安装包或其他成果。

### “智能”默认跳过审查

仅执行查询、搜索、读取、列出、浏览或状态检查，并且没有产生正式交付物或本地/远程状态变化时，默认跳过。例如简单查找、查看余额、读取日志或回答一个直接问题。

跳过审查只能显示为“未触发审查”，不能显示成“审查通过”。

## 判断机制

- 是否触发由 Runtime 根据 ToolRegistry 中的能力元数据和 canonical 事件判断，例如 `read_only`、`local_write`、`data_write`、`system_change`、`external_change` 和 `deliverable_created`。
- 模型可以规划和调用工具，但不能自行伪造“只读”标签，也不能隐藏已经发生的状态变化。
- 在 `auto` 下，任务起初可能是只读；如果执行途中首次出现变更或正式交付物事件，Runtime 必须在结束前把审查状态切换为“将自动审查”。
- 控件始终显示简短原因，例如“将自动审查：修改了 3 个文件”或“未触发：本次仅查询状态”。

## 与只报告规则的关系

- 触发策略只决定“是否审查”，不改变 ADR-0010 的只报告边界。
- 即使变更任务使用项目完全访问或电脑完全访问，审查仍没有编辑、发送、付款、发布或删除能力。
- 发现问题后只能生成建议和“创建修复任务”入口。

## 收益

- 重要变更和正式交付物默认获得独立检查。
- 简单只读任务不会平白增加一次模型调用、等待时间和 Token。
- 判断依据来自真实工具事件，比让执行模型自行决定更可解释。
- 高级用户仍能为特殊任务强制开启或关闭。

## 代价

- ToolRegistry 必须为工具准确标注能力类别。
- 纯文本结果是简单回答还是正式报告，需要由明确的交付物合同区分。
- 任务执行中可能从“无需审查”切换为“将自动审查”，界面需要及时说明原因。
