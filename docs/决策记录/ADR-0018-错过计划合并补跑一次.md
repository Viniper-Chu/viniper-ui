# ADR-0018：错过计划合并补跑一次

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

Viniper Harness 只在桌面或 CLI 调度进程运行时触发自动任务，权限和连接失效时也不会静默降级。因此进程关闭、电脑休眠或授权暂不可用时可能错过一个或多个计划点。用户选择方案 C：恢复后最多合并补跑一次，而不是全部跳过或逐次回放。

## 决策

### 一次性任务

- 如果计划时间到达时无法运行，保留一个“待补跑”记录。
- 调度器恢复且任务所需权限、连接均有效后执行一次。
- 成功触发补跑后，一次性任务完成，不会因为多次重启再次补跑。

### 重复任务

- 对间隔、每日和每周任务，把一个连续不可运行区间内的所有错过计划合并为一个补跑。
- 补跑使用该区间内最新错过点作为逻辑 `scheduled_at`，同时记录错过总数、最早和最晚时间。
- 无论错过一次还是多次，每个连续中断区间最多生成一个补跑。
- 补跑后仍按原始频率和日历锚点计算下一次正常运行，不从补跑完成时间重新排期。
- 待补跑项尚未开始时若遇到同一任务的当前正常触发，两者只执行一个 run，详细记账规则见 `ADR-0022-同任务补跑与正常触发合并.md`。

### 适用原因

同一规则适用于：

- 桌面/CLI 调度进程完全退出；
- 操作系统休眠或关机；
- 项目信任被撤销后又恢复；
- 电脑完全访问等待重新授权；
- 外部工具连接或账号权限暂时失效后恢复。

## 不补跑的时间

- 用户主动暂停任务期间不累计错过点。
- 任务被删除后不再补跑。
- 计划尚未生效或已经超过明确结束时间的部分不创建新补跑。
- 用户编辑任务后，尚未执行的补跑使用当前任务定义与当前权限/连接，不恢复旧指令。

## 执行与外部操作

- 补跑与普通触发进入同一个 Agent Runtime。
- 有效完全访问下，发布、发送、付款、改远程权限和远程删除仍不逐项确认。
- 补跑若产生状态变化或正式交付物，按任务感知规则自动进入只报告审查。
- 不因多个错过点而重复执行同一外部动作多次。

## 产品表现

- 任务列表显示“待补跑一次 · 错过 N 次”。
- 纯补跑开始时显示“正在补跑”，历史标记为“补跑”；与正常触发合并时显示“本次计划 + 补跑（曾错过 N 次）”。
- 历史保留中断原因、错过数量、首末计划时间、实际补跑时间和最终结果。
- 如果权限或连接仍不可用，继续保持一个待补跑项，不反复创建新的任务副本。

## 收益

- 一次性提醒或任务不会因为短暂离线永久丢失。
- 重复任务不会在恢复后突然密集发送、付款、发布或删除。
- 原始时间表不因补跑漂移。
- 用户能看到实际错过次数，又只承担一次恢复执行。

## 代价

- 重复任务中每个错过时间点的独立工作不会全部完成。
- 合并补跑使用当前任务定义，可能与最早错过时的内容不同。
- 对必须逐次处理每个时间点的业务，本策略不适用，需用户另建明确的批处理任务。
