# ADR-0055：使用分级应用内与系统通知

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

只用应用内状态最安静，但窗口隐藏后容易错过任务完成或等待授权；所有事件都发系统通知又会造成噪音。用户选择方案 C：普通状态只在应用内显示，任务完成、失败、等待用户处理和定时任务结果使用系统通知，并允许分类设置，声音默认关闭。

## 决策

### 应用内时间线是权威状态

- 所有 run、协调、调度、权限、更新和 Provider 状态都继续进入应用内 canonical 事件与时间线；系统通知只是提醒入口，不能替代历史或回执。
- 进度、流式文字、工具开始/结束、Token 变化、在线重试和普通队列变化只在应用内显示，不逐条发送系统通知。
- 点击系统通知打开对应会话、run、定时任务或设置入口；目标已经删除或不可用时只打开应用并说明，不创建虚假状态。

### 只有高价值结果发系统通知

- 窗口未聚焦、隐藏或只有 CLI Runtime 所有者运行时，以下类别默认允许系统通知：任务完成、任务失败、等待权限/用户选择、跨会话委派完成、定时任务完成或失败。
- 当前窗口聚焦并已显示同一结果时，默认不重复发系统通知；等待授权等需要处理的状态仍保留应用内醒目标记。
- 应用或 CLI Runtime 完全退出后没有调度和事件，也不会安装独立通知服务；错过计划仍按 ADR-0017/0018 处理。

### 声音和分类可控

- 系统通知总开关默认开启，声音默认关闭；用户可分别关闭“完成”“失败与等待处理”“定时任务”“跨会话协作”。
- 关闭某类系统通知不影响应用内事件、调度执行、自动审查或错误记录。
- 通知设置由本机默认数据根保存，不随普通会话消息跨设备同步；通过 ADR-0044 导入时可作为非秘密设置迁移，但目标系统权限仍需重新允许。

### 隐私与平台权限

- 锁屏和默认通知正文只显示产品名、会话/任务的安全标题和状态，不展示提示词、模型回复、工具内容、项目文件、凭据或外部动作详细目标。
- Windows 使用当前用户的原生系统通知；macOS 使用 Notification Center，并分别遵守系统勿扰、通知权限和应用身份。
- 用户拒绝系统通知权限时，产品继续正常运行并保持应用内提醒，不反复弹出权限请求或冒充通知已送达。

## 产品表现

- 设置页提供简洁的通知分类和“声音”开关；默认状态为“系统通知开、声音关”。
- 通知文案使用“任务已完成”“任务失败，需要查看”“任务在等待你的允许”，不显示技术事件名。
- 应用内收件箱保留未处理状态；系统通知被系统折叠或忽略不改变任务状态。

## 收益

- 后台任务和定时任务的重要结果不容易错过。
- 不为每个工具步骤制造系统通知噪音。
- 敏感执行内容默认不出现在锁屏通知正文。

## 代价

- 系统可能因勿扰或权限设置不展示通知，不能把发送请求当成交付保证。
- 需要 Windows 与 macOS 两套原生通知适配和深链接验证。
- 用户可能关闭某类通知后只在应用内看到结果。

## 与既有决策的关系

- 通知依赖 ADR-0031 的当前 Runtime 所有者，并遵守 ADR-0017 的“程序完全退出后不运行”。
- 不改变 ADR-0046 的匿名诊断同意；系统通知内容不会上传为诊断数据。
- 本 ADR 是后续目标设计；Windows 原生通知、CLI 所有者通知、分类设置和 macOS Notification Center 均为 `UNPROVEN`。
