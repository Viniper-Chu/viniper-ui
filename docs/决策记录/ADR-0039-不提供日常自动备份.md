# ADR-0039：不提供日常自动备份

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

轮换本地备份能提高恢复能力，但会增加磁盘占用、生命周期管理和用户对“哪份数据才是当前真源”的理解成本。用户选择方案 A：Viniper Harness 不自动备份正式数据。

## 决策

### 没有周期性或滚动备份服务

- Runtime 不按启动、关闭、每日、每周或会话数量自动复制 SQLite、日志、产物、插件数据或工作区。
- 产品不建立“最近 7 份”、影子数据库、自动快照目录或云端同步副本，也不在后台上传用户数据用于备份。
- 桌面端和 CLI 共用同一决定；CLI 所有者不会在桌面关闭后偷偷启动备份任务。
- 应用更新、长期未使用、磁盘空间变化和会话数量增加都不会自动触发正式数据备份。

### 用户承担正式数据根的持久性

- 设置页清楚显示正式数据根位置与占用，并说明“Viniper Harness 未自动备份此数据”。
- 用户可以依靠操作系统、磁盘工具或自己选择的备份方案保护数据；Harness 不把外部备份是否存在显示成已验证事实。
- ADR-0044 提供用户主动触发的完整非秘密归档和选择性导入导出；它不会按计划创建，也不由 Harness 轮换或监控，因此不属于自动备份服务。
- SQLite 或受管文件因磁盘损坏、误删或系统工具覆盖而丢失时，如果没有用户自己的副本，产品可能无法恢复会话、任务、记忆和运行历史。
- ADR-0038 的手动删除确认必须说明当前没有应用自动备份可供恢复。

### 操作级回滚副本不是日常备份

- ADR-0032 的旧格式迁移、数据库 schema 重写或其他会整体改写正式存储的维护动作，仍必须在动作范围内创建一次性可恢复副本并验证切换；这是该操作的事务回滚条件，不是常驻备份功能。
- 操作级副本只覆盖本次维护涉及的数据，在迁移验收和明确回滚窗口结束后按任务合同处理；它不形成定时备份历史，也不承诺恢复此前的用户误删。
- 没有新的管理任务合同，不得以“做备份”为由复制、上传或清理当前真实数据根。

## 产品表现

- 存储页显示“自动备份：关闭（产品固定策略）”，不展示不存在的恢复点数量。
- 发生损坏时只列出实际检测到的数据与可用恢复来源，不生成虚构的“自动恢复成功”。
- 数据迁移界面可以显示“迁移回滚副本”，并明确它只服务本次迁移。

## 收益

- 数据流向简单，没有隐藏副本或后台上传。
- 减少持续磁盘占用和备份清理逻辑。
- 用户清楚知道正式数据根是唯一产品真源。

## 代价

- 数据库损坏、磁盘故障或误删时，缺少产品提供的常规恢复点。
- 长期保留全部会话会让唯一数据根越来越重要，用户需要自行承担备份责任。
- 支持排障时不能默认依赖上一份自动快照。

## 与既有决策的关系

- 不改变 ADR-0032 的迁移前一次性回滚副本；该副本严格限制在维护操作生命周期内。
- 不改变 ADR-0034 的七天 worktree 恢复记录；它只保护已合并隔离任务的短期 Git 交付，不是整个 Harness 数据备份。
- ADR-0044 的手动归档是数据可携带能力，不改变本 ADR 的“没有产品自动恢复点”。
- 本 ADR 是后续目标设计，当前真实数据恢复能力仍须按现有证据判断，不能冒充已经验证。
