# ADR-0064：本地模型原生工具优先，并可选实验性提示词模拟

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

只允许具有可靠原生工具调用的本地模型最稳定，但会排除许多可用模型；把所有文本模型都包装成工具模型覆盖最广，却容易把普通文本误判成操作。用户选择方案 C：原生工具调用始终优先，不具备原生协议的模型可以由用户明确开启实验性的提示词工具模拟，并持续显示其可靠性边界。

## 决策

### 三档工具能力

- `native`：模型与运行器提供已验证的结构化工具调用协议，ProviderAdapter 直接规范化为统一 ToolRegistry 事件。
- `experimental_emulation`：用户为具体模型/profile 主动开启提示词协议，模型以受约束结构描述工具请求，再由适配层解析、校验并提交统一工具循环。
- `none`：未验证原生工具且未开启实验模拟，只能执行不需要工具的 Agent 步骤；界面不得把它标成完整操作型 Agent。

### 实验模拟不是绕过核心循环

- 开启前显示“实验性工具调用可能漏调、误调或格式失败”，并允许随时关闭；智能分配只有在用户明确允许实验能力后才能把它作为需要工具的候选。
- 只有完整通过结构解析、工具名称和参数校验的请求才进入 ToolRegistry；普通回复、残缺结构或未知工具保持为模型输出/可纠正错误，不直接执行。
- 模拟调用继续经过现有权限模式、资源锁、审计回执、取消、工具轮次和自动审查，不获得额外文件、Shell、插件或外部操作权限。
- 工具结果以统一、稳定的受限结构回送模型；失败原因清楚区分“模型格式失败、工具不可用、权限等待、执行失败”，便于诊断。

### 能力证据与运行冻结

- 能力页显示“原生 / 实验模拟 / 无工具”，并记录最近一次合同测试结果；不能只凭模型名称推断原生工具能力。
- run 开始时冻结工具模式、工具定义、模型和运行器版本；运行中不能从原生切到模拟或反向切换。
- 代码生成能力与文件操作能力分开表示：模型可以生成代码，但只有成功进入统一工具循环后才能读取、修改或运行项目。

## 产品表现

- 本地模型卡片使用清晰能力标签，实验模式不藏在普通“已支持工具”状态里。
- 用户第一次为某模型开启实验模拟时看到一次简短说明和可运行的能力测试入口。
- 任务失败时显示是模型没有产生有效工具请求，还是实际工具执行失败。

## 收益

- 优先保证原生工具模型的可靠体验，同时保留更多本地模型的实验空间。
- 所有真实操作仍走统一权限、审计和资源调度边界。
- 不会把“能生成代码文本”误写成“能完成编程闭环”。

## 代价

- 实验模拟的可靠性取决于模型遵循格式的能力。
- 需要维护结构解析、纠错反馈和能力测试。
- 同一任务在不同本地模型上的工具成功率可能差异明显。

## 与既有决策的关系

- 细化 ADR-0058 的本地模型能力合同，并遵守 ADR-0006/0007/0008/0009 的统一权限状态机。
- 真实工具仍由 ADR-0026 的完整编程能力和 ADR-0054 的有界输出合同管理。
- 本 ADR 是后续目标设计；原生合同测试、实验解析、权限联动和真实编程成功率均为 `UNPROVEN`。
