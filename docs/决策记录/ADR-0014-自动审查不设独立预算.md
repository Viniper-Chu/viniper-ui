# ADR-0014：自动审查不设独立预算

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

ADR-0013 已将模型审查硬限制为自适应最多两轮。下一步需要决定是否再为审查单独设置 Token 或时间预算。用户选择方案 A：不设独立预算，只保留最多两轮的停止规则；ADR-0059 后产品不维护金额。

## 决策

1. Viniper Harness 不为自动审查配置专用的 Token 上限。
2. Viniper Harness 不为自动审查配置专用的时间上限。
3. Viniper Harness 不为自动审查配置金额上限，因为产品没有价格或费用系统。
4. 不按主执行 Token 的一定比例为审查分配额度。
5. 满足 ADR-0013 的第二轮条件时，直接开始第二轮，不检查“剩余审查预算”，也不弹出追加预算对话框。
6. 审查唯一的 Harness 专用轮次硬停止是：最多两轮逻辑审查，绝不进入第三轮。每轮同一逻辑请求的可重试传输错误按 ADR-0023 总尝试最多 5 次；这些尝试不是新审查轮次，但产生的实际 Token、缓存和耗时必须分别展示。

## 仍然有效的外部限制

“不设独立预算”不表示模型或账号没有客观边界。以下限制仍按实际情况生效：

- 模型上下文窗口和单次输出限制；
- Provider 的余额、配额、速率和并发限制；
- 网络中断、模型错误和用户主动取消。

这些条件导致审查无法完成时，结果显示“审查停止”或“无法验证”，但不把它描述成“审查预算耗尽”。

## 用量展示

- 审查过程中继续实时显示估算输入/输出 Token。
- 每轮完成后以 Provider 返回值对账，并分别显示 Token、缓存读写和耗时。
- 未提供的 Token 或缓存数据明确显示“未提供”，不估成零。
- 界面不显示“剩余审查预算”进度条，也不预测价格或金额。

## 收益

- 审查不会因为人为设置过小的局部预算而在关键证据处被截断。
- 用户不需要理解或维护另一套审查额度。
- 两轮触发规则简单，桌面端与 CLI 行为一致。

## 代价

- 审查的 Token 和时长不能在运行前准确封顶。
- 大型成果或长上下文可能产生明显的额外消耗。
- 第二轮触发时不会因为 Token 较高而再次征求用户意见；用户始终可以取消。
