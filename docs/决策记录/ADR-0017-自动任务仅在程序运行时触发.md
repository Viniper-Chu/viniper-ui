# ADR-0017：自动任务仅在程序运行时触发

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

Viniper Harness 已确定自动任务的定义、权限继承和审查规则。下一步需要决定桌面端或 CLI 完全退出后，任务是否继续由常驻服务触发。用户选择方案 A：必须保持程序运行，不增加独立后台服务。

## 决策

1. 自动任务只由以下任一正在运行的进程触发：
   - 作为当前数据根 Runtime 所有者的 Viniper Harness Electron 主进程；
   - 用户显式启动并保持运行、且作为当前数据根 Runtime 所有者的 Viniper Harness CLI 无界面进程。
   桌面和 CLI 同时打开时，客户端不启动第二个调度器；所有权发现与交接按 ADR-0031 执行。
2. 窗口最小化、隐藏或进入托盘，只要 Electron 主进程仍在，调度继续运行。
3. Electron 主进程完全退出或 CLI 调度进程结束后，调度立即停止。
4. 不安装或创建：
   - Windows Service；
   - Windows Task Scheduler 计划任务；
   - Windows 开机启动项；
   - macOS LaunchAgent/LaunchDaemon；
   - 与桌面端、CLI 分离的常驻 daemon。
5. 任务定义、权限引用、下次计划点和历史继续持久保存；保存定义不等于退出期间发生了触发。

## 重新启动

- 程序重新启动后加载所有自动任务和最近调度状态。
- UI/CLI 显示上次调度进程停止到本次启动之间的离线时段，以及其中可能错过的计划点。
- 不得把退出期间的计划点记录为“成功”“失败”或“已执行”。
- 错过的计划点按 ADR-0018 合并补跑一次。

## 与权限规则的关系

- 受信任项目和外部连接引用仍可跨重启保存。
- 电脑完全访问令牌随当前 Runtime 所有者退出或所有权交接失效；新所有者启动/接管后，需要电脑权限的任务进入“等待重新授权”。
- 即使项目权限仍有效，没有调度进程时也不会发生后台执行。

## 产品表现

- 自动任务中心顶部显示“调度器正在运行 · 桌面”或“调度器正在运行 · CLI”。
- 创建任务时明确说明：“Viniper Harness 完全退出后不会触发。”
- 退出程序时不弹出阻断式确认；已有自动任务的情况下可给一次简短非阻断提示。
- 重新打开后，如存在离线期间计划点，显示真实数量和时间，不自动声称已经补跑。
- ADR-0055 的系统通知也只能由正在运行的桌面或 CLI Runtime 所有者发出；完全退出后不安装独立通知服务。

## 收益

- 不引入用户看不见的常驻进程。
- Windows 和 macOS 的行为容易保持一致。
- 安装、升级和卸载流程更简单。
- 电脑完全访问的“进程退出即失效”语义保持完整。

## 代价

- 电脑关机、休眠或用户退出程序时，自动任务不能准时运行。
- 用户需要保持桌面端或 CLI 调度进程运行。
- 不适合要求 24 小时可靠触发的服务器式自动化。
