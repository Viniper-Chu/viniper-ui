# ADR-0013：自适应两轮自动审查

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

自动审查已经确定为任务感知触发、只报告不修复，并使用执行任务的同一模型在新上下文中审查。下一步需要在固定一轮、固定两轮和自适应轮次之间选择。用户选择方案 C：默认一轮，必要时追加第二轮，硬上限为两轮。

## 决策

### 第一轮

- 每次已触发的自动审查先运行适用的确定性检查，再进行一轮完整模型审查。
- 第一轮覆盖目标符合性、结果正确性、遗漏、明显副作用和证据充分性。
- 如果确定性检查通过、第一轮没有发现问题、结论明确且任务不属于复杂高影响类型，审查立即结束。

### 第二轮触发条件

以下任一事实成立时，追加第二轮：

1. 确定性检查结果与第一轮模型结论冲突。
2. 第一轮报告一个或多个有具体证据的问题。
3. 第一轮结论为“无法验证”或关键证据不足。
4. 任务涉及多个变更域或多个正式交付物。
5. 任务包含付款、公开发布、远程权限修改、远程删除等高影响外部操作。

### 第二轮职责

- 第二轮是新的只读模型请求，不延续第一轮的对话状态。
- 如果由问题或冲突触发，第二轮逐项核对第一轮发现与对应证据，给出“确认 / 不成立 / 仍无法验证”。
- 如果由复杂或高影响任务触发，第二轮重点检查遗漏、跨成果一致性和可观察副作用。
- 第二轮不能编辑、修复、补救或重复任何外部操作。

### 硬停止

- 模型审查最多两轮，不存在第三轮。
- “两轮”是逻辑审查轮次，不是底层网络传输尝试数。同一轮在尚无语义输出时遇到可重试 Provider 临时错误，可按 `ADR-0023-Provider临时错误最多尝试五次.md` 对同一逻辑请求总尝试最多 5 次；重试不会创建第三轮。
- 第二轮后仍有矛盾、证据缺失或不确定性时，最终结果保留双方证据并标记“无法验证”。
- 用户若需要进一步分析，可显式创建新的审查或修复任务；原审查不能自行延长。

## 产品表现

- 第一轮显示“审查 1/2”。
- 第二轮开始前显示“追加复核”以及具体原因，例如“测试结果与首轮结论冲突”。
- 结果分别列出第一轮与第二轮的模型用量、缓存数据和耗时；如发生传输重试，再展开每次尝试的实际 Token/缓存、耗时与原因，并提供合并后结论，不记录金额。
- 只运行一轮时不显示“缺少第二轮”，而显示“第一轮证据一致，无需追加复核”。

## 收益

- 大多数正常任务只承担一轮模型审查的延迟和 Token 消耗。
- 有发现、冲突或高影响时得到额外复核，减少单轮误判。
- 硬上限为两轮，避免同一模型无限自我讨论。
- 两轮均只报告，不会演变成自动修改循环。

## 代价

- 第二轮仍使用同一模型，不能消除共同知识盲点。
- 复杂度和高影响分类必须来自 Runtime 的可解释事件，而不是模型随意判断。
- 两轮后仍可能只能得出“无法验证”。
