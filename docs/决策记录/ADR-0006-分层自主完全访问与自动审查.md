# ADR-0006：分层自主、完全访问与自动审查

- 状态：Accepted（方向）；范围细节待后续决策
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

在产品已经确定以通用个人执行 Agent 为主、同时保留一等编程能力之后，需要继续确定运行时默认自主程度。用户选择“分层受限自主”，并明确要求产品必须保留“完全访问权限”选项和类似 Claude Code 的自动审查选项。

## 决策

1. 默认采用分层受限自主，不采用每一步都询问的纯工作流，也不默认进入无限自主执行。
2. 同一个 Runtime 可按任务需要从“直接执行”升级到“单 Agent 计划与工具循环”，再升级到“并行协作或编排”，最后按需进入“独立只读审查”。界面不必要求用户理解五种内部工作流名称，但必须显示升级原因、当前阶段、预算和停止入口。
3. 将以下三项设计成彼此独立的维度：
   - 自主程度：如何规划、拆分、并行、等待和停止。
   - 权限级别：哪些工具可以执行，是否需要逐次批准。
   - 审查级别：完成后是否运行确定性检查和独立审查请求；审查只报告，不自动修复。
4. 产品必须提供显式“完全访问权限”选项。它用于减少已约定范围内的重复确认，不代表模型可以提升权限、修改模型自身、修改 Harness 系统边界、读取秘密明文、关闭审计或越过预算和停止规则。
5. 产品必须提供可选自动审查。主执行与审查角色保持区分，优先使用构建、测试、类型检查、lint、差异检查和任务验收等确定性证据；模型审查作为补充，不以“模型说已审查”代替证据。
6. 审查结果必须显示发现、证据、建议、审查轮次、Token/时间消耗和停止原因；不得只给一个无依据的绿色标记。
7. 自主运行必须有工具轮次、并行数、审查轮次、时间、Token 和成本上限；应用级并行数后续确定为默认 3、高级设置可调 1–8，见 `ADR-0021-全局并发默认三可调一至八.md`。

## 收益

- 新手默认得到简单、可控的体验，高级用户仍可用完全访问完成复杂项目和编程任务。
- 编排能力可以按复杂度升级，却不会因此偷偷扩大文件、终端、网络或系统权限。
- 自动审查提高交付可靠性，同时保留确定性验证与模型判断的事实边界。
- 三个独立维度可让桌面端和 CLI 共用同一运行合同。

## 代价与风险

- 设置和运行状态比单一“自动模式”更复杂，需要良好的渐进披露。
- 完全访问可能扩大误操作影响，必须进一步确定作用范围和持续时间。
- 自动审查会增加延迟和 Token；发现的问题必须通过一项新的用户发起任务修复。ADR-0059 后产品不维护金额。
- 多 Agent 审查若共享全部上下文，容易形成回声确认，因此后续要规定独立证据和上下文边界。

## 明确不等价

- “深度执行”不等于“完全访问”。
- “完全访问”不等于关闭日志、秘密保护、预算、禁止自修改或系统边界。
- “自动审查”不等于让模型自称已检查，也不拥有自动修复能力。
- “多会话并行”不等于共享完整会话历史或自动获得更高权限。
