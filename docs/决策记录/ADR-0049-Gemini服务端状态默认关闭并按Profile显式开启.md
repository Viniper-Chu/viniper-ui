# ADR-0049：Gemini 服务端状态默认关闭并按 Profile 显式开启

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

Gemini 的部分官方协议可以使用服务端交互标识续接状态，这可能减少重复发送并改善缓存或延迟，但也会把会话状态留在第三方服务端。用户选择方案 C：默认关闭 Gemini 服务端状态，只允许在具体 Provider profile 中明确开启，并在开启前说明保存、保留和删除语义。

## 决策

### Harness 默认状态为关闭

- 新建和迁移的 Gemini profile 默认 `server_state=off`；本地 SQLite 中的结构化历史始终是会话恢复、审计和跨端同步的权威真源。
- 关闭时，适配器使用本地历史构造每轮请求，不保存或复用服务端交互标识；如果所选端点支持明确的存储关闭字段，适配器按其当前官方协议映射。
- `server_state=off` 是 Harness 的统一设置语义，不要求所有 Gemini 端点都接受字面参数 `store=false`。端点不支持该字段时不得发送虚构参数，只能使用不依赖服务端状态的调用方式。
- 模型选择、智能路由、导入旧 profile 或应用更新都不能暗中把该选项打开。

### 只能按 Profile 明确开启

- 用户在具体 Gemini profile 的高级设置中主动开启后，后续新 run 才可使用该端点支持的服务端交互状态，例如续接官方返回的交互标识。
- 开启前必须显示当前端点的已知保存内容、保留时间、删除方式、地区/账户影响和官方资料时间；无法从当前官方协议证明的字段明确标为“未知”，不能用笼统文案承诺不会保存或一定可删除。
- 每个 run 在开始时固定服务端状态设置和所用交互引用；运行中切换只影响之后的 run，不把已有会话突然接到另一个服务端链。
- 服务端交互标识只保存在该 profile 与会话的结构化元数据中，不作为个人记忆，也不跨项目自动共享。

### 关闭不等于删除既有远程状态

- 用户从开切回关，只阻止后续 run 创建或续接服务端状态，不宣称自动删除此前已经保存的远程交互。
- 只有适配器对所选官方端点拥有经过验证的删除 API 和成功回执时，产品才显示“删除远程状态”；否则只说明当前无法由 Harness 验证删除。
- 删除本地会话、导出归档、移除 profile 或清除本地交互标识，也不能冒充已经删除第三方服务端数据。

### 能力探测与回退

- Provider profile 明确记录端点协议和服务端状态能力。端点不支持、文档不明或请求拒绝该能力时，保存设置失败或 run 进入清楚错误，不静默切换到另一种保存模式。
- 缓存 usage、服务端状态和本地上下文压缩分别记账；不能把使用服务端交互标识显示为已经命中缓存，也不能用它替代 ADR-0040 的本地长会话策略。

## 产品表现

- Gemini profile 默认显示“服务端会话状态：关闭（使用本地历史）”；高级开关旁提供“会保存什么”和“如何关闭/删除”的说明。
- 开启后，会话状态区可显示当前是否正在续接服务端交互，但不会回显完整第三方标识。
- CLI 与桌面共享同一 profile 设置；非交互 CLI 不得自动开启。

## 收益

- 默认保持本地可控历史，不因追求缓存或便利把会话状态无声留在第三方。
- 有明确需求的用户仍可使用官方服务端续接能力。
- 关闭、删除和本地历史三者边界清楚，不制造“本地删了等于云端删了”的错觉。

## 代价

- 默认本地历史模式可能重复传输更多上下文，并错过部分服务端续接收益。
- 不同 Gemini 端点的字段、保留和删除能力需要按当前官方资料持续适配。
- 已经发送的远程状态在没有删除 API 时不能由 Harness 保证清除。

## 与既有决策的关系

- 细化 `docs/API适配矩阵-v0.1.md` 中 Gemini Interactions 的本地历史默认策略。
- 保持 ADR-0030/0032/0040 的本地历史、结构化真源和上下文压缩合同；服务端状态不能取代它们。
- profile 的网络、凭据和 run 快照分别遵守 ADR-0031/0048；导出按 ADR-0044 排除秘密并清楚标记远程状态引用。
- 本 ADR 是后续目标设计；Gemini 真实鉴权、状态保存、保留、删除和缓存效果均为 `UNPROVEN`。
