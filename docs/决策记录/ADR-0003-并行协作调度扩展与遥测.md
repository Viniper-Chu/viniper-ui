# ADR-0003：并行协作、调度、扩展与 Token 遥测

状态：已接受；第 1 项并发规则由 ADR-0025 修订，第 6 项插件边界由 ADR-0029 扩展，第 7 项秘密端口目标由 ADR-0031 扩展，适用于 `v0.0.1 Preview` 内部更新

日期：2026-08-12

## 背景

Phase 1 已具备单会话内运行、队列、取消和多会话数据隔离，但还没有显式跨会话协作、Token usage、定时任务、真实 Provider、安全密钥或 Skills/插件执行主线。用户要求同时吸收 Codex、Claude Code 与 Hermes 的有用架构，同时不采用它们作为运行框架。

## 决策

1. 不建立全局串行队列。早期“每个 sessionId 最多一个当前 run”规则已经取消；当前规则允许同一 sessionId 的独立 run 并行，并在实际资源冲突时使用窄队列，见 `ADR-0025-同会话任务冲突感知智能并行.md`。ADR-0020 继续保留为这项规则的历史来源。
2. 跨会话只通过持久化 `CoordinationEnvelope`；信封包含来源、目标、类型、关联委派和状态，不共享对方完整消息历史。
3. 委派使用目标会话自己的 Provider、权限、Skill 和工具快照。完成后只回传结构化结果；父会话可显式等待、取消等待或继续别的任务。
4. `TokenLedger` 接收估算事件和 Provider 最终 usage。最终 usage 覆盖本次估算，但保留估算来源标记；聚合按 run/session/app 分层。
5. Scheduler 持久化定义与历史，支持一次、固定间隔、每日和每周；触发目标为现有会话或每次新建隔离会话。本阶段只承诺应用运行时执行。
6. SkillCatalog 启动只索引元数据，启用时才读取完整正文。插件最初只接收声明式清单；现行目标按 ADR-0029 区分 Skill、MCP 和可执行插件，可执行插件必须明确安装信任并进入受管子进程。未知可执行代码默认不运行。
7. Renderer 始终只能写入、删除和询问“是否已配置”，不能读取明文。当前桌面实现由主进程 `SecretVault` 与 Electron `safeStorage` 持有；桌面/CLI 共享目标按 ADR-0031 迁移到 Runtime 所有者唯一持有的 `PlatformCredentialVault`，未完成前 CLI 继续 fail-closed。
8. DeepSeek 使用原生适配器与模型发现；请求上下文稳定排序，运行中冻结工具/Skill 快照，保护前缀缓存。

## 影响

- 新增独立功能域 `coordination / telemetry / scheduler / skills / plugins / secrets` 与 `platform/security`，避免把所有新规则堆入 AgentRuntime。
- SessionSnapshot 增加派生摘要，不直接嵌入秘密；持久化 schema 需要显式迁移，不能破坏 Phase 1 数据。
- 插件“可发现”不等于可执行；可执行层现按 ADR-0029 要求安装信任、清单、受管子进程和统一工具权限。
- 应用退出后的后台调度和 macOS 真机不由本 ADR 证明。

## 被否决方案

- 用全局共享对话实现会话协作：会破坏隔离、缓存和可追溯性。
- 把所有 Provider 都压成最低公分母的 OpenAI-compatible 结构：会丢失缓存、reasoning、usage 和错误差异。
- 把 Key 放进环境变量文件或 renderer localStorage：不满足桌面秘密边界。
- 每个流式 token 都写磁盘并全量重绘：会造成高频 IO 和界面抖动；采用节流 UI 与最终事件对账。
