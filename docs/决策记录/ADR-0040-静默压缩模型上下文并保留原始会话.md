# ADR-0040：静默压缩模型上下文，并保留原始会话历史

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

超长会话如果完全依靠用户手动压缩，容易在执行中撞到模型上下文上限；每次压缩都要求确认又会打断普通用户。用户选择方案 A：Runtime 在后台静默总结并用摘要替换较早上下文。

## 决策

### 替换的是模型上下文，不是永久会话记录

- 当即将构建的 Provider 请求接近当前模型的安全上下文阈值时，Runtime 自动选择已完成的较早轮次生成压缩摘要，并在后续 Provider 上下文中用该摘要替代这些原始轮次。
- 原始 user/assistant 消息、工具调用/结果、协调信封、Token 和事件仍按 ADR-0038 永久保存在会话中并可查看；压缩不删除、归档或改写原始历史。
- 当前未完成的工具调用、待确认权限、最近对话窗口、活动任务目标、项目指令和稳定系统/工具前缀不进入可替换区，不能把正在执行的状态压成过去事实。
- 工具调用与对应结果必须作为完整单元处理，不能只保留调用或只保留结果。

### 静默自动执行

- 压缩不弹出确认框、不暂停任务，也不要求用户先阅读摘要；满足阈值后由 Runtime 自动执行。
- 摘要请求使用本次 run 已固定的 Provider、profile、model 和推理设置，或在新 run 开始前使用会话当前固定模型；不为压缩静默切换厂商或把会话广播给第二个模型。
- 摘要只获得历史读取能力，不调用文件、命令、外部服务或其他状态变更工具。
- 压缩产生的输入/输出 Token、缓存和耗时进入统一 usage 账本，来源标为“上下文压缩”；ADR-0041 只统计不限制该消耗，ADR-0059 后不记录金额。

### 摘要快照与缓存

- 每次成功压缩形成不可变的摘要检查点，记录覆盖的消息范围、所用模型、创建时间和后续上下文 generation；原始正文仍通过会话历史关联，不复制到普通运行日志。
- 后续请求稳定复用同一个摘要检查点，直到新的历史增长再次需要压缩；不能每轮重新改写摘要导致缓存前缀持续变化。
- 压缩会开启新的 ContextProfile generation，旧 generation 的 Provider 缓存不冒充仍然命中；界面仍按 Provider 实际 usage 对账。
- 用户不需要在主时间线看到压缩提示，但高级上下文详情和审计事件可以查到“何时压缩、覆盖哪些轮次、产生多少用量”。

### 失败处理

- 摘要请求的传输错误可按 ADR-0023 在尚无摘要输出时重试；失败后不静默丢弃原始轮次、不换模型生成，也不使用截断文本冒充完整摘要。
- 如果无法在模型上限内安全构建摘要请求或压缩仍不足以继续，当前 run 停在“上下文容量不足”，展示重新开始会话或用户主动选择范围的入口。

## 产品表现

- 默认体验中压缩不打断任务；Token 面板可看到单列的“上下文压缩”用量。
- 原始会话时间线仍能完整滚动和搜索，不用摘要替换用户看到的旧消息。
- 高级 ContextPanel 显示当前摘要覆盖范围和 generation，但普通用户不需要管理检查点。

## 收益

- 长会话可以持续运行，不依赖用户理解上下文窗口。
- 主会话历史保持完整，自动摘要只影响后续模型输入。
- 摘要检查点稳定复用，避免每次请求都破坏缓存身份。

## 代价

- 自动摘要可能遗漏细节，并在用户没有逐次确认时影响后续推理。
- 压缩本身产生额外 Token 和延迟。
- 原始历史永久保存且摘要另占结构化空间，数据根会继续增长。

## 与既有决策的关系

- 与 ADR-0038 共同规定“历史永久保存、模型上下文可静默压缩”，两者不矛盾。
- 不改变 ADR-0028 的 run 固定模型，也不改变 ADR-0023 的传输重试上限。
- 本 ADR 是后续目标设计，当前自动阈值、摘要质量、缓存代际和真实长会话表现均为 `UNPROVEN`。
