# ADR-0043：自动检查和下载更新，由用户确认安装

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

静默自动安装最省操作，但可能中断活动任务并在用户不知情时改变行为；完全手动检查又容易错过修复。用户选择方案 C：自动检查并下载应用更新，展示更新内容，由用户确认安装和重启。

## 决策

### 自动检查与下载

- 当前 Runtime 所有者在应用启动后和合理的运行间隔内检查官方应用更新通道；桌面与 CLI 共用检查状态，不重复下载同一包。
- 发现适用于当前操作系统、架构和渠道的新版本后，可以自动下载到数据根的受管更新暂存区，并显示版本、大小、发布日期、主要变化和是否需要数据迁移。
- 检查或下载失败不影响当前版本继续运行；离线缓存不能冒充“已经是最新版”。
- 应用更新只接受 Viniper Harness 配置的正式发布通道。ADR-0036 的公共插件市场、自定义来源和本地扩展不能发布或替换 Harness 本体。

### 安装必须由用户确认

- 下载完成后状态为“更新已准备”，不静默安装、不自动重启，也不在退出时偷偷替换程序。
- 用户可选择“稍后”或“安装并重启”。存在活动 run、审查、迁移或未完成外部动作时，默认保留更新并等待空闲；用户明确选择立即安装时，先显示哪些任务会停止或留待 ADR-0042 恢复。
- CLI 可以显示和下载更新，但涉及替换当前安装与重启时使用相同确认语义；非交互 CLI 不自动安装。
- 安装确认只授权这一份已展示的应用版本，不授权 Agent、模型、Skill、MCP 或插件修改 Harness 自身。

### Preview 与未来稳定通道分开

- 当前产品只属于 `0.0.1 Preview`，默认订阅 Preview 更新；不得把预览更新写成 Beta、公测、RC 或稳定版。
- 以后存在稳定通道时，用户可以显式切换；稳定通道不会自动接收更激进的 Preview 构建，Preview 也不会因为版本号变化被冒充正式发布。
- 更新说明必须区分功能、修复、数据格式变化和仍未证明的平台能力，不用“全面支持”覆盖 `UNPROVEN` 项。

### 安装、数据与失败恢复

- Windows 更新目标使用当前用户可验证的正式安装包和发布身份；macOS 目标还需签名、公证、arm64/x64 和原生更新流程真机验证。
- ADR-0039 决定不做日常自动备份。更新若包含 ADR-0032 的 schema/数据迁移，只能使用该维护操作的一次性回滚副本，不能借更新建立滚动备份历史。
- 安装失败时继续保留当前可运行版本或清楚报告无法启动；不得先删除当前程序再判断新包是否可用。
- 更新暂存包属于可再下载文件，可以在确认已安装或明确取消后清理；不能连带删除会话、凭据、项目、插件数据或工作成果。

## 产品表现

- 设置与状态区显示“正在检查 / 正在下载 / 已准备 / 等待空闲 / 安装失败 / 已是当前已知版本”。
- 更新卡以简短人话列出变化，主按钮为“安装并重启”，次要按钮为“稍后”。
- CLI 的状态输出与桌面一致；JSONL 只输出结构化更新事件，不夹带交互提示或 ANSI。

## 收益

- 用户能及时获得修复，又不会在任务执行中被静默重启。
- 下载与安装分开，普通用户只需在准备完成后做一次决定。
- 应用更新源与开放插件市场严格分离，模型不能借扩展机制修改自身 Runtime。

## 代价

- 自动检查和下载会使用网络和磁盘空间。
- 用户长期选择“稍后”时仍可能停留在旧 Preview。
- 跨平台更新、安装占用、数据迁移和失败回退需要单独验证。

## 与既有决策的关系

- 不改变禁止模型和插件修改 Harness 自身的系统边界；更新器是受管平台能力，不是 Agent 工具。
- 安装时的活动任务按 ADR-0042 形成可恢复状态，数据迁移按 ADR-0032/0039 的一次性回滚规则执行。
- ADR-0047 单独管理 Skill、MCP 和插件更新：全部扩展版本都要用户确认，不能与本 ADR 的应用更新确认合并授权。
- 本 ADR 是后续目标设计，当前正式更新服务器、Windows 安装闭环和 macOS 更新均为 `UNPROVEN`。
