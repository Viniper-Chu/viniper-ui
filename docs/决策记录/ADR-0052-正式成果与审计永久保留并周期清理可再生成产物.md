# ADR-0052：正式成果与审计永久保留，周期清理可再生成产物

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

全部永久保留会让构建缓存、下载和临时文件持续占用磁盘；按时间统一清理又可能删除最终成果或运行证据。用户选择方案 C：正式成果和审计记录不自动删除，可再生成缓存与临时构建物按可调周期清理。

## 决策

### 先按生命周期分类

1. **正式与审计数据**：会话、消息、run 事件、Token/缓存账本、权限/外部动作回执、长期记忆、用户标记的最终成果、ADR-0054 的完整工具输出和 ADR-0061 的单次详细诊断。它们不按时间自动删除，只能由用户明确删除所属数据或单独清理。
2. **受专门恢复规则保护的数据**：隔离 worktree、迁移回滚副本和更新暂存包继续使用各自 ADR 的期限与条件，不被通用清理器提前处理。
3. **可再生成产物**：没有被标记为正式成果的构建输出、测试临时目录、下载缓存、索引缓存、缩略图和其他明确声明可重建的受管文件。只有这一类可以周期清理。
- 用户项目目录中的源码、文档、数据库和其他文件不属于 Harness 可再生成产物，清理器永不扫描或删除。

### 可再生成产物默认保留 30 天

- `v0.0.1 Preview` 初始默认周期为 30 天，设置中可选择 7 天、30 天、90 天或“永不自动清理”。
- 周期按最后实际使用时间计算；仍被活动 run、待审查任务、恢复记录或导入/导出事务引用的产物不进入清理候选。
- 用户可随时查看各类别占用并手动清理选中的可再生成产物；界面显示预计释放空间和不会触碰的正式数据。
- 调整为更短周期只影响下一次清理，不在保存设置的同一动作中立刻删除文件。

### 清理只由当前 Runtime 执行

- 清理只在桌面或 CLI Runtime 所有者运行且空闲时执行，不安装后台服务，也不因应用退出继续删除。
- Runtime 只根据 SQLite 中已登记为 `regenerable` 的受管相对路径处理；未知文件、引用不完整或分类不明时保留并显示“需检查”。
- 清理完成记录类别、数量和释放空间，不记录被删除内容正文，也不把释放空间冒充备份或恢复能力。

### 删除后的产品语义

- 可再生成产物被清理后，数据库记录可以保留“已清理，可重新生成”的状态；需要使用时重新运行相应构建、下载或索引流程。
- 如果某个所谓缓存无法通过正式路径重新生成，它就不能登记为可再生成产物。
- 清理失败只报告未处理项，不把仍存在的文件显示为已删除。

## 产品表现

- 存储页按“正式数据 / 运行证据 / 恢复保护 / 可再生成”分组，不用一个总清理按钮混合全部数据。
- 默认文案为“自动清理可再生成文件：30 天”，旁边明确写出“不会删除会话、记忆、最终成果或完整工具输出”。
- 空间不足时可以打开管理页，但不自动扩大删除范围。

## 收益

- 保留可追溯成果的同时控制缓存和临时构建物增长。
- 30 天默认值对普通用户无需配置，高级用户可延长或关闭。
- 清理范围由显式分类决定，不会碰用户项目。

## 代价

- 需要每类产物准确声明是否可再生成及最后使用时间。
- 选择“永不自动清理”时磁盘占用仍会持续增长。
- 被清理的构建物或缓存再次使用时需要时间重建。

## 与既有决策的关系

- 细化 ADR-0032 的受管文件生命周期，不改变 SQLite 结构化真源和文件引用合同。
- 不改变 ADR-0034 的 worktree 七天恢复、ADR-0038 的会话永久保留、ADR-0039 的无自动备份或 ADR-0045 的长期记忆永不自动删除。
- ADR-0054 的完整工具输出属于运行证据，不进入可再生成周期清理。
- ADR-0056 的项目索引、未完成模型下载块和转换缓存可登记为可再生成；ADR-0058 中用户明确安装的模型权重、ADR-0060 的 previous 扩展包和 ADR-0061 的单次详细诊断不能被通用周期清理。
- ADR-0066 的词法/符号/语义索引和 ADR-0067 的索引检查点可删除重建；ADR-0063 保留的本地模型新旧版本都属于用户明确安装的权重，只能手动删除。
- 本 ADR 是后续目标设计；产物分类、30 天调度、占用统计和真实删除边界均为 `UNPROVEN`。
