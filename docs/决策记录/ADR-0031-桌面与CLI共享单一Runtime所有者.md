# ADR-0031：桌面端与 CLI 共享单一 Runtime 所有者

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

桌面端与 CLI 使用完全分开的数据根容易实现，但任务、Token、会话和设置会分叉；让 CLI 必须依赖桌面窗口又失去原生终端的独立价值。用户选择方案 C：两端共用同一个核心和默认数据仓库，桌面运行时 CLI 连接桌面 Runtime，桌面未运行时 CLI 可以成为无界面 Runtime 所有者，任何时刻只允许一个写入者。

## 决策

### 一个数据根只有一个 Runtime 所有者

- 默认桌面端和 CLI 使用同一正式数据根、会话、任务、Token、Provider profile、扩展目录、记忆和全局并发设置。
- 目标存储按 ADR-0032 使用 SQLite 保存结构化权威状态、受管文件保存大型日志和产物；无论介质如何，只有 Runtime 所有者可以经正式持久化端口写入。
- 第一个打开该数据根的正式进程成为 Runtime 所有者，独占持久化写入、调度器、run 队列、资源锁、Provider 调用和 SecretVault 端口。
- 后续桌面或 CLI 进程作为客户端，通过本机 IPC 调用所有者提供的正式应用服务和订阅事件；客户端不得绕过服务直接修改 JSON、NDJSON、数据库或秘密存储。
- 桌面端运行时，CLI 通常连接 Electron 主进程中的 Runtime；桌面端未运行时，用户启动的 CLI 可以在自己的进程中启动无界面 Runtime，并成为所有者。

### 发现、连接与交接

- Windows 使用当前用户范围的命名管道或等价本机 IPC；macOS 草案使用当前用户范围的 Unix domain socket。端点只接受同一系统用户，并使用进程启动时生成的短期连接凭据。
- 所有者保存带进程存活和租约信息的发现记录；发现活动所有者时，新进程只能连接，不能以“锁文件疑似过期”为由直接双开写入者。
- 如果桌面在 CLI 所有者运行时启动，桌面先作为客户端接入。所有权只能在状态已落盘、没有未完成写事务且活动 run 可以安全保持或已结束的交接点转移；不能迁移时继续由原所有者运行并清楚显示。
- 所有者退出但仍有客户端时，优先向合格客户端进行显式、可记录的安全交接；交接失败则客户端进入断开状态，绝不自行双写。
- 所有者异常结束后，新进程必须完成租约失效确认和存储恢复检查，再成为新所有者；PID 文本或单个锁文件不能单独证明安全。
- 新所有者完成接管后，按 ADR-0042 自动恢复异常中断的 run，并重放没有完整结果的 Provider/工具步骤；已持久化成功回执的步骤不重放。
- 项目完全访问和普通持久状态可以按既有合同由新所有者重新加载；电脑完全访问令牌只存在原所有者内存，所有权交接或原所有者退出时立即失效，不通过 IPC 迁移。需要该权限的 run 或自动任务在新所有者中进入“等待重新授权”。

### 不新增永久后台服务

- Runtime 所有者只能是正在运行的 Electron 主进程或用户显式启动的 CLI 进程，不安装 Windows Service、Task Scheduler、开机项、macOS LaunchAgent 或独立常驻 daemon。
- 桌面和 CLI 都完全退出后，没有 Runtime、调度或 Provider 请求；自动任务继续按 ADR-0017 记录离线点并在下次启动后处理。
- 同时打开桌面和 CLI 不会创建第二个调度器、第二套并发名额或重复触发自动任务。

### 共享凭据端口

- 目标架构使用 `PlatformCredentialVault`：Windows 采用当前系统用户保护的凭据/DPAPI 适配，macOS 采用 Keychain；Runtime 所有者是唯一解密端口。
- 桌面 renderer 和 CLI 客户端只能提交写入、删除、选择引用和查询“是否已配置”，不能读取或回显明文。
- 旧 Electron `safeStorage` 数据只有在桌面端能够安全解密时才迁移；迁移先验证新存储可读，再保留可回滚记录。未完成共享 Vault 前，CLI 对需要桌面秘密的任务继续 fail-closed，不能把 Key 降级写入普通文件。

### 独立数据根仍可显式使用

- 测试、演示或用户显式指定的 `--data-root` 可以创建隔离实例；它拥有自己的 Runtime 所有者、数据和并发上限，不与默认实例冒充同步。
- 同一路径仍严格单写者；不同数据根的隔离实例在界面和 CLI 中必须明确标识。
- ADR-0050 进一步规定普通产品只有当前设备的一个默认本地身份和数据根；隔离实例不升级为账号、多身份或跨设备同步系统。

## 产品表现

- 桌面状态区和 CLI `/status` 显示“Runtime：桌面所有 / CLI 所有 / 已连接”，但普通用户不需要手动配置端点。
- 从桌面创建的会话、任务和 Token 统计立即可在已连接 CLI 中看到，反之亦然。
- 连接失败时显示正在占用的数据根、可重试连接或使用隔离实例，不能偷偷回退为第二套数据。
- 所有权交接、断开恢复和隔离数据根进入审计事件。

## 收益

- 桌面和 CLI 真正共享会话、任务、Token、权限状态和调度，而不是只有代码复用。
- CLI 在桌面关闭时仍可独立完成 Agent 任务。
- 单一写入者消除两个进程同时改写数据和重复调度的风险。

## 代价

- 本机 IPC、所有权租约、安全交接和崩溃恢复增加实现复杂度。
- CLI 所有者运行活动任务时，桌面接入后可能暂时只能作为客户端，不能立即接管。
- 现有 Electron `safeStorage` 与独立 CLI 数据根需要受保护迁移，不能直接合并文件。

## 与既有决策的关系

- 落实 ADR-0005 的桌面/CLI 编程执行真源和 ADR-0021 的共享全局并发设置。
- 保留 ADR-0017 的“只有用户运行程序时调度”，本 ADR 的无界面 Runtime 不是独立后台服务。
- ADR-0032 已确定结构化状态与大型文件的混合事务模型；当前文件存储仍须按其迁移合同另行实施和验证。
- ADR-0042 细化所有者异常结束后的 run 恢复；它不允许跳过本 ADR 的租约确认、存储恢复或电脑完全访问失效规则。
- ADR-0048 细化共享 Provider profile 的网络配置：默认跟随系统，按 profile 的代理和自定义信任证书由同一 Runtime 所有者投射，秘密仍只进入平台凭据库。
- ADR-0050 明确本机共享 Runtime 不能作为远程访问端口；跨设备普通数据通过 ADR-0044 手动归档，portable 秘密只通过 ADR-0057 的独立加密密钥包迁移。
- 修订 Phase 3 v0.6 中“CLI 默认独立 Preview 数据根”的实现阶段限制；该旧合同和验收事实仍保留为历史，不冒充已经完成共享迁移。
