# ADR-0047：所有扩展更新均需用户确认

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

让纯 Skill 自动更新可以减少操作，但它仍会改变后续 Agent 的指令、工具说明和缓存前缀；只拦截可执行插件又会让“看起来没有代码”的更新无声改变行为。用户选择方案 B：发现任何 Skill、MCP 或插件更新时通知，所有扩展更新都必须由用户确认。

## 决策

### 可以检查更新，不能静默更新

- 扩展中心可在启动后的合理间隔或用户打开页面时检查已启用来源的版本元数据，并显示可用更新；来源离线时保留当前版本并如实显示上次检查时间。
- Skill、MCP 本地包、可执行插件和扩展清单的每次版本替换，都必须先由用户确认；纯文本 Skill 也不例外。
- 未确认前不下载并安装、不替换当前文件、不激活新版本，也不把“检查更新”解释为安装授权。
- 用户可以明确勾选多项并一次确认，但每项都必须在清单中可见；不能默认全选或在应用更新确认中夹带扩展更新。

### 确认页展示行为变化

- 更新卡显示实际来源、当前版本、新版本、发布者声明、更新说明，以及清单、入口、工具、权限和外部目标是否变化。
- 新增或改变可执行入口、权限、外部目标、数据范围或信任身份时，除更新确认外还必须按 ADR-0029 重新确认信任；一次普通版本确认不能绕过能力变化。
- 只有说明文本改变且能力清单不变的 Skill 仍需更新确认，但不额外制造可执行插件信任页。
- 来源无法确认、包格式不匹配或更新说明缺失时可以继续使用旧版本，不能为追求最新而猜测入口。

### 运行中的快照保持不变

- 每个 run 继续固定其 Skill、MCP 和插件版本与工具快照；用户确认更新只影响之后开始的 run。
- 更新失败、回滚或来源消失不影响当前已加载 run；扩展中心保留旧版本并显示失败原因。
- 对远程托管且用户无法本地安装的 MCP 服务，Harness 只能报告服务声明的版本或能力漂移；若能力清单变化，后续连接需重新查看并按信任规则确认，不能声称已替远端完成更新。

### 与应用更新严格分离

- ADR-0043 的 Harness 应用更新仍可自动下载官方包并由用户确认安装；扩展市场不能更新应用本体。
- 扩展更新确认只授权列出的扩展版本，不授权应用升级、Provider 配置改变、秘密迁移或 Agent 修改自身。

## 产品表现

- 扩展中心统一显示“有更新 / 等待确认 / 正在更新 / 更新失败 / 已固定版本”，并按 Skills、MCP、插件分类。
- 普通用户先看到“它会改变什么”；高级详情再展示 manifest 与版本信息。
- CLI 可以列出和交互确认更新；非交互 CLI 没有显式 `--confirm` 及精确目标时只报告，不安装。

## 收益

- 所有会改变 Agent 行为的扩展版本都在用户知情后生效。
- 运行中快照不变，避免更新破坏正在执行的任务和 Provider 缓存前缀。
- 开放市场仍可使用，同时保留来源、能力和信任的可追溯性。

## 代价

- 纯 Skill 的小更新也多一次确认，用户可能长期停留在旧版本。
- 多来源版本比较、差异展示和旧版本保留需要额外实现。
- 远程 MCP 服务并不总能提供可靠版本信息，只能如实报告能力变化。

## 与既有决策的关系

- 收紧 ADR-0029/0036 的更新行为：不仅可执行插件，所有 Skill、MCP 和插件更新都禁止静默安装。
- 保持 ADR-0029 的运行快照与重新信任规则；公开市场可发现不等于新版本已获信任。
- 与 ADR-0043 的应用更新通道完全分开。
- ADR-0060 细化旧版本保留：正常保存 current 与一个 previous，更新和回退都需确认，活动 run 快照优先保留。
- 本 ADR 是后续目标设计；当前扩展更新检查、差异页、确认安装和失败回退均为 `UNPROVEN`。
