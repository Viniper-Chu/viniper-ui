# ADR-0048：默认使用系统网络并支持按 Provider 代理与自定义证书

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

只跟随操作系统网络最简单，但企业、校园、地区网络和私有兼容端点常需要独立代理或自定义信任证书；全局代理又可能把不相关 Provider 和更新流量送到同一路径。用户选择方案 C：默认遵循系统网络与代理，高级设置允许按 Provider profile 配置代理和自定义证书。

## 决策

### 默认跟随操作系统

- 没有 profile 覆盖时，Windows 使用当前用户的系统网络、代理和受信任证书链；macOS 目标使用当前用户的系统网络配置与 Keychain 信任链。
- 桌面端与 CLI 通过同一 Runtime 网络端口发出 Provider 请求，因此同一个 profile 在两端使用一致配置，不各自读取一套隐藏代理变量。
- 连接测试和错误回执显示“系统网络”或“此 Provider 的高级网络”，但不回显代理凭据。

### 按 Provider profile 覆盖

- 每个 Provider profile 可选择“跟随系统”或配置该 profile 专用的 HTTP/HTTPS 代理，以及运行库真实支持时的 SOCKS 代理；未支持的类型不展示为可用。
- 可为私有或受管端点添加该 profile 专用的自定义 CA/信任证书；它只扩展该 profile 的证书验证范围，不修改操作系统全局证书库。
- 不提供“忽略证书错误”或关闭 TLS 验证的便捷开关。需要客户端证书的双向 TLS 属于后续独立能力，不能把自定义 CA 配置冒充为已支持 mTLS。
- profile 的代理、证书引用和 endpoint 在 run 开始时进入不可变网络快照；运行中修改只影响之后开始的 run。

### 秘密与范围

- 代理用户名/密码和证书私钥（若未来支持）只保存在 `PlatformCredentialVault`；普通设置、renderer、日志、诊断报告和 ADR-0044 的普通数据归档只保存非秘密引用。
- Provider profile 专用代理只作用于该 Provider 请求。应用更新、公共扩展市场、MCP 连接和诊断上传默认继续使用各自声明的系统或专用网络策略，不能被某个模型 profile 静默接管。
- 自定义 endpoint 与自定义证书必须同时显示实际目标主机，避免用户误以为仍在连接官方域名。

### 连接测试与失败

- 保存前可执行不生成内容的连接测试，分别验证代理可达性、TLS 信任和 Provider 鉴权阶段，并把失败分类为网络、代理、证书或 Provider 响应。
- 测试失败不自动回退到绕过代理、关闭证书校验或其他 profile；用户明确修改后再试。
- 系统代理或证书在 run 中失效时，按普通网络错误和 ADR-0023 的边界处理，不静默改变路由。

## 产品表现

- Provider 编辑页默认只显示“网络：跟随系统”；展开“高级网络”后才出现代理地址、凭据引用和自定义信任证书。
- Windows 与 macOS 使用相同概念和状态文字，平台选择器、证书文件权限和系统信任实现分别放在 `platform`。
- CLI 读取同一 profile；命令行参数如需临时覆盖，必须明确显示且只作用于本次 run，不能把秘密写进历史命令建议。

## 收益

- 普通用户无需配置，高级网络环境又能按 Provider 精确接入。
- 不相关服务不会因一个 Provider 的代理设置被一起改道。
- 自定义 CA 保留 TLS 验证，比关闭校验更清楚可靠。

## 代价

- 系统代理、HTTP/SOCKS、证书链和跨平台差异需要分别验证。
- 同一用户配置多个 Provider 时可能需要维护多套网络资料。
- 本决策不包含 mTLS 客户端证书，少数企业端点仍需后续扩展。

## 与既有决策的关系

- 扩展 ADR-0031 的共享 Provider profile 与 `PlatformCredentialVault`；桌面和 CLI 不重复保存秘密。
- 不改变 ADR-0023 的重试边界，也不允许智能模型分配因网络失败静默换 Provider。
- ADR-0053 的模型目录刷新使用同一 profile 网络配置；代理、证书或网络失败不会被解释为权威空目录。
- 普通导出、匿名诊断和扩展系统继续遵守各自数据与网络范围。
- 本 ADR 是后续目标设计；真实系统代理读取、按 profile 路由、自定义证书和 macOS 行为均为 `UNPROVEN`。
