# ADR-0009：完全访问包含外部操作

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

ADR-0007 与 ADR-0008 已确定完全访问的范围和持续时间，尚未确定它是否还要为发布、发送、付款和远程删除等外部动作再次询问。用户选择方案 A：完全访问全部包含，不做逐项二次确认。

## 决策

1. 普通按需确认权限仍可在外部写操作前请求批准。
2. 项目完全访问或电脑完全访问一旦有效，Viniper Harness 不再对当前会话中已经配置并启用的外部工具逐项弹出确认。
3. 无需二次确认的动作包括但不限于：
   - 公开发布、部署和上传；
   - 发送消息、邮件或通知；
   - 下单和付款；
   - 修改远程账号、仓库、云服务或协作平台权限；
   - 删除远程文件、数据、部署、分支或其他资源。
4. 用户选择完全访问时的那一次明确操作，就是对这些外部动作的 Harness 授权。权限摘要必须提前用人话写明“包含外部操作”，但执行期间不再插入重复确认框。
5. 项目级与电脑级仍用于限定本地文件、命令和应用范围；外部操作的可用范围由当前会话实际启用的工具和已连接账号决定。

## 不改变的边界

- 完全访问不能凭空创建账号、获得第三方服务没有授予的权限，或绕过服务自身强制的登录、验证码、支付验证和风控流程。
- Windows UAC、macOS 系统授权或第三方服务必须由用户完成的交互，仍按系统或服务要求进行；这不属于 Harness 的二次确认。
- Agent 不能读取凭据明文、修改自身、修改权限引擎或自行延长权限持续时间。
- 自动重试和自动审查不得重复已经确认成功的发送、付款、发布或删除。

## 产品表现

- 完全访问选择器明确显示：“包括已启用工具的发布、发送、付款、改远程权限和远程删除；执行时不再询问。”
- 每次外部动作完成后显示非阻断结果回执，包括服务、目标、动作、时间和 Provider 返回状态。
- 回执和审计不要求用户继续点击，也不会把完全访问重新变成逐步确认。
- 如果 Provider 返回结果不确定，界面如实显示“结果未确认”，不能将其标成成功或自动重复执行。

## 收益

- 完全访问真正适合无人值守或长链路任务，不会在最后一步等待用户点击。
- 桌面端和 CLI 的语义直接：普通权限会询问，完全访问不逐项询问。
- 发布、协作和云端任务可以与本地编程任务使用同一 Runtime。

## 代价

- 错误指令可能直接造成公开发布、错误发送、付款或远程删除。
- 项目完全访问不再只代表本地文件范围；用户必须理解它也会放开当前会话已启用的外部工具。
- 结果回执只能帮助追溯，不能保证第三方操作可撤销。
