# ADR-0026：完整编程能力采用分阶段实现与验收

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

ADR-0005 已确定 Viniper Harness 以通用个人执行 Agent 为主，但编程能力必须是一等能力。下一步需要决定首版只保留少量安全工具、一次性开放全部能力，还是在不缩水最终目标的前提下分阶段交付。用户选择方案 C：完整能力全部保留，按可独立验证的阶段逐步实现。

## 决策

### 最终 Preview 目标不缩水

同一正式 Runtime 最终必须覆盖完整编程闭环：

1. 识别项目、目录和语言，搜索并阅读代码、配置与文档；
2. 创建、修改、移动和删除用户项目范围内的文件，提供结构化差异与可追溯结果；
3. 运行项目终端命令、依赖操作、构建、类型检查、lint、测试和诊断；
4. 使用 Git 查看状态、差异与历史，并在权限允许时执行分支、提交、合并等项目操作；
5. 根据真实命令结果继续规划、修复或如实停止，并按既有自动审查合同复核交付物。

这些能力属于 `v0.0.1 Preview` 持续迭代的完整目标，不得因为面向新手而删除，也不得外包给 Claude Code、Codex、Hermes 或另一套编程内核。

### 分四个验收阶段

- 阶段 P1：项目发现、目录浏览、代码搜索和文件读取，只建立只读能力与上下文证据。
- 阶段 P2：范围明确的文件创建、编辑、补丁、移动和删除，必须展示差异、权限结果与失败原因。
- 阶段 P3：受控终端、依赖、构建、测试、lint、类型检查和诊断，把退出码、标准输出、错误与取消映射为正式事件。
- 阶段 P4：Git 状态、差异、历史、分支、提交、合并与结果复核，并与 ADR-0027 的工作区隔离协作。

每个阶段都要先建立失败用例和消费者级验收，再实现并回归此前阶段。通过 P1 不得宣称已经具备 P2–P4；最终只有四阶段均通过，才能称为“完整编程闭环”。

### 一条 Runtime 主线

- 全部编程工具注册到同一 ToolRegistry，复用同一 run、权限、资源锁、Token、Provider、缓存、协调、事件、取消和自动审查。
- 桌面端与 CLI 只负责不同呈现，不能复制工具语义或各自维护权限判断。
- 普通权限、项目完全访问和电脑完全访问继续按 ADR-0006 至 ADR-0009 执行；阶段顺序不会暗中扩大权限。
- 已安装的 Viniper Harness Runtime、系统边界、凭据、权限规则和工具注册表不是用户项目，任何权限模式都不能让模型修改自身。只有明确打开的用户项目进入编程工具范围。

### 渐进披露

- 新手默认只看到目标、计划、权限、当前步骤和结果。
- 进入代码项目后才显示文件差异、终端、Git、测试和诊断入口；高级细节可以展开，但不能隐藏失败、外部影响和停止入口。
- 能力是否存在由 Runtime 和工具目录决定，不由界面是否默认展开决定。

## 产品表现

- 项目标题区显示当前已验收能力，例如“可读取 / 可编辑 / 可运行测试 / 可使用 Git”，未实现能力明确写“尚未提供”。
- 每次编程 run 把读取、修改、命令、测试、Git 和审查按步骤分组，不用终端日志淹没普通用户。
- 桌面端可打开差异和测试详情；CLI 提供等价文本/JSONL 事件。

## 收益

- 完整编程目标得到保留，同时每一阶段都能独立诊断和验收。
- 新手路径不会因全部高级入口一次出现而变复杂。
- 权限、缓存和协作不会因编程功能另起一套系统。

## 代价

- 预览期会出现“部分编程阶段已完成、部分仍未证明”的过渡状态。
- 分阶段验收比一次性堆叠工具需要更多合同和回归测试。
- 桌面端也必须真实证明编程闭环，不能只以 CLI 可用代替。

## 与既有决策的关系

- 细化 ADR-0005 的编程一等能力，并解决其“第一批编程工具与开放顺序”待定项。
- P1 始终可用 ADR-0056 的词法/符号与实时搜索，ADR-0066 的语义索引只是可选增强；使用 ADR-0064 实验工具模拟完成的编程任务必须单列能力证据，不能替代原生工具合同验收。
- 权限边界继续由 ADR-0006 至 ADR-0009 管理；自动审查继续由 ADR-0010 至 ADR-0015 管理。
- 并发编程任务的工作目录策略由 ADR-0027 管理。
- ADR-0056 细化 P1 搜索：只为用户明确项目建立本地增量索引，索引不可靠时退回项目内实时搜索；不扫描整台电脑。

## 后续待定

1. 每个阶段的具体工具 schema、命令分类和 Windows 真机验收矩阵由后续任务合同发布，不由本 ADR 直接授权实现。
