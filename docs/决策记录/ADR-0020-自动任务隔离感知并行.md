# ADR-0020：自动任务隔离感知并行

- 状态：Accepted（同会话串行与能力快照级项目锁已由 ADR-0025 修订）
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

> 后续修订：用户于 2026-08-13 进一步选择同会话冲突感知智能并行。下文“同一会话串行”和“只要具有项目写入能力就锁整个项目”是历史规则，不再是现行合同。run 隔离、冲突可见、无全局串行队列等原则继续有效；当前完整规则见 `ADR-0025-同会话任务冲突感知智能并行.md`。

## 背景

Viniper Harness 已支持同一会话串行、不同会话并行。多个自动任务可能在同一时间到点：全部并行会让同一会话或同一项目互相覆盖，全部放入全局队列又会让无关项目彼此阻塞。用户选择方案 C：按会话和项目冲突隔离并行。

## 决策

### 历史规则：同一会话串行（已被 ADR-0025 替代）

- 每个 `sessionId` 同时最多运行一个 run。
- 手动任务、跨会话委派和自动任务进入同一个会话队列，不能绕过彼此。
- 同一会话内按进入可运行队列的顺序执行；后续任务显示“等待会话”。
- 等待消息本身不占运行槽位，也不阻塞其他会话。

### 不同会话和项目可以并行

- 不同 `sessionId` 的任务默认可以同时运行。
- 绑定不同项目的任务不因调度器存在而进入全局串行队列。
- 每个 run 仍使用自己的消息、权限、工具、Provider、Token、取消信号和错误状态，不共享隐形上下文。

### 历史规则：按工具能力锁项目（已被 ADR-0025 的实际资源锁替代）

- 同一项目的全部只读 run 可以并行。
- 只要一个 run 可能写入项目，它就与该项目的其他 run 互斥；后续冲突任务显示“等待项目”。
- “可能写入”由 run 开始时冻结的工具能力元数据判断，不依赖模型自报。包含文件写入、会改变项目状态的终端命令、Git 状态变更或项目数据修改能力时，按写入 run 处理。
- 项目以规范化工作区路径识别；新建隔离会话不会绕过同项目队列。
- 项目锁只保护对应项目，不冻结其他项目或整个应用。

### 队列与取消

- 排队项必须显示原因、目标会话/项目和进入队列的时间，开始后记录实际等待时长。
- 已进入队列的触发不记作“错过计划”，也不冒充正在运行。
- 用户可以取消单个等待项；取消不会停用自动任务定义，也不会取消其他会话的 run。
- 一个 run 结束、失败或取消后必须释放其实际持有的资源锁和等待项，再按 ADR-0025 的柔性优先级唤醒符合条件的任务；不再存在会话槽位。

## 与既有规则的关系

- 本决策细化 ADR-0003 的“同会话串行、不同会话并行”，不建立全局串行队列。
- 权限仍按 ADR-0016 判断；并发资格不会扩大任何任务的权限。
- 离线错过仍按 ADR-0018 合并补跑；补跑进入与普通任务相同的会话和项目队列。
- 自动审查使用只读新上下文，仍属于原 run 的完成阶段；在审查结束前只对本 run 实际修改过的资源保留稳定性保护，不阻塞其他资源或同会话的独立 run，具体按 ADR-0025 执行。

## 产品表现

- 自动任务列表区分“等待依赖”“等待具体资源”“等待空闲名额”和“正在运行”。
- 状态详情用人话说明，例如“同一项目正在被另一个任务修改”。
- 协作星图和会话侧栏继续分别显示各会话状态，不把项目锁误画成会话共享。
- Token、耗时和缓存统计只计入实际运行；排队等待时长单独显示。

## 收益

- 无关会话和项目保持真正并行。
- 同一会话不会出现消息、工具结果或取消信号串线。
- 同一项目的写入任务不会同时修改文件或 Git 状态。
- 用户能看到为什么等待，而不是误以为程序卡住。

## 代价

- 两个不同 run 只要实际争用同一写入或独占资源，仍必须排队。
- 工具无法可靠声明资源范围时会退化到较粗的项目、应用或账号资源键，部分无冲突操作仍可能保守排队。
- 即使会话和项目互不冲突，达到 ADR-0021 的全局上限或 Provider 更低的已知限制后仍需排队。
