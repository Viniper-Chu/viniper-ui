# ADR-0057：普通归档排除秘密并提供可选密码加密密钥包

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

让用户在新设备重新填写全部密钥最简单，但 Provider、代理、MCP 和插件较多时迁移成本很高；把密钥明文放进普通归档则不可接受。用户选择方案 C：普通数据归档继续默认排除全部秘密，同时提供一个完全独立、由用户主动创建并设置密码的加密密钥包。

## 决策

### 与普通数据归档彻底分开

- ADR-0044 的完整/选择性数据归档继续不含密钥、密码、权限令牌或证书私密材料；导出数据不会顺带勾选密钥。
- “导出加密密钥包”只出现在秘密与 Provider 设置中，必须由用户单独进入、选择条目、确认风险并设置密码。
- 密钥包只迁移，不同步；导入完成后两台设备各自保存和更新自己的秘密，不建立远程读取或自动合并。

### 只允许可携带的 Viniper 秘密

- 可选条目限于 Viniper 自己保存在 `PlatformCredentialVault` 且被类型合同标为 portable 的 Provider API Key、代理密码、MCP/插件凭据等。
- 系统登录令牌、Windows/macOS 账户绑定材料、系统证书私钥、临时权限令牌、电脑完全访问令牌、第三方服务端会话状态和 Viniper 不拥有的系统秘密不进入密钥包。
- 选择界面只显示安全标签、所属 profile/扩展和类型，不回显秘密正文；默认不选中任何条目。

### 密码保护与文件格式

- 密钥包使用版本化容器、内存困难型口令派生和经过审计的认证加密实现；具体算法套件和参数作为格式版本的一部分固定，并在实现任务合同中接受跨平台互操作测试。
- 导出密码要求用户输入两次，Viniper 不保存密码、提示答案或可恢复副本；忘记密码时无法恢复，只能回到原设备重新导出。
- 秘密只在 Runtime 所有者内存中完成读取、加密、解密和写入 Vault，不生成明文临时文件，不进入 renderer、日志、诊断或普通归档。
- 文件头只保留解密所需的格式版本和非秘密参数；条目名称等预览信息也放在加密正文中。

### 导入先验证再写入

- 用户选择密钥包并输入密码后，Runtime 先完整解密、验证格式和条目类型，再显示不含值的导入预览。
- 同名凭据逐项选择“保留本机 / 用密钥包替换 / 跳过”；默认保留本机，不能静默覆盖。
- 用户最终确认后才写入目标设备的 `PlatformCredentialVault`。验证或写入失败不得删除已有秘密，也不能把部分导入冒充整体成功。
- 导入后 Provider、MCP 或插件仍需按目标设备的连接、信任和系统权限合同验证；拥有密钥不等于连接一定可用。

## 产品表现

- 数据迁移页清楚分成“数据归档”和“加密密钥包”，并说明二者必须分别保存和导入。
- 导出完成页提示用户妥善保存密码与文件；不提供上传云盘、发消息或自动同步按钮。
- 导入结果按条目显示“已导入 / 已保留本机 / 已跳过 / 不支持”，不显示值。

## 收益

- 多 Provider 用户换设备时无需逐个重新输入全部可携带凭据。
- 普通数据归档继续保持非秘密、易检查的边界。
- Windows 与 macOS 可以通过同一版本化格式迁移，而秘密最终仍落入各自平台凭据库。

## 代价

- 用户必须自行保管密码；遗忘后没有恢复渠道。
- 加密格式、Vault 事务和跨平台互操作需要独立实现与测试。
- 一些系统绑定或第三方限制的凭据仍不能迁移。

## 与既有决策的关系

- 本 ADR 只扩展 ADR-0044/0050 的手动跨设备迁移；普通归档排除秘密的默认规则不变。
- 继续遵守 ADR-0031/0048 的 `PlatformCredentialVault`、当前用户范围和网络凭据边界。
- 本 ADR 是后续目标设计；加密容器、无明文中间件、冲突处理、Windows/macOS Vault 互操作和真实凭据导入均为 `UNPROVEN`。
