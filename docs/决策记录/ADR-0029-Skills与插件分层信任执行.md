# ADR-0029：Skills、MCP 与可执行插件采用分层信任

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

只允许内置 Skills 和 MCP 容易理解，但会限制生态；允许任意本地插件直接在主进程运行又会污染 Runtime、扩大权限并破坏可追溯性。用户选择方案 C：按能力层分开管理，普通 Skill 渐进加载，MCP 独立连接，可执行插件必须先安装和信任，再按统一权限运行。

## 决策

### 三层能力

1. **Skill**：指令、参考、模板和资产的渐进加载包。仅仅读取 `SKILL.md` 不执行代码；Skill 中若包含脚本，执行脚本时按可执行工具规则处理。
2. **MCP 连接**：本地或远程的独立工具服务，通过声明的工具 schema、连接状态和凭据引用接入；未经配置的 MCP 不自动启动或联网。
3. **可执行插件**：包含本地可执行代码的扩展包，必须有清单、明确安装动作和信任记录，并在独立子进程中运行，不能把未知代码加载进 renderer、Electron 主进程或核心 Runtime 内存。普通子进程是故障隔离边界，不得冒充已经通过验证的敌对代码安全沙箱。

### 安装信任与运行权限分离

- 可执行插件清单至少声明名称、版本、来源、入口、所需文件/网络/进程/外部服务能力、贡献的工具和数据目录。
- 分发来源按 ADR-0036 对公开市场、公开直链、自定义来源和本地包开放，不要求先进入 Viniper 官方精选目录；公开上架不等于已受信任。
- 首次安装显示人话信任页；用户明确安装并信任后，Runtime 才注册其工具。发现文件或扫描目录不等于信任。
- 所有 Skill、MCP 和插件更新都按 ADR-0047 先等待用户确认；如果新增入口、权限、外部目标或可执行内容，还必须重新确认信任。
- 信任只说明“允许这份插件代码被加载到隔离进程”，具体工具调用仍经过普通权限、项目完全访问或电脑完全访问的统一状态机。
- 完全访问可以免除已信任插件工具的逐次批准，但不能自动信任未安装、未知来源或权限发生变化的插件。

### 进程与数据边界

- 可执行插件使用环境变量最小化的受管子进程、独立数据目录和窄 IPC；Runtime 只通过能力代理交付清单声明且当前权限允许的数据与动作，不向插件传递 Provider Key、权限数据库或其他插件数据。
- 在没有 Windows AppContainer、macOS sandbox 或等价平台隔离的真实证据前，清单中的文件/网络限制是信任说明、Runtime 代理约束与审计合同，不能声称绝对阻止一个已获用户信任、以当前系统账户运行的恶意程序自行访问操作系统资源。
- 因此 v0.0.1 只运行用户明确选择并信任的插件；来源为“本地未验证”时界面必须直说。需要按“不可信代码”运行的插件必须等平台沙箱另行实现和真机验证。
- 插件崩溃只使其自身工具失败，不能带崩主窗口或其他 run；错误映射为来源明确的工具结果。
- MCP 和插件的秘密只以 SecretVault 引用传给拥有该连接的受管进程，不进入 renderer snapshot、日志、协调消息或普通记忆。
- 停用插件立即阻止新工具调用；卸载不顺带删除用户成果或插件数据，删除数据需要单独明确动作。

### Skills 与缓存

- 启动时只索引 Skill 名称、描述、来源和能力摘要；确定启用后才读取完整正文、参考和资产。
- 每个 run 固定启用的 Skill、MCP 和插件工具快照，运行中安装、更新或停用只影响后续 run，保护权限判断与缓存前缀稳定。

## 产品表现

- 扩展中心分为“Skills / MCP / 可执行插件”，分别显示来源、是否已信任、连接状态、声明权限和最近错误。
- 安装信任页优先用“可读取哪些位置、能否联网、能否启动进程、会连接哪个账号”解释，不要求用户阅读原始清单。
- 运行卡明确显示工具来自 Viniper、某个 MCP 或某个插件；失败不能只写“工具错误”。

## 收益

- 默认 Skills 保持轻量，可执行生态又有清楚入口。
- 未知代码不会进入主进程或因完全访问而自动获得信任；对子进程隔离强度的表述保持真实。
- 桌面端和 CLI 可通过同一 Runtime 使用一致的扩展目录与权限。

## 代价

- 插件清单、子进程协议、生命周期和权限代理需要独立实现。
- 部分原本假设能直接访问主进程的插件无法兼容。
- 插件升级和新增权限会多一次信任确认。
- 未实现平台沙箱前，明确受信任的插件仍继承当前系统账户本身能触达的操作系统表面，不能当作安全运行任意未知代码。

## 与既有决策的关系

- 修订 ADR-0003 只接收声明式插件清单的早期阶段边界；“未知可执行代码默认不运行”继续有效。
- 不改变 ADR-0006 至 ADR-0009 的权限层级，也不允许插件修改 Harness 自身。
- ADR-0036 已确定开放公共市场和直接安装；它扩大可发现来源，但不降低本 ADR 的显式信任与运行权限边界。
- ADR-0047 进一步禁止任何扩展静默更新，包括纯文本 Skill；活动 run 继续使用已冻结版本。
