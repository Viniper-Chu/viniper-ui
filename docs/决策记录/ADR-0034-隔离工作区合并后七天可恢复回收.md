# ADR-0034：隔离工作区合并后回收并保留七天恢复期

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

永久保留每个 Git worktree 最安全但会持续占用磁盘；合并后立刻删除全部痕迹又不利于误合并后的恢复和问题追踪。用户选择方案 C：成功合并后回收大型工作目录，保留七天可恢复记录；脏、未合并或结果不明确的工作区不自动删除。

## 决策

### 只有明确完成的隔离任务进入自动回收

- 只有同时满足“任务提交已形成、目标分支合并成功、合并后检查完成、受管 worktree 干净、没有未纳入成果、没有冲突或未知状态”时，才能进入自动回收。
- 回收只删除该 run 创建且已验证可移除的受管 worktree 大目录及其中可再生成的构建缓存，不碰用户原目录、用户分支、用户提交、未跟踪文件或其他 run 的空间。
- Git 删除 worktree 和受管任务分支仍使用仓库级资源锁；清理失败只标记为“待回收”，不能影响已经合并的产品结果。

### 七天可恢复记录

- 大目录回收后，保留系统拥有的任务分支或等价恢复引用、最终任务提交说明、差异摘要、检查/审查结果、合并回执和原 worktree 位置记录七天。
- 七天从成功回收大目录时开始计算。结果页显示明确到期日，并提供“保留更久”和“现在移除恢复记录”入口；后者是单独的用户动作。
- 到期时，只有恢复引用仍由 Harness 创建和拥有、任务保持已合并、没有重新打开或被其他任务引用、仓库状态仍可确认时，才自动删除该恢复引用和大型临时证据。目标分支中的正式提交和精简审计回执继续保留。
- 七天恢复期用于快速重新建立受管 worktree、查看差异和继续修复，不承诺撤销用户在此期间对目标分支做出的后续变更；需要恢复时仍先检查当前仓库状态。

### 任何不确定成果都不自动删除

- 脏、未提交、未合并、合并冲突、检查失败、审查有未解决问题、归属不明或 Git 状态无法可靠读取的 worktree 不进入回收队列，也不启动七天倒计时。
- 用户明确选择“放弃隔离成果”时，Harness 必须先列出将删除的受管目录、任务分支和未合并文件，再执行单独的放弃动作；完全访问不能把不确定成果变成可自动删除。
- 非 Git 受管副本若以后实现，必须遵守同样的“确认已交付或用户明确放弃”边界，不能因时间过去自动清除未知成果。

### 容量提示

- 存储页按“活动工作区 / 待处理成果 / 七天恢复记录 / 可再生成缓存”分类显示占用，不把所有受管目录混成一个清理按钮。
- 容量紧张时可以提示用户处理，但不得以磁盘压力为由绕过成果状态自动删除脏或未合并工作区。

## 产品表现

- 合并成功后显示“工作区已回收，可恢复至 YYYY-MM-DD”；恢复或延长保留均从任务结果进入。
- 未合并任务显示“成果已保留”，并说明是检查、审查、冲突还是未知状态阻止了回收。
- CLI 提供同样的到期日、恢复和保留状态，不以静默后台清理作为唯一行为。

## 收益

- 日常不会无限积累完整 worktree 和构建缓存。
- 合并后的短期问题仍有明确恢复窗口和证据。
- 未完成成果的保护边界简单：状态不确定就不删。

## 代价

- 需要管理恢复引用、到期任务、磁盘分类和跨重启清理。
- 回收大目录后恢复需要重新建立 worktree，速度慢于原目录仍在。
- 七天后自动移除系统恢复引用意味着长期恢复依赖正式 Git 历史和用户自己的备份。

## 与既有决策的关系

- 细化 ADR-0027 的 worktree 生命周期和 ADR-0033 的单任务提交交付单元。
- 大型目录属于 ADR-0032 的受管文件产物；恢复状态和到期时间属于 SQLite 结构化真源。
- ADR-0052 的通用可再生成产物清理不能提前删除本 ADR 保护期内的 worktree、恢复引用或结果不明确现场。
- 本 ADR 是后续目标设计，当前自动回收、七天恢复与真仓库恢复证据均为 `UNPROVEN`。
