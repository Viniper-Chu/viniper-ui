# ADR-0027：编程任务采用自适应 Git 工作区隔离

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

ADR-0025 允许同一会话和同一项目的无冲突任务并行。只使用原项目目录最简单，但多文件或并发编程任务仍可能相互污染；每个任务都建立 Git worktree 又会产生大量目录、分支和清理负担。用户选择方案 C：默认自适应，由任务范围和并发事实决定是否创建独立 Git worktree。

## 决策

### 默认模式为 `auto`

每个编程 run 保存 `workspaceMode = auto | shared | isolated`，默认 `auto`：

- 只读任务直接使用原项目目录。
- 没有其他写入 run、范围明确且仅涉及少量已知文件的小改动，可以使用原项目目录并继续遵守 ADR-0025 的资源锁。
- 同一 Git 仓库出现第二个写入 run、多文件变更、分支/提交/合并任务、范围可能扩大的长任务，或用户明确要求隔离时，在第一次修改前创建独立 Git worktree。
- 高级用户可为本次任务强制 `shared` 或 `isolated`；强制 shared 仍不能绕过同文件、Git 和未知范围命令的资源锁。

是否隔离由 Harness 根据已解析的任务计划、工具范围和当前活动 run 决定，不能只依赖模型自称“不会冲突”。如果任务在第一次写入前扩大范围，可从 shared 升级为 isolated；已经修改原目录后不得静默搬迁半成品，后续继续使用资源锁并明确提示。

### 原生 Git worktree，不依赖外部 Agent 框架

- 隔离使用本机 Git 的原生 worktree 和本项目自己的调度器，不依赖 Codex 云端工作树、Claude Code 或任何 Agent 框架。
- 运行目录进入 Viniper Harness 当前数据根下的受管 `workspaces` 区域，必须位于原 Git worktree 之外；不得嵌套进原项目目录，也不散落在桌面、磁盘根目录或用户主目录顶层。辅助元数据归当前 Runtime 所有者管理。
- 每个隔离 run 使用可读的任务名称与唯一 run 引用；界面不要求普通用户理解 Git worktree。
- Git 仓库元数据仍是共享资源，创建/删除 worktree、分支、提交和合并等 Git 变更按仓库级资源键串行；不同 worktree 内的普通文件与构建步骤可以并行。

### 保护原工作区和未提交改动

- 创建隔离 worktree 前先只读检查原工作区状态和当前基线，不运行 reset、clean、checkout 覆盖、自动 stash 或替用户提交现有改动。
- 隔离 worktree 从用户明确选择的当前已提交基线建立；原目录中的未提交改动不会被偷偷复制、移动或标成隔离任务成果。
- 如果任务明确依赖原目录的未提交改动，`auto` 不得假装已经隔离。它应继续在原目录使用窄资源锁，或让用户明确选择受管副本/先形成自己的可恢复基线。
- 合并前重新检查原工作区和目标分支；用户改动或基线已经变化时进入冲突/待确认状态，不覆盖或清理用户现场。

### 合并与保留

- 隔离 run 完成后先展示差异、构建/测试结果和适用的自动审查结果，再进入合并步骤。
- 确定性检查完成、适用审查结束且没有阻断问题后，先按 ADR-0033 自动形成一个只包含本任务成果的可读提交；原目录或 shared 工作区只有用户明确要求时才提交。
- 确定性检查失败、自动审查报告具体问题、证据无法验证或出现合并冲突时，不自动合并；保留 worktree，并给出“继续修复 / 查看差异 / 稍后处理”入口。
- 合并不由只读审查层执行。审查结束后，原执行编排器把合并作为一个单独、可见、受资源锁和权限约束的执行动作；普通权限下需要的批准仍按统一权限状态机处理，完全访问有效时不重复确认。
- 只有变更已经合并且 worktree 干净，或用户明确放弃且没有未保存成果时才清理。成功合并后的大型 worktree 按 ADR-0034 回收并保留七天恢复记录；脏、未合并或结果不明确的 worktree 不自动删除、也不启动倒计时。
- 清理只影响该 run 创建的受管 worktree 和分支，不删除用户原有分支、工作区、提交或未跟踪文件。

### 非 Git 项目

- 非 Git 项目不能伪装成 worktree 隔离，继续使用原目录和 ADR-0025 的文件/目录资源锁。
- 需要强隔离时可以提示用户初始化 Git 或复制到用户明确选择的受管工作副本；未经选择不自动改造项目版本控制。

## 产品表现

- 运行卡显示“原项目目录”或“隔离工作区”，并用一句话解释自动选择原因。
- 隔离任务结束后显示差异、测试、审查、合并状态和保留位置；普通用户只需选择继续修复、合并或保留。
- CLI 提供相同状态，不输出难以理解的内部目录作为唯一说明。

## 收益

- 小任务保持轻量，多任务和复杂变更获得真正隔离。
- 同仓库的不同功能任务可以并行，不必锁住整个项目目录。
- 未通过检查或尚未合并的成果不会被自动清理。

## 代价

- 自动判定和 worktree 生命周期比单一目录更复杂。
- Git 元数据操作仍需串行，不能因为文件目录不同就完全并发。
- 非 Git 项目只能退回资源锁或由用户选择受管副本。
- 依赖原目录未提交改动的任务无法自动获得干净 worktree 隔离，需要继续共享或由用户明确建立可恢复基线。

## 与既有决策的关系

- 细化 ADR-0025 的冲突感知并行和 ADR-0026 的编程阶段 P4。
- 提交行为由 ADR-0033 细化，合并后的回收与七天恢复期由 ADR-0034 细化。
- 完全访问影响批准，不影响 worktree 冲突、审查和成果保留规则。
