# ADR-0046：匿名诊断遥测仅在用户主动开启后上传

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

完全不收集诊断信息最保护隐私，但会让 Preview 阶段难以定位只在真实设备出现的崩溃和性能问题；默认上传即使声称匿名，也会让用户在不知情时把运行信息发送出去。用户选择方案 C：允许匿名崩溃与性能诊断，但默认关闭，只有用户明确主动开启后才能上传，并且可预览内容和随时关闭。

## 决策

### 默认关闭与明确同意

- 新安装、升级和导入数据后，匿名诊断上传均保持关闭；不以继续使用应用、接受条款或加入 Preview 作为隐含同意。
- 设置页先展示允许字段、明确排除项、接收端和用途，再由用户主动打开“分享匿名诊断”。
- 开启只影响之后产生或用户明确选择发送的报告，不自动上传开启前积累的本地日志。
- 用户关闭后立即停止后续上传；已经明确发送并被服务端接收的报告无法从本机撤回，界面必须直说。

### 只允许崩溃与性能诊断

- 可上传字段限制为应用版本与渠道、操作系统和架构、功能域、状态/错误类别、耗时、内存等性能计数、经过路径清理的崩溃栈，以及单份报告的随机引用。
- 禁止上传用户提示词与消息、模型回复、思考内容、工具参数或结果、项目文件与内容、会话/记忆正文、API Key/令牌/私钥、账号标识、代理凭据和原始本地文件路径。
- 不建立跨项目画像，不用持久设备标识把多份报告拼成用户行为档案，不用于广告、模型训练或扩展市场排序。
- 本地 Token/缓存账本属于产品运行数据，不因为名称中已有 `telemetry` 就自动上传；匿名诊断由独立功能域管理。

### 上传前可预览

- 设置页提供与真实待发送 payload 同源的预览，用户能查看字段和值，而不是只看一段隐私承诺。
- 自动报告在开启后可以直接发送允许字段；用户仍可选择“每次发送前询问”，也可以从本地诊断列表手动发送单份报告。
- 清理器如果无法确认某个字段不含内容或秘密，就删除该字段并标记报告不完整，不能为追求诊断完整度扩大收集范围。
- 上传只发送到 Viniper Harness 明示的官方诊断端点；Skill、MCP、插件和公共市场不能接管或订阅该数据流。

### 本地诊断不等于远程遥测

- 为排错而保存在正式数据根或项目 `codex/运行残留` 的本地日志可以在上传关闭时继续存在，但必须遵守既有秘密与文件卫生边界。
- ADR-0061 已将本地日志收敛为默认结构化精简事件和用户主动开启的单次 run 详细诊断；远程同意不自动附带任何详细日志。
- Provider 请求、用户主动安装扩展、应用更新检查与下载是各自功能的必要网络动作，不标成匿名遥测；它们的目的和目标地址分别说明。

## 产品表现

- 初始设置不强迫用户回答；设置中的开关默认关闭，并提供“查看示例报告”“查看待发送报告”和“立即停止分享”。
- 错误界面优先提供本地复制/导出诊断，再提供在已同意状态下发送；不使用“帮助我们改进”弱化真实上传含义。
- CLI 与桌面共享同一同意状态，但非交互 CLI 不自行改变开关。

## 收益

- Preview 可以在用户知情同意下获得真实崩溃与性能证据。
- 默认关闭、字段白名单和真实预览让普通用户能理解发送了什么。
- 诊断数据与提示词、项目内容、凭据和产品 usage 账本明确分离。

## 代价

- 选择开启的用户可能较少，某些问题仍难复现。
- 匿名化、路径清理、预览和上传队列需要额外实现与测试。
- 关闭只能阻止未来上传，不能撤回已接收报告。

## 与既有决策的关系

- 不改变 ADR-0003/0041/0059 的本地 Token 与缓存统计；本 ADR 的远程诊断必须使用独立 `diagnostics` 功能域。
- 遵守秘密不进入 renderer、日志和扩展的既有边界；诊断端点不是 Provider 或插件能力。
- ADR-0061 负责本地日志粒度、单次详细开关与保留，本 ADR 只负责用户主动同意后的远程字段白名单。
- 本 ADR 是后续目标设计；当前官方诊断服务、同意界面、匿名化效果和真实上传均为 `UNPROVEN`。
