# ADR-0067：项目索引低优先级运行，并按资源压力自动降速或暂停

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

后台全速索引完成最快，却会与 Agent、构建和本地推理争用资源；只在完全空闲时运行影响小，但忙碌设备可能长期无法完成。用户选择方案 C：索引默认作为低优先级后台工作运行，在前台任务或系统资源压力上升时自动降速或暂停，条件恢复后继续。

## 决策

### 统一低优先级索引调度

- 基础索引和可选语义索引都由单一 `ProjectIndexService` 调度；同一项目不启动相互竞争的重复全量任务。
- 首次建立、增量更新和重建默认低优先级执行，不阻塞项目打开、实时搜索、文件编辑、Agent run 或构建命令。
- 索引进度与检查点持久化；自动暂停或应用正常退出后从最近可用位置继续，不把暂停冒充失败或重新从零开始。

### 根据真实活动降速或暂停

- Runtime 观察当前 Agent 工具活动、本地模型推理、已知构建/测试任务，以及 CPU、内存和磁盘压力；压力升高时先降低索引并行和吞吐，仍不足时暂停。
- 前台任务结束且资源恢复稳定后，索引自动继续；使用短暂稳定窗口避免在忙闲边界频繁启停。
- 用户可以手动暂停、继续或重建具体项目索引。手动暂停优先于自动恢复，直到用户再次继续。
- 桌面端与 CLI 连接同一 Runtime 时共享索引状态和资源判断，不各自启动后台扫描。

### 搜索与界面降级

- 索引降速或暂停期间，搜索继续按 ADR-0056 使用现有索引和项目内实时补查；语义层不可用时按 ADR-0066 回退基础搜索。
- 状态必须说明“因 Agent 运行降速 / 因系统资源暂停 / 已手动暂停”等原因，并显示仍可工作的搜索路径。
- 资源调度只影响用户明确加入的项目，不利用空闲时间扫描其他目录或整台电脑。

## 产品表现

- 项目状态显示“低优先级建立中、因任务降速、因资源暂停、手动暂停、已就绪、需要刷新”。
- 用户无需配置 CPU 百分比才能获得合理默认体验；高级诊断可以查看暂停原因和累计建立时间。
- Agent 正在编程或本地推理时，索引状态变化采用低干扰提示，不弹出阻断式对话框。

## 收益

- 索引可以持续完成，同时优先保证用户当前任务响应。
- 基础与语义索引共享资源治理，减少重复扫描和竞争。
- 暂停原因、失败和搜索降级能够被准确区分。

## 代价

- 忙碌设备上的首次索引可能需要更久。
- 需要跨平台资源观察、检查点和恢复机制。
- 自动阈值必须通过真实项目与硬件测试调整。

## 与既有决策的关系

- 细化 ADR-0056/0066 的非阻塞索引、实时回退和语义降级规则。
- 与 ADR-0025/0031/0065 共用 Runtime 活动与资源状态，但索引后台工作不冒充一个占用全局 Agent 并发名额的 run。
- 本 ADR 是后续目标设计；节流、暂停恢复、检查点、Windows/macOS 资源感知和大型项目性能均为 `UNPROVEN`。
