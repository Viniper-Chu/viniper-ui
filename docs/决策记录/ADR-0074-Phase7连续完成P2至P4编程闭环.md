# ADR-0074：Phase 7 连续完成 P2 至 P4 编程闭环

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

Phase 6 已验收编程 P1 的项目发现、搜索和读取。用户随后明确要求“继续进入 P2，将剩下的全干完”，因此本轮不再把文件编辑、终端与 Git 分散到彼此独立的未来版本，但仍需要保留能定位失败的阶段门。

## 决策

- Phase 7 在同一任务合同内连续完成 ADR-0026 的 P2 文件变更、P3 终端/依赖/构建测试、P4 Git/隔离工作树/复核。
- 顺序固定为 `P2 -> P3 -> P4 -> Windows 便携包 -> 管理验收`。每一段先建立可证伪测试，再接入同一个 Runtime、ToolRegistry、PermissionPolicy、事件、Token 账本、桌面与 CLI；上一段绿灯后才进入下一段。
- 最终交付不能只完成其中一段后宣称“剩余已完成”。若后段被客观条件阻断，必须保留前段真实结果并将总状态写为 `PARTIAL`，不得回写成全量 `PASS`。
- “全部剩余”仅指已确定的完整编程 P2–P4，不顺带实施 SQLite 迁移、本地模型、远程 Git、扩展市场、自动更新、Windows 安装器或 macOS 可执行包。
- 文件、终端、Git 和审查继续是 Viniper Harness 自有 Runtime 的能力；不得调用 Claude Code、Codex CLI、Hermes 或其他 coding agent 作为执行后端。调用本机文件系统、原生 shell 和 Git 可执行程序属于平台适配，不属于套壳。
- 本轮继续使用固定“执行层”会话作为唯一生产代码写者；管理层维护设计、合同和验收。执行层可使用最多两个只读子 Agent 做代码映射与测试审计，子 Agent 不修改生产代码。
- 开发与回归先全部离线完成。Phase 6 的 DeepSeek 真实调用授权已经冻结；Phase 7 任何新的付费公网生成必须由管理层在离线门全绿后取得用户新的明确授权并续发有界附录。

## 收益

- 用户在一个阶段内得到完整、可使用的编程闭环，不再停留在只能读取项目的状态。
- 仍保留 P2/P3/P4 三个诊断门，失败可以准确归因，不会把文件、进程和 Git 问题混成一个结论。
- 桌面、CLI、权限、审查与 Provider 复用一套核心，不形成第二个 coding runtime。

## 代价

- Phase 7 变更面较大，需要更完整的直接消费者测试、Windows 原生进程测试和临时 Git 仓库验收。
- 在取得新的真实 DeepSeek 授权前，模型主动选择写入/终端/Git 与模型自动审查只能由协议 fake 和本地消费者证明，真实 Provider 证据保持 `UNPROVEN`。

## 与既有决策的关系

- 只改变 ADR-0026 的实施节奏，不改变 P2–P4 的能力边界。
- 工作区、提交、合并与回收继续服从 ADR-0027、ADR-0033、ADR-0034；权限和审查继续服从 ADR-0006 至 ADR-0015。
- Windows 交付继续服从 ADR-0071；macOS 只同步草案并保持 `UNPROVEN`。
