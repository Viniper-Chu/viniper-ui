# ADR-0019：首次关闭询问并记住

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

自动任务只有在桌面或 CLI 调度进程运行时才能触发。桌面窗口的标题栏关闭按钮若总是退出，用户可能无意停止任务；若总是隐藏到托盘，用户又可能误以为程序已经退出。用户选择方案 C：第一次询问并记住选择。

## 决策

### 首次标题栏关闭

尚未保存关闭偏好时，第一次点击标题栏关闭按钮显示两个清楚的选项：

1. `继续在托盘运行`（macOS 草案文案为“继续在菜单栏运行”）
   - 隐藏主窗口；
   - Electron 主进程继续运行；
   - 自动任务继续调度；
   - 当前进程内的电脑完全访问继续有效。
2. `完全退出`
   - 结束 Electron 主进程；
   - 自动任务停止；
   - 电脑完全访问令牌失效；
   - 错过的计划下次启动后按 ADR-0018 合并补跑一次。

选择后立即保存为全局偏好，以后标题栏关闭不重复询问。

### 随时可以修改

- 设置页提供“关闭窗口时”选项：`继续在托盘/菜单栏运行` 或 `完全退出`。
- 用户修改后从下一次标题栏关闭生效。
- 不提供无法解释的第三种混合状态。

### 显式退出永远是真退出

- Windows 应用菜单、系统托盘菜单中的“退出 Viniper Harness”始终结束主进程。
- macOS 的应用菜单“退出 Viniper Harness”和 `Cmd+Q` 始终真正退出。
- 显式退出不受标题栏关闭偏好影响，也不再次弹出同一个选择框。
- CLI 的 Ctrl+C、进程结束或明确 exit 始终结束 CLI 调度进程。

## 状态入口

- 选择继续运行后，Windows 系统托盘必须有 Viniper Harness 图标；macOS 草案使用菜单栏状态项。
- 菜单显示调度器是否运行、当前运行任务数量、“打开 Viniper Harness”和“退出 Viniper Harness”。
- 第一次隐藏后给一次简短提示：“Viniper Harness 仍在运行，自动任务会继续。”以后不重复打扰。

## 可访问性

- 首次选择框支持键盘和屏幕阅读器。
- Escape 取消本次关闭并返回窗口，不保存偏好。
- 两个选项都说明对自动任务和电脑完全访问的实际影响，不只使用“是/否”。

## 平台说明

- Windows 是 v0.0.1 Preview 当前必须实现和验收的平台。
- macOS 保持相同用户选择与状态合同，使用原生菜单栏和退出命令表达；真机交互仍为 `UNPROVEN`。
- 该行为不创建独立后台服务；“继续运行”只是保持现有桌面主进程。

## 收益

- 用户首次就能决定符合自己习惯的关闭方式。
- 后续操作简单，不会每次关闭都弹窗。
- 自动任务是否继续与电脑完全访问是否仍有效都可解释。

## 代价

- 首次关闭比直接退出多一步。
- 选择继续运行后，用户仍需理解“关窗口”和“退出程序”的区别。
- Windows 与 macOS 的系统入口外观不同，需要分别验收。
