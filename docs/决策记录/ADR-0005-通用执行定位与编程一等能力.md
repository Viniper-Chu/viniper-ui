# ADR-0005：通用执行定位与编程一等能力

状态：Accepted  
日期：2026-08-12  
决策人：用户 / Viniper Harness 管理层  
适用版本：`v0.0.1 · Preview（预览版）`

## 背景

用户希望 Viniper Harness 面向没有代码能力的普通用户，成为能够完成项目、文件、网页、研究、办公与自动任务的通用个人 Agent；同时明确要求绝对不能放弃编程能力。产品不能在“通用易用”和“开发者级执行”之间做互斥选择。

## 决策

1. 产品定位以“通用个人执行 Agent Harness”为主，不定位为只面向开发者的编程客户端，也不在当前阶段定位为复杂的 Agent 搭建平台。
2. 编程能力属于长期一等核心能力，不是可删除的可选插件、单独付费版本或另一个隐藏产品。
3. 普通任务与编程任务共用同一 Agent Runtime、会话、Provider、权限状态机、ToolRegistry、Token 账本、缓存、协作信封、事件和审计链，不建立第二套编程内核。
4. 新手界面采用渐进披露：默认只呈现目标、计划、权限和结果；进入代码项目或调用编程工具时再展示文件、差异、终端、Git、测试和诊断细节。简单来自交互组织，而不是删除能力。
5. 编程能力的长期最低范围包括代码库理解与搜索、文件读取和可审查编辑、受控终端、Git、构建/测试、错误诊断和结果复核。现按 ADR-0026 保留完整目标并分 P1–P4 实现验收，按 ADR-0027 自适应使用原目录或 Git worktree。
6. 桌面端与 CLI 共享编程执行真源；两端可以有不同呈现和交互能力，但不得出现互不兼容的两套任务语义。目标运行关系由 ADR-0031 细化为同一数据根单一 Runtime 所有者与 IPC 客户端。

## 收益

- 普通用户能够从简单任务开始，不必理解终端和代码概念。
- 开发者仍可获得完整、可追溯的项目执行能力，产品不会退化成只能聊天或调用少量办公工具的助手。
- 通用任务和编程任务共享权限、缓存、协作与测试基础，减少长期重复和行为分叉。
- 产品形成区别于纯编程 CLI 与无执行力桌面助手的清晰定位。

## 代价

- 工具与权限矩阵会比纯编程 Agent 或纯办公助手更广，必须分阶段开放并分别真实验收。
- 桌面信息架构需要同时照顾新手与高级用户，渐进披露和可解释状态成为长期约束。
- 编程能力不能仅靠 CLI 证明；桌面端也必须提供可理解的差异、批准、运行和结果入口。

## 否决方案

- 只做 Codex/Claude Code 式开发者工具：不符合普通用户优先的定位，也会成为现有产品的复制品。
- 为了新手体验删除终端、Git、构建测试等编程能力：违背用户明确决定。
- 先做复杂的可视化 Agent 搭建平台：会在底层工具、权限和记忆尚未完全定型时过早增加概念和配置。
- 通用版与编程版各自维护一套 Runtime：会造成权限、会话、缓存和行为长期分叉。
