# ADR-0050：单设备只使用本地数据并通过手动归档跨设备迁移

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

账号云同步能让多台设备随时看到同一数据，但会引入账号、服务端存储、冲突合并和隐私边界；多个本地身份也会增加普通用户理解成本。用户选择方案 A，并补充：本机只能取得本机数据，但允许把数据导出到其他设备。

## 决策

### 一台设备一个默认本地身份

- 每个操作系统用户只拥有一个 Viniper Harness 默认身份和默认数据根；桌面与 CLI 按 ADR-0031 连接这一个本机 Runtime 真源。
- 产品不要求登录 Viniper 账号，不创建云端用户资料，也不以邮箱、手机号或第三方账号作为访问本地会话的条件。
- 当前设备只读取当前设备的数据根；另一台电脑不能远程浏览、搜索、控制或继续本机 run。
- `--data-root` 等隔离数据根继续只服务测试、演示和明确隔离场景，不包装成普通用户的多身份系统，也不与默认数据自动同步。

### 不做自动跨设备同步

- 不提供云端同步、局域网自动发现、后台上传、实时双向合并或“在另一台设备继续”的隐藏服务。
- 同一归档被导入两台设备后，两边成为独立本地副本；之后的会话、记忆、任务和设置各自发展，不产生自动冲突合并。
- 本机 IPC 只接受当前设备同一系统用户，不能借桌面/CLI 共享 Runtime 变成远程访问端口。

### 通过 ADR-0044 手动迁移

- 用户需要换设备时，使用 ADR-0044 的完整非秘密归档或会话/项目选择性归档，在目标设备手动导入。
- 归档可以经用户自行选择的 U 盘、局域网文件传输、网盘或其他文件通道搬运；Harness 不把传输通道冒充自身同步服务。
- API Key、代理凭据、证书私钥和平台凭据库秘密仍不进入普通归档，目标设备需要重新配置。
- 导入目标设备后继续遵守“先暂存、验证、预览再合并”，不会覆盖目标设备已有本地数据，也不会自动启用调度、扩展或权限。

## 产品表现

- 设置中显示“数据位置：仅此设备”，并提供“导出到另一台设备”和“从另一台设备导入”的人话入口。
- 主界面不显示不存在的账号头像、云同步进度或“所有设备已同步”。
- 导出完成只显示归档路径和验证状态；目标设备是否已经接收、导入或删除旧副本必须按真实结果表达。

## 收益

- 无需建设账号和云端数据服务，数据默认只留在本机。
- 普通用户只理解一套本地会话与设置，不需要管理多个身份。
- 仍能通过可检查的归档完成换机或有选择的数据搬运。

## 代价

- 不能在多台设备之间实时继续同一任务。
- 用户需要手动搬运归档，并在新设备重新配置秘密。
- 两台设备分别使用后不会自动合并各自产生的新数据。

## 与既有决策的关系

- 细化 ADR-0031：桌面与 CLI 共享的是同一台设备上的默认数据根和 Runtime，不扩大为远程 Runtime。
- 使用 ADR-0044 作为普通非秘密数据的唯一产品内跨设备路径，并保持 ADR-0039 的无自动备份策略；portable 秘密只走 ADR-0057 的独立密钥包。
- ADR-0057 的加密密钥包是同一手动迁移原则下的独立秘密通道；它不建立同步，导入后仍由目标设备自己的 Vault 保存。
- 本 ADR 是后续目标设计；当前“仅此设备”入口、跨设备归档导入和 Windows/macOS 互迁均为 `UNPROVEN`。
