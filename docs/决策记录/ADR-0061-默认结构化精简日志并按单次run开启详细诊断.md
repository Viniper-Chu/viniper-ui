# ADR-0061：默认结构化精简日志，并按单次 run 开启详细诊断

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

只保存最少错误有利于隐私，但复杂 Provider、工具和并发问题难以定位；默认记录完整请求、回复和文件内容又会扩大秘密、隐私和磁盘风险。用户选择方案 C：默认保存不含正文的结构化精简日志，只有用户为某一次 run 主动开启时才记录更详细的诊断事件。

## 决策

### canonical 事件与精简日志

- 会话、run、工具、权限、Provider、调度和外部动作的 canonical 事件与回执仍是产品权威审计；诊断日志不能替代或改写它们。
- 默认诊断字段限于时间、级别、组件、事件代码、会话/run/profile/model 引用、状态变化、尝试次数、持续时间、数据大小/数量和规范错误类别。
- 默认日志不记录提示词、模型回复、隐藏推理、完整工具输出、工具正文参数、项目文件内容、长期记忆正文、凭据、请求头、原始环境变量或不必要的完整路径。
- 日志使用稳定事件代码和结构化字段，避免只写无法检索的长文本错误堆栈；界面用普通语言解释，技术字段可展开。

### 详细模式只绑定单次 run

- 用户可在运行前选择“为这次任务记录详细诊断”，或在运行中为之后的事件开启；它只绑定该 run，在完成、取消、失败或 Runtime 所有者退出后自动结束，不形成永久全局开关。
- 详细模式增加状态机转换、序列化形状、流分段、网络阶段耗时、队列/资源锁、重试判断、工具投影范围和取消传播等排错信息。
- 详细模式仍执行秘密过滤，也不默认保存提示词、回复、项目正文或完整工具输出；完整工具输出继续由 ADR-0054 的专用受管证据查看器管理。
- 开启后只记录未来事件，不声称能补回此前没有采集的数据；界面明确显示开始时间和覆盖范围。

### 本地、可见、不会自动上传

- 默认结构化事件保存于本地 SQLite 审计；用户主动生成的单次详细诊断保存为受管文件并由数据库引用，直到用户明确删除该诊断或所属 run。
- 诊断查看器允许按 run、组件、级别和事件代码筛选，并可导出经过同一秘密过滤的诊断包；导出不自动发送给 Viniper 或 Provider。
- ADR-0046 的匿名诊断上传仍默认关闭。即使用户开启匿名诊断，也只能上传其字段白名单，不自动附带本地详细日志。
- renderer、插件和模型只取得界面所需的安全投影，不能直接遍历本地诊断目录。

## 产品表现

- 普通错误页先提供“发生了什么、任务是否受影响、建议动作”，再提供“查看技术详情”。
- run 菜单提供一次性的“记录详细诊断”开关，并显示“不会记录提示词或文件正文”。
- 详细诊断开启时在当前 run 显示低干扰状态标记，结束后给出查看和删除入口。

## 收益

- 默认状态保持较低隐私和磁盘负担。
- 遇到难复现问题时，可以为单次任务取得足够的状态、网络和并发证据。
- 本地日志、完整工具输出和匿名上传三者边界清楚。

## 代价

- 未提前开启详细诊断时，早期细节无法事后补回。
- 详细模式仍会增加一定磁盘和运行开销。
- 不记录内容正文意味着少数内容相关问题仍需用户主动提供最小复现材料。

## 与既有决策的关系

- 细化 ADR-0046 的本地诊断与主动同意上传边界，并复用 ADR-0032 的 SQLite + 受管文件存储。
- 完整工具输出继续由 ADR-0054 管理；单次详细诊断按 ADR-0052 作为用户主动保留的审计证据，不进入周期清理。
- 本 ADR 是后续目标设计；结构化事件、单次开关、秘密过滤、导出和 Windows/macOS 行为均为 `UNPROVEN`。
