# ADR-0078：先完成前端完整重构再恢复 Phase 8

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

Phase 8 原计划先完成 Runtime、并行恢复、记忆索引、调度扩展和 Provider，再在 Checkpoint 8 统一收口 UI。用户在 SQLite Checkpoint 1 完成后明确改变顺序：先从 GitHub 获取前端制作 Skill，除既定主色外完整重构前端，以新前端完成验收，再继续其余完整版能力。

现有 Phase 7 界面虽然通过过阶段性 Visual Ralph，但用户认为整体仍缺乏高级感，尤其要求继续解决字号、Token 遮挡、顶部默认菜单感、模块断层、历史标记、大按钮、品牌图标和信息放置问题。

## 决策

- v0.11 的产品范围不缩减，只暂停在 Checkpoint 1 之后；v0.12 前端合同通过后，从 Checkpoint 2 恢复。
- 新视觉采用 Operate 模式的“冷青绘图仪工作台”：连续信号轨连接会话、run、Token、协作和状态；以 V 形汇流作为品牌签名。
- 既定冷青/青绿主色保持不变。Phase 7 外观仅作功能与缺陷证据，不再作为视觉权威。
- 当前已实现的全部 renderer 消费者先换成新界面；尚未实现的功能只保留诚实槽位，后续实现必须复用新 token、组件和布局，不得恢复旧页面或建立第二套前端。
- 新 V 图标本轮以小尺寸清楚、可审计、可打包的原创矢量资产交付。没有 OpenAI CLI Key 时不虚构 `gpt-image-2` 来源，未来若用户提供所需本地配置可再做图像模型品牌探索，但不阻塞当前 Preview。
- 视觉验收必须来自当前生产 Electron 的新前端真窗，并与功能、无障碍、全量回归和 IPC 边界一起通过；旧截图、静态概念图或评分单独不能建立 PASS。

## 收益

- 后续所有功能中心在稳定的新壳和设计系统中落地，避免最后阶段再大规模返工。
- 用户可先验证日常操作是否简单、清楚和有品质，再投入其余完整能力。

## 代价

- Runtime Checkpoint 2–8 暂缓，整体安装时间顺延。
- 新功能尚未完成时只能显示诚实状态，不能用静态假数据提前制造“完整版”错觉。

## 与既有决策的关系

- 不改变 ADR-0077 的最终用户级安装授权，只调整 v0.11 的执行顺序。
- 保留 ADR-0075 的冷青主色、自定义顶栏、可读字号、Token 无遮挡、均匀历史短横和连续画布要求，但替换其具体视觉实现。
- macOS 继续 `draft-only / UNPROVEN`；本轮同步草案不构成真机结论。

## 落地结论

- 2026-08-13，v0.12 已由固定执行层完成，并由管理层独立复核 `typecheck PASS / 169 of 169 tests PASS / git diff --check PASS / Git CLEAN`。
- 1440x900、1280x800、960x720 真窗与 Token、Provider、调度、扩展、顶栏菜单状态均使用新前端；独立视觉完成审查结论为 `APPROVED 95/100`，全部关键项不低于 93。
- 新的图像模型 V/circuit-node 主图及 16/32/64 PNG、ICO 已接入 BrowserWindow、Tray 与便携包合同；renderer 使用同品牌简化 SVG small-mark。
- 本 ADR 的暂停条件已解除，Phase 8 现恢复到 v0.11 Checkpoint 2。
