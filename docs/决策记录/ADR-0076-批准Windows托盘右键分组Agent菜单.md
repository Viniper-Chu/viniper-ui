# ADR-0076：批准 Windows 托盘右键分组 Agent 菜单

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

用户提供了 Codex 系统托盘右键菜单截图，并明确要求 Viniper Harness 按该格式实现隐藏菜单。产品已经确定为纯 Agent 桌面端，因此参考的是分组、层级、密度和原生菜单秩序，而不是照搬 Chat 文案。

## 决策

- Windows 使用 Electron 原生 `Tray` 与 `Menu`，不在 renderer 中制作假托盘菜单。
- 菜单依次显示“正在运行 / 未读 / 已固定 / 最近”，组间使用原生分隔线。每组先显示最多 3 个 Agent 任务，超过部分进入“更多”子菜单；空组显示禁用的“暂无”。
- 任务项只显示任务标题和可安全展示的项目或类型摘要，不显示消息正文、命令正文、绝对路径、密钥或其他秘密。若 Windows 原生菜单不能可靠显示双列，则使用“任务标题 — 项目名”，不得借快捷键栏伪造右侧元数据。
- 点击任务项必须显示并聚焦主窗口，再选中对应 Agent 会话。菜单只消费 canonical session/run snapshot，不建立第二份会话、未读、置顶或运行状态。
- 底部固定动作是“新建 Agent”“打开/隐藏 Viniper Harness”“完全退出 Viniper Harness”；不得出现 `New Chat` 或 `Chats`。
- 托盘使用批准的冷青 V 图标小尺寸资产。单击打开或切换主窗口，右键显示菜单；应用生命周期内只创建一个 Tray，并在正式退出时销毁。
- “隐藏”不终止运行中的 Agent、终端任务或调度器；“完全退出”复用正式退出路径，释放 Runtime、租约、进程与托盘资源。

## 验收

- 菜单模板构建器可注入并可单测，覆盖分组顺序、排序、3 条上限、“更多”、空组、动态打开/隐藏以及新建、选择、退出动作。
- 测试证明无 Chat 文案、无敏感字段，状态来自 canonical snapshot，点击任务可定位到正确会话，并且 Tray 单例和退出清理可靠。
- 必须有真实 Electron 启动与原生 Tray 创建证据；若不能在不接管用户输入的前提下安全截取原生菜单，则将“原生菜单视觉截图”如实标为 `UNPROVEN`，不得以 HTML mock 冒充。
- 新增托盘后重新运行 1440×900 与约 960×720 的 Visual Ralph 回归，主窗口分数仍不低于 90，且 Token、顶栏、时间线和 Composer 不回退。

## 代价与边界

- Windows 原生菜单的次要信息排版受系统能力约束，结构与语义优先于伪造逐像素双列。
- macOS 将来映射为菜单栏状态项，但菜单栏、Dock、Retina 图标、交通灯、VoiceOver 和真机生命周期仍为 `UNPROVEN`。
- 本决策不新增后台服务、开机启动、远程同步或 Chat 模式。
