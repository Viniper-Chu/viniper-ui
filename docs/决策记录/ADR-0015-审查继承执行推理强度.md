# ADR-0015：审查继承执行推理强度

- 状态：Accepted
- 日期：2026-08-12
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

自动审查已经确定使用执行模型、使用全新只读上下文、自适应最多两轮且不设独立预算。最后需要决定审查的推理强度是继承执行任务、固定最高档，还是按复杂度调整。用户选择方案 A：继承执行任务的推理强度。

## 决策

1. 执行 run 开始时，Runtime 将本次 Provider/profile/model 的推理强度设置写入只读 run snapshot。
2. 第一轮审查继承该快照中的同一推理设置。
3. 如果触发第二轮，第二轮继续使用同一设置；不会因首轮发现问题、任务复杂或外部影响较高而自动升档。
4. 执行阶段若使用 `auto`、`default` 或等价 Provider 默认策略，审查沿用同一策略。
5. Provider 不提供可调推理强度时，adapter 不伪造参数，界面显示“推理强度：模型默认”。
6. 任务运行中修改全局模型设置不影响当前执行或审查；新设置从下一个 run 生效。

## 兼容不同 Provider

- Provider adapter 只映射厂商真实支持的 reasoning/effort/thinking 参数。
- 不同厂商的档位名称可以不同，Runtime 保存规范化语义和原始 Provider 值，避免把不等价档位强行说成完全相同。
- 如果 Provider 不返回实际采用的推理设置，界面显示请求时设置，不冒充 Provider 已确认。

## 产品表现

- 审查区显示“审查模型：同执行模型”与“推理强度：继承执行（具体值）”。
- 若模型没有此能力，则显示“推理强度：模型默认”。
- 第二轮不会出现新的推理强度选择器或额外升档提示。

## 收益

- 执行与审查配置一致，用户不需要理解第二套推理设置。
- 速度和 Token 消耗倾向更可预测，不会在第二轮悄悄切到高消耗模式；产品不维护金额。
- 桌面端、CLI 和不同 Provider 使用同一快照合同。

## 代价

- 使用低推理强度执行时，审查也可能偏浅。
- 高影响任务不会因为风险较高自动获得更强推理。
- 同模型、同推理强度可能保留相同盲点，只能依靠新上下文和确定性证据缓解。

## 后续待定

自动审查的模型、上下文、触发、只读权限、轮次、预算和推理强度核心合同至此已经确定。后续只剩实现细节和界面文案，不再增加新的默认行为，除非用户主动修改这些决策。
