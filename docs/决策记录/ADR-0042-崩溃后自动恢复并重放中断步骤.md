# ADR-0042：崩溃后自动恢复，并重放中断步骤

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

崩溃后全部标记失败最容易避免重复副作用，但长任务必须从头开始；等待用户逐项决定更稳妥，却会让无人值守任务停住。用户选择方案 B：Runtime 恢复后自动从中断位置继续，包括重新执行尚未确认完成的工具步骤。

## 决策

### 从最后一个持久化检查点恢复

- Runtime 所有者异常结束、应用崩溃或系统强制终止后，下一个合格 Runtime 所有者完成 ADR-0031/0032 的租约与存储恢复检查，再扫描状态为 active/reviewing 且没有用户取消记录的 run。
- 每个 run 从最后一个完整持久化检查点恢复原 Provider、model、推理设置、上下文 generation、工具/Skill/插件快照、任务来源和资源范围，不重新规划成一项看似全新的任务。
- 已有明确成功回执并持久化完成状态的 Provider 轮次、工具步骤和外部动作不重放；只继续检查点之后未完成的步骤。
- 用户已经取消、明确停止、正常完成或确定失败的 run 不自动恢复。

### 结果未知的中断步骤自动重放

- Provider 请求只有部分输出、没有完整持久化 assistant/tool-call 结果时，恢复器按原冻结快照重新发起该轮请求；旧部分输出保留为“中断片段”，不冒充最终结果。
- 工具调用已记录开始但没有完整成功/失败回执时，使用相同规范化参数和原动作引用自动重新执行，不弹出“是否重试”确认。
- 这条规则同样适用于文件写入、命令、Git、上传、发送、发布、付款、远程权限修改和删除等已获该 run 授权的工具。若第一次动作实际成功但回执未落盘，第二次执行可能产生重复副作用。
- 工具或外部服务支持幂等动作引用时，重放必须复用原引用以减少重复；不支持时仍按用户选择自动重放，并在事件和结果回执中标记“崩溃恢复重放，原结果未知”。
- 重放不能修改原工具参数或扩大能力范围；任何参数变化都属于新的工具动作，回到正常 Agent 循环和权限判断。

### 权限和连接仍需有效

- 原 run 对同一具体动作已经取得且仍有效的批准可以随检查点恢复，不为完全相同的重放再次询问。
- 项目完全访问只有在项目仍受信任时可继续；插件必须仍安装且信任合同未变化，外部连接和凭据必须仍可用。
- 电脑完全访问按 ADR-0008/0031 在 Runtime 所有者退出时失效。恢复步骤需要电脑完全访问时进入 `waiting_permission`，用户重新授权后自动继续，不能因本 ADR 持久化或绕过整机令牌。
- UAC、macOS 系统授权、第三方登录/验证码和服务端账号权限继续由各自系统决定。

### 调度、用量与可见性

- 自动恢复发生在下次桌面或 CLI Runtime 正式启动后，不安装后台服务，也不在所有程序退出时自行运行。
- 恢复 run 重新参与全局并发、Provider 容量和资源锁；同一自动任务的新周期继续按重叠合并规则处理，不能与恢复中的旧 run 重复并发执行同一个周期。
- 原尝试、崩溃点、恢复时间、重放步骤、重复风险、实际 Token/缓存/耗时和最终回执都进入同一 run 历史。ADR-0041 不因重放 Token 自动停止任务，ADR-0059 后不记录金额。
- 桌面和 CLI 显示“正在恢复 / 正在重放第 N 步”，但不要求用户逐项批准；用户仍可随时取消。

### 与在线重试的区别

- ADR-0023 仍控制同一活动 Runtime 中的 Provider 传输错误：出现语义输出或外部影响后不得在线自动重放。
- 本 ADR 专门处理进程已经失去执行现场、没有完整持久化结果的崩溃恢复，并明确允许下次 Runtime 对中断步骤重新执行；它不把在线重试上限扩大成无限重试。

## 收益

- 长任务和无人值守任务在应用重新启动后能够自动继续。
- 已完成步骤不会全部从头执行，恢复仍使用原 run 身份和模型快照。
- 支持幂等引用的服务可以降低重复副作用概率。

## 代价

- 结果未知的非幂等工具可能重复写文件、执行命令、发送、发布、付款或删除。
- Provider 轮次重放会产生额外 Token 和延迟。
- 需要精确、持久的步骤状态、动作引用和恢复事件，否则无法区分已完成与结果未知。

## 与既有决策的关系

- 细化 ADR-0031 的 Runtime 所有者崩溃恢复和 ADR-0032 的持久化检查点。
- 在“崩溃后结果未知”这一专门场景下补充 ADR-0023；在线传输重试边界保持不变。
- 本 ADR 是后续目标设计，当前自动恢复、工具重放和真实外部副作用行为均为 `UNPROVEN`。
