# ADR-0038：会话永久保留在主列表，直至用户手动删除

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

自动归档可以保持列表简洁，但会让旧任务在用户没有操作时从主入口消失；按时间自动删除更可能丢失仍有价值的项目过程。用户选择方案 A：所有会话永久留在主列表，除非用户明确手动删除。

## 决策

### 不自动归档、隐藏或删除

- 新建会话默认进入左侧主会话列表，并持续保留在该列表中；时间经过、长期未打开、应用升级、项目解绑或数量增加都不会让它自动进入归档区。
- 系统不提供后台会话清理周期，也不因磁盘空间不足自动删除旧会话。
- 会话可以按最近活动排序，并支持搜索、筛选、固定和虚拟滚动；这些只改变当前视图，不改变会话是否仍在主列表的事实。
- 项目/个人长期记忆的“可能过时”规则不作用于会话历史。旧会话仍保存其原始消息、run、协调、Token 和事件记录。

### 删除只能由用户明确发起

- 删除入口属于单个或用户明确勾选的多个会话动作，必须列出影响数量并要求一次明确确认；不提供默认全选的“清空旧会话”。
- 删除会话只删除 Harness 保存的该会话内容、索引和受管会话产物引用，不删除用户项目文件、Git 历史、已经发送的外部消息或第三方服务数据。
- 删除后不能依赖 ADR-0039 所不存在的自动备份恢复；界面必须在确认前写明当前应用内是否可恢复，不用“移出列表”冒充删除。
- 全局汇总可以保留不含会话正文的已对账用量总数和必要审计计数，但不得继续把已删除正文用于模型上下文、记忆检索或搜索结果。

### 大列表性能

- 主列表只按视口加载必要行，搜索和排序通过结构化存储索引完成，不能因为永久保留就一次性把全部消息装入 renderer。
- 启动恢复只读取会话摘要和最近状态；打开具体会话时再加载正文和事件页。
- 会话数量或占用较大时可以显示统计和手动管理入口，但不得把提示升级为自动清理。

## 产品表现

- 左侧始终是完整主会话列表，没有系统自动生成的“已归档”黑箱。
- 用户可以搜索、按项目/状态筛选或固定会话；清除筛选后所有未删除会话重新出现。
- 设置页显示会话数量与占用，但只提供用户主动进入的管理动作。

## 收益

- 旧任务不会因为系统策略从主入口消失，行为最容易预测。
- 用户不必理解归档与删除的差别。
- 跨很长时间回看项目过程时仍能直接找到原会话。

## 代价

- 主列表和数据根会持续增长，需要搜索、筛选、分页与占用统计维持可用性。
- 用户需要自己清理不再需要的会话。
- 手动删除后没有自动备份兜底，误删代价更高。

## 与既有决策的关系

- 细化 ADR-0030 的会话历史自动持久化，并与 ADR-0037 的长期记忆过时状态保持分离。
- 会话索引和正文元数据属于 ADR-0032 的结构化真源，大型会话产物仍使用受管文件。
- ADR-0052 继续把会话、run 审计和最终成果排除在可再生成产物自动清理之外；ADR-0054 的完整工具输出随运行证据保留。
- 本 ADR 是后续目标设计，当前永久主列表、规模性能和真实删除行为均为 `UNPROVEN`。
