# ADR-0059：不维护模型价格，只记录 Token 与缓存用量

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

模型价格经常按地区、账户、套餐、缓存和批处理方式变化，维护价格表会制造过期数据与复杂界面。用户明确决定不需要 Viniper 写模型价格，用户自行到 Provider 查询；产品记录 Token 已经足够。

## 决策

### 产品不建立价格系统

- Viniper 不维护模型单价目录、币种、地区价、套餐价或折扣，也不在模型选择器、用量页、会话或报告中显示“每百万 Token 价格”。
- 不计算或展示任务费用估算、会话累计金额、日/月消费、预计账单、最便宜模型或节省了多少钱。
- Provider 即使返回金额或余额字段，也不把它们纳入 canonical usage 账本、智能路由或产品 UI；余额不足、配额或计费拒绝只按 Provider 错误如实显示，用户到对应官网核对账户。
- 本地模型也不标成“免费”或把电力、硬件成本虚构为 0。

### 保留可核对的 Token 账本

- 每个 Provider 尝试继续记录已提供或本地估算的 input、output、reasoning、cache read、cache write、cache miss、总 Token、模型/profile、持续时间和停止原因。
- Provider 提供最终 usage 时与本地估算分开展示；Provider 未提供某项时显示“未提供”，不伪造为 0。
- 主执行、在线重试、上下文压缩、自动审查和崩溃恢复的 Token 分开归类，并可汇总到 run、会话和本机时间范围。
- ADR-0041 的“只统计、不设 Harness 预算”继续成立，但“统计”从 Token/缓存/费用收敛为 Token/缓存，不再产生任何金额或费用字段。

### 智能模型分配不看价格

- ADR-0035 的智能路由只使用能力硬条件、用户允许范围、质量偏好、可用性、延迟、上下文、缓存连续性和用户排序，不抓取或比较价格。
- 原界面“节省”档改称“轻量优先”：倾向用户允许的较轻模型、较短推理和较低 Token 消耗，但不承诺更便宜。
- “质量优先 / 均衡 / 轻量优先”都必须显示选择原因；没有价格数据不会被当成 0 成本优势。

## 产品表现

- Token 用量页只展示 Token、缓存、请求次数、延迟和 Provider 是否给出最终值，不出现货币单位或价格入口。
- Provider 设置不要求用户填写价格，也不提供价格自动刷新。
- 帮助文案直接说明：“Viniper 不维护模型价格，请以 Provider 官网和你的账户账单为准。”

## 收益

- 避免过时、地区错误或套餐不适用的价格误导。
- Token 页面更简单，且仍可帮助用户理解上下文与缓存消耗。
- 智能路由不会因未知或错误价格做出错误选择。

## 代价

- 用户不能在 Viniper 内直接查看预计金额或跨 Provider 费用对比。
- Token 数量无法直接反映不同 Provider 的真实账单。
- 用户需要自行到 Provider 官网查询价格和余额。

## 与既有决策的关系

- 本 ADR 取代 ADR-0041、ADR-0035 及相关设计中所有本地费用/价格估算部分；无预算控制、Provider 客观限制和用户取消边界不变。
- 不改变 ADR-0003 的 Token 实时统计目标和 ADR-0053 的模型目录刷新；目录刷新不再维护价格字段。
- 本 ADR 是后续目标设计；费用字段移除、用量迁移、轻量优先路由和桌面/CLI 一致性均为 `UNPROVEN`。
