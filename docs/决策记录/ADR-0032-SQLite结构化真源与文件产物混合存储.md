# ADR-0032：采用 SQLite 结构化真源与文件产物混合存储

- 状态：Accepted
- 日期：2026-08-13
- 决策人：用户 / Viniper Harness 管理层
- 适用版本：`v0.0.1 Preview`

## 背景

继续只用 JSON/NDJSON 最容易延续当前 Demo，但会让多会话、并行 run、调度、Token 对账、信任记录和 Runtime 交接缺少统一事务边界；把所有日志、构建物和隔离工作区都存进数据库又会造成体积膨胀和维护负担。用户选择方案 C：SQLite 保存结构化权威状态，大型日志和产物继续使用受管文件。

## 决策

### SQLite 是结构化状态的唯一权威真源

- 默认数据根使用一个受管 SQLite 数据库保存会话与消息索引、run 状态与事件元数据、协调信封、调度定义与历史、Token/缓存账本、Provider profile 元数据、权限与信任记录、扩展清单、长期记忆条目及索引、Runtime 所有权租约和迁移版本。
- ADR-0031 的当前 Runtime 所有者是唯一数据库写入者；桌面 renderer、CLI 客户端、MCP 和插件都只能经正式应用服务或本机 IPC 读写，不能直接打开数据库改状态。
- 需要同时成立的状态变化使用同一事务提交，例如“run 完成 + usage 对账 + 调度历史更新”，避免界面已完成而账本仍在运行的分叉。
- 数据库不保存 Provider Key、验证码、私钥或其他秘密明文；它只保存 SecretVault 引用和“是否已配置”等非秘密状态。

### 大型内容继续使用文件

- 流式完整日志、大型工具输出、构建与测试产物、下载缓存、截图、导出文件、插件数据和 Git worktree 保存在数据根下各自受管目录，不作为 SQLite 大字段长期堆积。
- SQLite 只保存这些对象的类别、相对位置、所属会话/run、状态、大小、创建时间和生命周期；路径必须位于对应受管根内，不能引用成散落在桌面、用户主目录顶层或磁盘根目录的临时文件。
- 用户项目中的正式成果仍留在用户选择的位置；混合存储只管理 Harness 自身状态和运行产物，不接管或搬运用户原文件。
- 文件不存在、写入未完成或引用失效时必须显示为“产物缺失 / 不完整”，不能让数据库记录冒充真实文件仍然存在。
- ADR-0054 已确定完整工具输出流式进入受管文件，SQLite 只保存摘要、范围、完整性和引用；模型按需接收有界片段。
- ADR-0052 将受管文件分为正式/审计、专门恢复保护和可再生成三类，只有明确登记为可再生成的产物可按周期清理。

### 事件与恢复

- SQLite 保存规范化事件和当前投影的事务关系；超大原始流可以按文件分段保存，并由数据库记录连续范围和最终状态。
- 异常退出恢复以数据库事务和已落盘文件为准，不从 renderer 临时状态反推权威结果。
- 单一写入者不等于不做恢复验证：新 Runtime 所有者接管前仍需完成数据库完整性、迁移版本和关键文件引用检查。

### 从当前文件存储迁移

- 当前 `sessions.json + events.ndjson` 是已存在的 Preview 实现事实，不因本 ADR 被改写成已迁移。
- 迁移必须先生成仅服务本次维护的一次性可恢复回滚副本，再以可重复执行的导入器写入新数据库；验证会话、消息、run、usage、调度和文件引用数量及关联后，才切换正式读写入口。该副本按 ADR-0039 不扩展成日常自动备份。
- 切换失败时继续使用旧数据或恢复本次回滚副本，不静默建立空数据库，不删除旧文件，不把部分导入标成完成。
- 旧格式的最终保留和清理必须由新的迁移任务合同决定；本 ADR 不授权当前执行层改库或删除历史数据。

## 产品表现

- 普通用户不需要选择“数据库模式”；设置中的存储页只显示数据位置、占用分类、迁移/恢复状态和大型产物清理入口。
- 桌面与 CLI 展示同一份会话、任务、Token、调度、插件和记忆状态；发生恢复或引用缺失时说明具体影响范围。
- 数据库、文件产物和 SecretVault 分开统计，不把秘密数量或内容暴露给 renderer。

## 收益

- 并行任务、调度和桌面/CLI 共享 Runtime 获得清楚的事务真源。
- 大日志、构建物和 worktree 不会拖累日常状态查询与维护操作的回滚副本。
- 结构化迁移、恢复和审计比散落的多份 JSON 更容易验证。

## 代价

- 需要实现数据库迁移、schema 版本、文件引用一致性和恢复检查。
- 数据库与文件两种存储都需要生命周期管理；维护操作的回滚副本不能只覆盖其中一种。
- 当前文件存储不能一步替换，迁移阶段需要兼容和回滚证据。

## 与既有决策的关系

- 细化 ADR-0031 的单一 Runtime 写入真源；单一所有者负责数据库与受管文件的协调。
- 不改变 ADR-0027 的 Git worktree 位置、ADR-0029 的插件独立数据目录或 ADR-0030 的记忆作用域。
- ADR-0039 已决定不提供周期性或滚动自动备份；本 ADR 只保留会改写正式存储的维护操作所需的一次性回滚条件。
- ADR-0052/0054 细化受管文件生命周期和完整工具输出，不允许通用清理器删除正式成果、运行证据或分类不明文件。
- ADR-0056 的项目索引属于可再生成受管产物；ADR-0061 的默认结构化事件进入 SQLite，用户主动生成的单次详细诊断进入受管文件。
- ADR-0066 的语义索引与 ADR-0067 的索引检查点同样属于可再生成受管产物；本地模型来源/版本元数据进入 SQLite，权重继续只存在受管模型文件区。
- ADR-0059 取消价格与金额字段；结构化 usage 只保存 Token、缓存、请求和耗时。
- 本 ADR 是后续目标设计，当前代码和真实迁移证据均为 `UNPROVEN`。
