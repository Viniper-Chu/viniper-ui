## 1. 用户目标与本轮结论

用户要求先在 GitHub 找到图片列出的前端 Skill，除既定主色调外整体重构前端，提升高级感，并保证后续完整版验收全部基于新前端。已安装并读取：

- Anthropic `frontend-design`：负责避免模板化、先冻结视觉方向与自我批评。
- Vercel `web-design-guidelines`：负责语义、焦点、表单、动效、内容、性能和 Windows 深色控件审查。
- `ui-ux-pro-max`：负责设计系统、信息密度、交互、图标和交付检查。
- Impeccable `4.0.4`：负责 replacement-world、Operate 模式、craft floor、机械 detector 和最终独立审查。

`vercel-react-best-practices` 不用于当前实现，因为 renderer 是原生 HTML/CSS/TypeScript DOM，不是 React/Next；`using-superpowers` 是通用工作流而非前端设计 Skill，当前已有项目工作流和 Visual Ralph，不再叠加。

Skill 自动建议中的紫色、装饰性玻璃、Bento 卡片墙、视差滚动、外部 Web Font 和移动端触觉不采纳：它们与用户固定冷青主色、离线 Electron、Operate 工作台和“整块页面、不要断层”冲突。保留 16px 基准字号、统一线性图标、清晰焦点、渐进披露、细分隔线、低强度状态动效与高密度可读布局。

## 3. 产品与方向真源

- 产品事实由 `PRODUCT.md` 维护；已有 `DESIGN.md` 中 Phase 7 视觉只作为反例与功能证据，不再是视觉权威。
- 访客模式为 Impeccable `Operate`：用户要完成任务，熟悉、清楚、状态可信优先于装饰表达。
- 构建路径为 code-first：用户已要求直接实施、提高效率；界面基于真实生产 DOM 与状态完成两轮有界截图验收，不以一张概念图冒充产品。
- Impeccable direction seed `f81fed8f` 已执行。采用第 7 个 grounded 方向：**冷青绘图仪工作台 / Cyan Plotter Rail**。

### 3.1 方向合同

- `THESIS`：界面是连续运行的绘图仪工作台；会话、run、Token、工具和协作沿一条可追溯信号轨组织，拒绝通用三栏聊天壳和卡片仪表盘。
- `OWN-WORLD`：保留既定冷青/薄荷/冰青语义色；以精密细线、刻度、注册点、短横历史和 V 形汇流轨形成识别。主画布连续，浮层只用于真正的 popover/drawer/dialog。
- `STORY`：用户先看到当前任务与是否需要处理，再沿轨读取步骤和结果；Token、权限、模型与工具细节按需展开；所有动作都能找到停止或恢复路径。
- `FIRST VIEWPORT`：46–48px 自定义顶栏贯穿窗口；左侧会话轨约 248–272px，中部执行画布为绝对主角，右侧详情默认收起。当前 run 的冷青轨从会话列表汇入标题和时间线，Token 入口贴近模型但不挤压标题。
- `FORM`：Operate / Cyan Plotter Rail；方向种子 `f81fed8f`。记忆点是连续的 V 形信号轨，而不是渐变、发光、巨型按钮或装饰卡片。
- `FINISH`：`unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, and DESIGN.md`。

### 3.2 从候选世界保留的纪律

- 来自数据场：Token 和耗时使用 tabular numerals，密度高但不闪烁；reduced motion 下完全静态。
- 来自节奏机：同一会话多 run 用一条不换行的运行轨和清楚的当前位置，不把流式内容混在一起。
- 来自信息噪声系统：使用明确的密度层级和容器断点，但不采用黑/橙/紫噪声或伪品牌装饰。
- 来自折纸序列：文件变更、权限、恢复与撤销状态必须可逆、可解释，不能只显示完成色。

## 4. 必须保留的用户重点

1. 主色只用既定巳月仙人模式意象的冷青、青绿和相邻冷色；状态红/黄独立语义化。不得改成紫色主题。
2. 正文默认 16px；常用导航、按钮、表单至少 14px；元数据通常 12–13px，任何生产文字不得小于 12px。系统缩放和长中文必须可换行或明确省略并可查看全文。
3. 顶部使用完全自定义、与页面同一画布的菜单和标题栏，信息结构参考 Codex/Claude Code；不得恢复 Electron 默认菜单或额外断层标题条。
4. 窗口必须是一整块连续页面：层级主要来自底色、留白和 1px 分隔线。禁止卡片套卡片、悬浮模块墙、全页玻璃和无意义大圆角。
5. 左侧历史使用等宽、等长、等间距的短横轨标记；状态点和文本是附加语义，不允许每条长短随机。
6. Token 入口和明细参考 Codex/Claude Code 的按需层：主栏只放总量/状态和小型 ring/rail；展开层分别显示估算、Provider 实际 usage、input/output、cache read/write/miss、上下文占用、压缩用量、请求与耗时。未知显示“未提供”，不冒充 0，不显示价格或预算。
7. 不用巨大主按钮。普通按钮高 32–36px，主要动作 36–40px；图标按钮视觉 20px、命中区至少 36px，均有 hover/focus/active/disabled/loading。
8. 品牌保持 `Viniper Harness`。重画一个小尺寸清楚的冷青 V 矢量图标，线条与信号轨同源；接入标题栏、窗口、Tray 和打包资产。当前无 OpenAI CLI Key，不能声称图标由 `gpt-image-2` 生成；本轮以可审计矢量生产资产交付，`gpt-image-2` 来源继续诚实标为 `UNPROVEN`。
9. 原生 Tray 右键菜单继续按 `Running / Unread / Pinned / Recent / More / New Agent / Show-Hide / Exit` 分组，保持原生菜单，不做 HTML 假菜单。
10. 桌面仍是独立 Harness；终端只是工具能力和 CLI 入口，不把桌面改成终端壳。

## 5. 本轮生产范围

### UI-1：设计系统与 AppShell

- 收敛 `renderer/styles` 中重复/覆盖的 token 和 Phase 7 临时 CSS；建立单一颜色、字体、间距、圆角、边界、动效、z-index、图标和状态 token。
- 重构自定义标题栏、全局导航、会话侧栏、中央工作区、可收起详情层和 Composer，使 1440×900、1280×800、960×720 都保持连续画布。
- 每个低频菜单使用 popover/drawer/inline expansion；overlay 不得被 `overflow` 容器裁切，Escape 和焦点回归必须工作。

### UI-2：现有功能全部换新

- 重构当前所有已实现 renderer 消费者：`sessions / conversation / activity / composer / coordination / telemetry / scheduler / extensions / providers / workspaces / programming` 及设置、权限、自动审查、错误、空状态和加载状态。
- 保留所有已实现功能、事件和 IPC；不得用漂亮静态数据替换 canonical snapshot，不得删除 Viniper 功能基线。
- 尚未实现的 Phase 8 后端功能只建立可复用导航槽位和诚实的 unavailable/empty state，不添加会误导用户的可点击假功能。后续 CP2–CP8 的 UI 必须复用本轮 token、组件和轨道结构，不得恢复旧界面。

### UI-3：品牌与图标

- 生产图标必须是原创、简洁、矢量优先的 V：两条等粗冷青信号线在中心汇合，负空间仍能读出 V；16/20/24/32px 不糊、不粘连。
- 形成 SVG、PNG 和 Windows ICO/PE 所需尺寸并实际进入窗口、Tray、portable/package 消费者；不得用截图、emoji 或其他产品标志。

### UI-4：交互、性能与无障碍

- 语义元素优先；图标按钮有 `aria-label`，装饰 SVG `aria-hidden`，表单有可点击 label，异步状态用克制的 `aria-live`。
- 所有交互有 `:focus-visible`，不用 `outline: none` 无替代；不使用 `transition: all`；动效只用明确属性并支持 `prefers-reduced-motion`。
- 长标题、长项目名、长模型名、Token 大数、0/1/50+/10,000 会话、空数组和错误文案都不破版；会话大列表采用现有/后续虚拟化合同，不在本轮用全量重绘掩盖性能问题。
- 数字使用 `font-variant-numeric: tabular-nums`；日期和数字用 `Intl.*`；Windows 深色原生 `select/input` 有显式前景/背景。

## 6. 验收门

### 6.1 机械门

- `npm run typecheck`、clean build、完整测试及所有新增 UI contract 测试 PASS；Phase 8 CP1 的 168 项基线不得回退。
- 对变更的 HTML/CSS/renderer 文件只运行一次 Impeccable detector；Vercel Web Interface Guidelines 对变更文件逐条审查并输出 `file:line` 结果。
- 检查：生产文字 `<12px` 为 0、`transition: all` 为 0、无替代的 `outline:none` 为 0、无 label 表单为 0、无 aria-label 图标按钮为 0、默认 Electron 菜单重新出现为 0、外部 Web Font 请求为 0。

### 6.2 真窗门

使用当前生产 Electron 入口和隔离数据根，在同一源码冻结点一次批量捕获第一轮：

- 1440×900：主工作台、Token 展开、Provider 设置、定时任务、扩展中心、编程/工作区、顶部菜单。
- 960×720：主工作台、左侧历史、Composer、Token 入口/展开、长中文/长模型名。
- 代表性状态：空、加载、两个独立 run、等待用户、失败可恢复、disabled、通知/未读、权限选择。

所有截图必须是新前端；旧 Phase 7 截图只能作反例，不能作为验收证据。第一轮集中修复全部重要问题，再做一次相同视口确认；正常上限两轮。

### 6.3 视觉门

- 自定义顶栏与主体无断层；中央执行时间线是主角；左侧短横均匀；Token 无重叠/遮挡；按钮无巨型 CTA；V 图标在小尺寸清楚。
- 采用 Visual Ralph 与 Impeccable fresh finish review 双门；Visual Ralph 总分不得低于 92，且 typography、hierarchy、continuity、token readability、interaction consistency 均不得低于 90。
- 分数不是替代证据：任一用户重点未满足、真实控件不可用、截图来自旧前端或窗口尺寸未覆盖，均不得 PASS。

- 现有 canonical renderer/IPC 消费者全在，桌面 fake E2E、Tray 模板/生命周期、Provider 设置、调度、跨会话、Token/cache、P1–P4 编程闭环均不回退。
