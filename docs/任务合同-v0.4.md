## R8 结构化历史与真实 Agent 工具循环

- `ProviderRequest` 改为协议无关的结构化消息/内容项，保留 user、assistant、tool call、tool result、reasoning/continuation 标识和原始顺序。禁止再用 `role: text` 拼接历史。
- 工具定义由 `ToolRegistry` 以稳定顺序、JSON Schema 和权限元数据提供给 Provider。工具集只在 run 开始时快照；运行中变化进入下一代 ContextProfile。
- Provider 发出完整工具调用后，Agent Runtime 统一走：解析与校验 → 权限门 → ToolRegistry 执行 → canonical 活动/消息 → tool result → 同一 Provider 续轮。Provider 适配器不得自己执行本地工具。
- 本阶段可执行工具仅限既有本地 Demo 和内置 coordination plugin；未知第三方插件、任意 shell 和真实文件写入仍不可执行。
- 取消、工具拒绝、工具失败、Provider 失败都要形成可见 canonical 状态；不丢掉已完成文本。设置合理且可见的工具续轮上限，达到上限时停止并说明，不无限循环。
- OpenAI `call_id`、Anthropic `tool_use_id`、Gemini function call/result 关联和 Chat `tool_call_id` 必须原样保留；续轮不能猜测 ID。
- 会话并行、同会话串行、队列、委派结果和 completion-listener 隔离不得回归。

## R9 协议族适配器

实现五个可复用协议族：

1. OpenAI Responses：typed SSE、output item/function call 聚合、continuation、usage/cache mapping。
2. Anthropic Messages：message/content block SSE、thinking、tool_use/tool_result、cache_control、usage。
3. Gemini Interactions：interaction/step SSE、arguments delta 聚合、function result 续轮、可选 previous interaction、usage。
4. OpenAI Chat Completions：role/tool history、SSE delta、reasoning、tool calls、usage。
5. SenseNova 自定义封装：自定义 data/SSE/usage；未由官网确认的工具和缓存能力保持关闭。

每个协议族必须统一产出 Provider-neutral events/error/usage；HTTP 错误至少区分认证、余额/配额、限流、无模型/无权限、无效请求、网络、服务端和取消。错误正文不能把请求头或凭据带入日志/UI。

## R10 Provider Profile Catalog

按照 `docs/API适配矩阵-v0.1.md` 建立 profile，不复制协议客户端。首批范围：

- 国外：OpenAI GPT、Anthropic Claude、xAI Grok、Google Gemini。
- 国内：DeepSeek、阿里百炼/Qwen、火山方舟/豆包、腾讯 TokenHub/混元、百度千帆/文心、智谱 GLM、Kimi、MiniMax、StepFun、讯飞星火、华为云 MaaS、百川、零一万物 Yi、商汤 SenseNova、小米 MiMo、美团 LongCat、360 智脑、蚂蚁百灵、中国电信 TeleChat、中国联通元景、硅基流动、魔搭 ModelScope、京东 JoyBuilder。
- 自定义：OpenAI-compatible，必须由用户明确填写 base URL、model 和声明能力；不能自动声称 tools/cache 可用。

每个 profile 至少声明 id、类别、厂商、协议族、默认/手工 endpoint、鉴权字段、模型发现策略、stream/tools/reasoning/cache/usage 能力、证据等级、官方资料链接。无统一端点或模型能力动态时必须要求手工配置并显示“部分能力未由官网确认”。

中国移动九天、天工、网易伏羲等没有足够当前第一方公开通用文本 API 证据的项目只在矩阵附录说明，可由自定义端点接入；不得伪装为官网已验证 profile。

## R11 密钥、连接与设置

- SecretVault 扩展为 per-profile 密钥引用。普通 snapshot/IPC/DOM/日志仍只能看到 configured，不返回明文或片段。
- 支持常规 Bearer、x-api-key、api-key，以及电信 TeleChat 的多字段鉴权；额外秘密也必须进入安全存储，不能进入普通 settings JSON。
- Provider 设置采用“国外模型 / 国内模型 / 国内平台 / 自定义”分类、搜索和简单连接卡。初学者主路径只有：选厂商 → 保存凭据 → 获取/填写模型 → 用于当前会话；endpoint、协议与能力放进高级区。
- `/models` 或官方模型发现存在时可做无生成连接测试；不存在时不伪造模型列表，允许手工模型 ID，并明确“尚未真实验证”。
- 当前会话运行中禁止更换 Provider/model/tool schema/Skill；下一轮生效。

## R12 Provider-aware 缓存与 Token 对账

- 稳定前缀固定为 tools → system/instructions → project → enabled Skills → 稳定历史；当前用户输入、时间戳、随机 ID 和变化状态放在断点之后。
- OpenAI GPT-5.6 及后续家族：生成语义化、稳定的 `prompt_cache_key`，在稳定前缀末端使用显式 breakpoint；按模式设置 `prompt_cache_options`；映射 `cached_tokens` 与 `cache_write_tokens`。更早模型走其官方支持规则。
- Claude：保持 tools → system → messages 顺序，automatic 或末端显式 `cache_control`，支持 5 分钟/1 小时，并映射 cache creation/read。
- xAI：稳定 `x-grok-conv-id` / `prompt_cache_key`，保持追加式前缀；映射 cached tokens。
- Gemini Interactions：使用隐式缓存；默认 stateless / `store=false`，仍保持稳定大前缀；若以后启用服务端状态，必须由用户显式选择并说明保存语义。
- 国内 Provider 只映射官方明确公开的缓存参数/usage；未确认时显示“未提供/未确认”，不能按 0 命中冒充真实统计。
- TokenUsage 增加必要的 cache write 字段；实时估算、Provider 最终对账、current/session/app 累计继续隔离。
