## 1. 本阶段目标

`新建会话并选择项目 -> 选择 DeepSeek/profile/model -> 模型调用项目只读工具 -> 统一权限处理 -> 工具结果续轮 -> 最终答复、历史与 Token 持久化 -> Windows x64 便携包`

## 4. B 组：P1 产品能力

### R1 显式项目会话

- 桌面端提供容易理解的“打开项目 / 新建项目会话”入口，使用 Electron 原生目录选择器；取消选择不创建空会话、不改变当前会话。
- 新会话保存规范绝对项目根，界面持续显示项目名称、路径和当前能力“可搜索 / 可读取”。已有消息或活动 run 的会话不得静默换根；最简单可接受策略是另建项目会话。
- CLI 默认使用当前工作目录，并为非交互入口提供明确 `--project <path>` 或等价稳定参数；桌面与 CLI 都调用同一个 session/application port。
- 目录不存在、不是目录或不可读取时在 Provider 请求前失败，且保留原会话和历史。

### R2 三个最小只读编程工具

在 `src/features/programming`（或等价高内聚目录）实现并注册同一 ToolRegistry 的最小工具集：

1. `project.list`：列出项目内指定相对目录的直接子项，返回名称、类型和相对路径；支持可解释上限与截断标记。
2. `project.search`：在项目内按文本/路径条件搜索，优先使用可用的高效本机搜索实现，保持实时回退；返回相对路径、行号、短片段和结果来源，不扫描项目外。
3. `project.read`：按相对路径和可选行范围读取文本文件，返回行号、编码/文本状态、范围和截断信息。

共同合同：

- 工具 schema 简短、职责单一、参数可由主流模型稳定生成；错误采用结构化可诊断结果，不把异常堆栈直接塞给模型。
- 所有路径从当前 session 的规范项目根解析；普通 `..`、绝对路径和解析后落在根外的符号链接目标拒绝执行。只做这条必要边界，不扩展成安全攻防项目。
- 不读取平台凭据库、Harness Preview 数据根、`.git` 内部对象或常见私钥/凭据文件；拒绝时说明“该文件未发送给模型”。
- 二进制、不可解码或过大文件不整块进入模型；返回类型/大小和建议的下一步。文本读取与搜索结果有明确字节/行/条数上限。
- P1 不建立全盘或后台索引。索引关闭/不存在时的项目内实时搜索就是正式路径；ADR-0056/0066 的增量/语义索引留给后续阶段。

### R3 工具循环、权限与历史

- 三个 P1 工具均标为只读：`auto` 模式可自动执行，`ask` 模式必须停在现有批准卡；允许一次后同一 callId 精确执行一次，拒绝时执行零次并让模型收到明确结果。
- 工具请求、批准/拒绝、结果、Provider continuation、最终答复与 usage 都进入既有正式事件和历史，不新增第二套 P1 日志或测试捷径。
- 重启隔离 Runtime 后，项目根、普通消息、结构化 Provider history、工具对和 Token 累计仍可恢复；不同项目会话不得混入文件内容或历史。
- 本阶段不伪造“项目完全访问/电脑完全访问”已经覆盖 P2/P3。现有 `ask/auto` 继续可用；两级完全访问的实际读写/终端范围在对应工具落地时再验收。

### R4 DeepSeek 优先但协议族不回退

- 新 P1 descriptors 必须进入公共 ToolRegistry，并在五个协议族的本地 fake/序列化测试中保持可投射、可续轮或按能力清楚 fail-closed。
- DeepSeek 继续走 OpenAI Chat 适配边界：canonical 点号工具名经既有可逆投射，thinking 工具续轮完整回传 `reasoning_content`，Provider call id 和 usage/cache 字段保持。
- 不为 DeepSeek 复制项目工具、权限、历史或 Token 代码；不修改其他 Provider 的请求字段来迁就 DeepSeek。

### R5 桌面、CLI 与简单交互

- 桌面主工作区显示当前项目和 P1 能力，工具时间线用普通语言呈现“搜索了什么、读取了什么、结果是否截断/拒绝”，详细参数按需展开。
- 文件选择、路径错误、等待批准、无结果、截断、二进制和取消均有可见状态；不能用巨型按钮或终端日志淹没主任务。
- CLI TTY、`--plain` 和 `--jsonl` 均投影同一 P1 事件；JSONL 保持一行一个稳定对象且无 ANSI。
- 1440×900 与 960×720 原生窗口均须真实观察；物理界面未观察时只能写 `UNPROVEN`，不能由 DOM/static test 代替。

### R6 Windows x64 便携交付

- 增加仓库内可复现的 Windows portable 打包脚本，不引入 Agent 框架，也不生成安装器。
- 产物固定进入 `D:\Agent\codex\工作输出\Phase6-P1-Windows-Portable\`，包含可直接运行的便携目录和压缩包；中间打包残留进入 `codex\运行残留`。

- 不写注册表、快捷方式、服务、计划任务或开机启动，不把会话/凭据写入程序目录。当前只验收 Windows x64；arm64 与安装器保持 `UNPROVEN / 未实现`。

## 5. DeepSeek 官方事实基线

实现前只用第一方资料复核：

- 模型目录：`https://api-docs.deepseek.com/api/list-models`
- Chat Completions：`https://api-docs.deepseek.com/api/create-chat-completion`
- Tool Calls：`https://api-docs.deepseek.com/guides/tool_calls`
- Thinking 工具续轮：`https://api-docs.deepseek.com/guides/thinking_mode`

当前基线是 `deepseek-v4-flash` / `deepseek-v4-pro`；函数名只能使用字母、数字、下划线和连字符且不超过 64 字符；thinking 模式发生工具调用时，后续请求必须完整回传该 assistant message 的 `reasoning_content`。若官网或真实 `/models` 与本合同冲突，先在 Checkpoint 回报，不自行扩大范围。

## 6. 本轮真实 API 授权与硬停止

- 用户已明确授权使用此前提供的真实 DeepSeek API Key完成本阶段复验。凭据只允许从本机既有安全来源进入测试进程内存或隔离 Electron `safeStorage`；不得打印、复制到命令参数、源码、普通文件、报告、截图、Git 或协调消息。
- 允许 `GET /models` 最多 1 次；不调用 balance，不查询或记录价格、金额、币种或费用。
- generation HTTP POST 总上限为 5 次，包含工具续轮、失败和网络重试；总 Provider 实际 input 不超过 60,000 tokens，output 不超过 5,000 tokens。任一上限到达立即停止。
- 主测只用 `/models` 当前存在的 `deepseek-v4-flash`。认证失败、模型不存在、请求无效、凭据无法安全注入或离线门未全绿时，真实生成次数保持 0 并准确报告阻断。
- 只允许一个生产链场景：隔离项目包含少量无敏感文本与 `AGENTS.md` 标记；模型必须通过 P1 搜索/读取工具找出指定事实、根据工具结果回答，并在最终事件中形成真实 usage。工具循环所需的多个 POST 仍合计在 5 次内。
- 真实请求前先向管理层提交 Checkpoint 2：离线结果、预计 POST 数、隔离根、模型 id、密钥不落盘证明和停止条件。未经管理层续发不得调用。
- 首次产品失败立即停止真实调用，保留首错层；先用本地 fake 建红灯和最小修复。只有剩余总上限允许且管理层明确续发，才可用一个新场景复验。
- usage 冻结后，截图、便携包、报告、清理或测试 harness 失败不得增加请求。清理隔离 safeStorage 凭据和专属运行根，保留脱敏最小事件/usage 证据；最终不回显 Key。

以上是测试验收授权，不是产品 Token 预算功能。
