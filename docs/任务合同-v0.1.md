## 用户目标与当前基线

用户要从零搭建一个不依赖现成 Agent 框架的桌面 Agent Harness，最终兼容主流模型 API、提高缓存命中，并完整继承 Viniper v5.0.2 的所有功能。Windows 当前必须原生运行；macOS 从第一天同步设计，每阶段更新草案但当前不宣称真机通过。界面以 Viniper 为功能和交互基线，可做克制优化，操作必须简单。

当前 `D:\Agent` 为非 Git 新项目，仅有设计草案和本合同类文档；Viniper 参考仓库干净且只读，正在端口 17373 运行，严禁修改、停止或写入其用户数据。

## 本轮结果目标

在 `D:\Agent` 实现一个可真实运行的 Windows Electron 桌面纵切，并初始化 Git：

1. 原生窗口展示 `DESIGN.md` 定义的 Calm Command Studio 界面，具备 Chat/Agent 切换、会话侧栏、主对话、Composer、状态轨道、按需活动检查器和设置中心。
2. 自建 TypeScript Agent Runtime，界面只通过 preload/IPC 调用；不得接入 Claude Code、Codex 或其他 Agent 框架。
3. Demo Provider 走正式 `ModelProvider` 接口并产生真实流式事件；Chat 只回复，Agent 可产生一个只读示例工具事件。Demo 标识必须清楚。
4. 会话创建、切换、重命名、置顶、删除和重启恢复可用；Agent 运行时至少实现发送、排队、取消的最小闭环。
5. 建立 Provider Registry、原生适配器边界与 `CachePlan` 稳定前缀规划；首轮无需真实调用付费模型，但设置页应展示 OpenAI、Anthropic、Gemini、DeepSeek 和 OpenAI-compatible 的可配置入口与能力状态。
6. Windows 原生启动可见，窄窗和常见大窗主要内容可达；补足最小单元测试和构建验证。
7. 创建并更新 `docs/平台草案/macOS实现草案-v0.1.md` 的本轮差异，保持 macOS `UNPROVEN`。

## 架构与影响边界

- 允许修改：`D:\Agent` 内新建的生产源码、测试、构建配置、正式文档与本轮 `codex` 证据。
- 禁止修改：`D:\Viniper UI\source\viniper-ui` 全部内容；桌面工作流；系统配置；用户会话、凭据、数据库和其他项目。
- 依赖方向：renderer -> preload contract -> application/runtime -> domain interfaces；infrastructure/provider/storage 实现上层接口，domain 不依赖 Electron、DOM 或具体 Provider。
- 唯一真源：session snapshot + append-only runtime events；Provider 适配器不得复制会话状态机；活动检查器只读。
- 工具执行第一阶段只允许内置只读 Demo 工具，不能执行任意 shell 或写文件。

## A/B 验收矩阵

- A1 Chat/Agent 边界：Chat 文本即使要求读文件也不产生工具事件。
- A2 Viniper 核心壳：模式、会话、Composer、模型/权限、设置和置顶入口可达。
- A3 会话隔离：两个会话的消息、运行状态、队列不串线。
- B1 Demo 链路：发送 -> IPC -> Runtime -> Provider stream -> canonical events -> Conversation/Inspector。
- B2 队列与取消：运行中第二条 Agent 输入进入队列；取消后当前 run 终止并能继续处理后续输入。
- B3 恢复：重启或重载后已有会话和消息从项目自有数据目录恢复。
- B4 缓存计划：system/tool/project 稳定段位于可复用前缀，当前消息追加；界面显示本轮复用/新增上下文的 Demo 指标。
