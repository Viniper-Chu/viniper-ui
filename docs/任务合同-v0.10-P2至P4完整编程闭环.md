## 4. 统一能力与安全合同

### R1 单一 Runtime 与功能目录

- P2 放入 `src/features/programming`，P3 放入 `src/features/terminal`，P4 工作区与 Git 分别放入 `src/features/workspaces`、`src/features/git`，自动审查放入 `src/features/review`；平台实现进入对应 `src/platform/*` 目录，renderer 只做投影。
- 所有模型可调用能力注册到现有 ToolRegistry，复用现有 Agent tool loop、PermissionPolicy、Provider continuation、事件、取消、Token ledger 和 session 隔离；不得新增第二个 coding loop。
- installed Harness 程序目录、Harness 自身数据根、SecretVault、权限策略、ToolRegistry 和 Runtime 配置不是用户项目。即使用户误选 Harness 源码或安装目录，也必须阻止 Agent 借产品工具修改自身运行时；普通外部用户项目不增加无关限制。

### R2 权限与审查是独立维度

- 保留普通 `ask/auto` 语义，并真正接通“项目完全访问”和“电脑完全访问”。普通模式的写文件、删除、终端和 Git 状态变更进入可恢复批准；只读状态可按既有规则自动执行。
- 项目完全访问只对用户明确选择并受信任的项目生效，可记住到该项目；它允许该项目内文件变更、终端、依赖、构建测试和 Git 操作免逐项批准，但不扩大到项目外文件、系统提权或未知插件。
- 电脑完全访问只在当前 Runtime 所有者进程存活期间有效；退出、崩溃或 Runtime 交接后失效。它取消当前已注册本地工具的逐项批准，不创建管理员权限，也不新增产品尚未提供的能力。
- 两级完全访问均不能修改 Harness 自身、读取或回显 SecretVault 明文、关闭权限/审计、绕过第三方登录/验证码/支付或静默提权。
- 审查策略为 `auto/on/off`，与权限模式分开保存并按 run 冻结。`auto` 观察到文件、进程、Git 或正式交付变更时开启；纯读取时跳过。

## 5. P2：文件变更与差异

### R3 工具集合

在 P1 工具之外增加职责单一的公共工具：

1. `project.write`：创建新文本文件或明确替换整个文本文件；区分 `create` 与 `replace`，默认不覆盖现有文件。
2. `project.edit`：按精确旧文本执行一个或多个局部替换；旧文本不存在或匹配数量与声明不符时零写入，返回可诊断冲突。
3. `project.move`：在当前项目内移动或重命名一个文件/目录；默认不覆盖目标。
4. `project.delete`：删除当前项目内明确路径。默认进入 Harness 为本 run 管理的可恢复区并生成恢复回执；不把“移动到恢复区”伪装成永久删除。
5. `project.diff`：只读返回本 run 或指定项目路径的结构化差异摘要与有界 patch；完整差异保存到受管输出并可继续读取。

共同要求：

- 继续使用 P1 的规范相对路径、根外符号链接、秘密路径、二进制和大小边界；写入前后都重新确认实际目标仍在项目根内。
- 文本写入使用同目录临时文件与原子替换；失败不留下半文件。局部编辑以精确旧文本作为并发校验，不引入哈希字段。
- 每次成功变更记录动作、相对路径、前后大小、差异摘要和恢复信息；模型、桌面与 CLI 不接收无限正文。
- 删除、覆盖、移动和批量编辑都必须按一次工具调用实现全成或零写入；不得在失败后留下部分清单。
- `AGENTS.md` 等项目指令在 run 内仍使用开工快照；本 run 修改只影响下一 run。

### P2 Checkpoint 门

- 建立红灯并通过：创建、精确编辑、冲突零写入、原子替换、移动、可恢复删除、恢复、差异投影、秘密/越界零写入、权限允许/拒绝/callId 去重、两个会话同路径资源冲突。
- 桌面显示人话文件动作与折叠差异；CLI TTY/plain/JSONL 投影同一事件。
- P2 专项、typecheck、现有 110 项全部绿色后提交 Checkpoint 1；未经管理层复核不得进入 P3 生产修改。

## 6. P3：终端、依赖、构建测试与诊断

### R4 工具集合与进程模型

1. `terminal.run`：在当前 run 工作区内启动本机 shell 命令，参数含命令、可选项目内 cwd 和可解释超时；返回 execution id、退出码、耗时、stdout/stderr 有界片段与完整输出引用。
2. `terminal.output`：只读续取本 run 拥有的完整 stdout/stderr 范围；不能用任意路径读取 Harness 数据根。
3. 取消继续使用现有 run/cancel 应用动作，不要求模型调用“取消工具”；必须终止该 run 拥有的完整进程树，并生成 `cancelled` 终态。

执行要求：

- Windows 使用原生进程和 PowerShell 语义，cwd 必须位于当前 shared 或 isolated 工作区；不把终端嵌入桌面当作产品架构，也不调用外部 coding agent。
- 环境只继承运行项目所需的普通系统变量和 PATH；SecretVault 不自动注入终端，Provider Key 不进入命令、环境投影、输出或报告。
- 不自动提权、不绕过 UAC，只终止 Harness 创建且仍可归属的进程树。超时、非零退出、命令不存在与用户取消是不同结构化状态。
- stdout/stderr 持续写入本 run 受管文件；timeline 与模型只接收有界首尾片段、总字节和截断标记。ANSI 控制码不得污染 plain/JSONL。
- 安装依赖、build、test、lint、typecheck 都通过同一 `terminal.run`，但事件标记命令用途；网络依赖在普通模式仍需批准，项目完全访问可免重复批准。

### P3 Checkpoint 门

- 建立红灯并通过：成功/非零/不存在命令、stdout/stderr 分离、大输出续读、项目 cwd、超时、取消整个子进程树、两会话进程隔离、权限四种模式、CLI 退出状态。
- 在新建的最小 Node fixture 中真实运行依赖无关的 build/test；不为测试下载新依赖，不触网。
- P2 回归、P3 专项、typecheck 和全量测试绿色后提交 Checkpoint 2；未经管理层复核不得进入 P4 生产修改。

## 7. P4：Git、隔离工作树、提交、合并与复核

### R5 Git 工具

增加以下公共工具，全部使用本机 Git 且输出结构化结果：

1. `git.status`：分支、跟踪/未跟踪/冲突及简明文件状态。
2. `git.diff`：工作区、暂存区或指定基线的有界差异与完整受管引用。
3. `git.log`：有界历史的时间、作者和主题；产品与报告不要求展示提交哈希。
4. `git.branch.create`：在明确基线创建任务分支，不覆盖既有分支。
5. `git.commit`：只纳入本 run 可证明拥有的路径并使用可读主题；禁止全量暂存未知改动、amend、reset、clean、自动 stash 或改写历史。
6. `git.merge`：作为独立可见动作把已完成任务分支合并到明确目标；冲突时停止并保留现场，不强制覆盖。

P4 不实现 fetch、pull、push、远程建分支、远程 PR、force、rebase 或远程删除；这些不是本轮“本地完整编程闭环”的缺口。

### R6 自适应工作区

- run 支持 `workspaceMode=auto/shared/isolated`。只读使用原项目；`auto` 在干净 Git 仓库出现文件状态变更或 Git 任务前创建受管原生 worktree，避免后来扩展范围时污染原目录。用户显式选择 `shared` 才在原目录做无竞争小改动；非 Git 项目使用 shared 与资源锁，不伪造 worktree。
- worktree 只能位于 Harness 隔离数据根的 `workspaces` 受管目录，禁止放入用户项目或项目根 `codex` 之外的散落位置。仓库元数据操作使用仓库级独占锁。
- 原目录有用户未提交改动时，不自动 stash、复制、提交、覆盖或清理。无法证明任务不依赖这些改动时保持 shared/等待用户选择，不能悄悄建立错误基线。
- 隔离任务只有在确定性检查完成、适用自动审查结束且无阻断问题时自动形成一个任务提交；shared/original 只有用户目标明确要求提交时才能提交。
- 合并前复查目标基线。冲突、检查失败、审查问题、未合并或归属不明时保留 worktree 和任务分支，不自动删除。
- 明确合并成功、合并后检查完成且 worktree 干净时回收大目录，保留任务分支或等价恢复引用、差异/检查/审查/合并回执七天；到期清理只处理 Harness 拥有且状态仍明确的恢复引用。测试必须使用新建 fixture 仓库，不在 `D:\Agent` 自身上演练产品合并。

### R7 自动审查

- 自动审查先读取确定性检查、任务目标、最终差异、工具回执与交付物，再使用执行 run 同一 Provider/profile/model/reasoning 快照在全新只读上下文中审查；不复制隐藏推理或完整聊天。
- 审查工具集只允许读取本 run 证据、项目文件、Git 状态/差异和测试输出；不能调用 P2 写入、P3 终端、P4 提交/合并或任何外部状态变更。
- 第一轮输出问题、证据、严重度、建议和 `PASS/ISSUES/UNPROVEN`。仅在证据冲突、发现问题/无法验证或多域高影响时追加第二轮定向复核；硬停止为最多两轮。
- 审查永远只报告，不自动修复、重跑会产生外部影响的命令、提交或合并。原模型不可用时标记 `UNPROVEN/REVIEW_STOPPED`，不静默换模型。
- 本地 fake 必须证明触发、跳过、强制 on/off、只读工具白名单、两轮上限、usage/cache 计入本 run；真实 DeepSeek 审查另受第 9 节授权门约束。

### P4 Checkpoint 门

- 新建干净与脏状态 Git fixture，覆盖 status/diff/log、任务分支、单任务提交、shared 零自动提交、显式 shared 提交、合并成功、冲突保留、七天恢复、非 Git 回退和零 reset/clean/stash。
- local fake 端到端完成“模型编辑 -> 终端测试 -> Git diff -> 自动审查 -> 隔离任务提交 -> 显式合并”，并证明审查执行写工具次数为 0。
