# Agent Desktop 架构参考与采纳记录 v0.1

日期：2026-08-12

定位：记录本项目从 Codex CLI/桌面、Claude Code CLI、Hermes Agent 与 DeepSeek 官方接口中采纳的可验证设计。它不是运行时依赖清单，也不授权复制第三方代码。

## 第一性目标

输入是用户任务、会话状态、已启用 Skills、插件/工具能力、Provider 配置和时间触发；输出是可追溯的消息、工具结果、协作回执、Token usage 和运行历史。硬约束是会话默认隔离、跨会话协作显式、密钥不进渲染快照/日志/Git、Windows 原生运行、macOS 不被架构锁死。

权威主线采用“窄核心 + 边缘能力”：领域核心只认识会话、运行、事件、能力与端口；Provider、插件、Skill、桌面安全存储和调度器在边缘接入。任何入口——手动发送、委派、定时触发——都进入同一个 Agent Runtime。

## Codex：采纳的模式

官方资料：

- Skills: <https://learn.chatgpt.com/docs/build-skills>
- Subagents: <https://learn.chatgpt.com/docs/agent-configuration/subagents>
- Scheduled tasks: <https://learn.chatgpt.com/docs/automations>

采纳：

- Skill 使用渐进披露：目录扫描时只读取名称、描述和能力摘要；会话明确启用或模型匹配后才加载完整 `SKILL.md`，脚本/参考/资产仍按需读取。
- 协作由显式编排器管理 `send / delegate / wait / complete`，每个参与会话拥有独立上下文和运行控制，父会话只接收结构化回执与总结。
- 自动任务既可投递到现有会话保持连续性，也可每次新建隔离会话；任务定义、触发记录和会话结果分开保存。

不采纳：

- 不依赖 Codex 本体、Codex 云端工作树或云端任务服务；当前产品的本地调度、会话和工作区选择自行实现。ADR-0027 可以调用本机原生 Git worktree，但不复用 Codex 的任务服务或运行框架。
- 不照搬 Codex 的开发者向复杂入口；普通用户主路径仍为添加 Provider、选模型、交任务。

## Claude Code：采纳的模式

官方资料：

- Subagents: <https://code.claude.com/docs/en/sub-agents>
- Status line: <https://code.claude.com/docs/en/statusline>
- Hooks: <https://code.claude.com/docs/en/hooks>
- Plugins: <https://code.claude.com/docs/en/plugins>

采纳：

- 子任务/委派使用隔离上下文、独立工具与权限快照；前台/后台只是调度方式，不改变权限合同。
- Token 状态采用事件驱动、节流刷新；流式阶段显示明确的估算值，Provider usage 到达后原位对账成权威值。
- 生命周期事件有稳定名称，后续 Hook 或插件订阅事件而不是修改核心历史。
- 插件包只通过清单声明 Skills、工具、Provider 和 UI 扩展；渲染器不直接加载插件代码。

不采纳：

- 不复刻终端 statusline 配置文件或 Claude Code 的命令语法；同样的信息改为桌面 Token 脉搏与活动面板。
- 不让后台任务绕过权限；无人值守时遇到需要确认的能力应进入等待/失败态，而不是自动批准。

## Hermes Agent：采纳的模式

官方资料：

- Repository/README: <https://github.com/NousResearch/hermes-agent>
- Architecture rules: <https://github.com/NousResearch/hermes-agent/blob/main/AGENTS.md>
- Plugins: <https://github.com/NousResearch/hermes-agent/blob/main/docs/features/plugin-system.md>
- Skills: <https://github.com/NousResearch/hermes-agent/blob/main/docs/user-guide/features/skills.md>
- Cron: <https://github.com/NousResearch/hermes-agent/blob/main/docs/user-guide/features/cron.md>

采纳：

- 同一套窄核心服务桌面、未来 CLI 和后台调度入口；能力优先放在 Skill、插件或 Provider 边界，只有基本语义进入 core。
- 一个会话开始运行后，system 前缀、工具定义、项目指令和 Skill 快照保持稳定；不会因插件热更新偷偷改写已发送上下文，从而保护 Provider 前缀缓存。
- Provider 和插件经注册表发现，核心依赖稳定接口而非具体厂商。
- Profile/会话数据隔离思路用于本项目 Preview 数据根、Provider 密钥引用和未来多工作区。

不采纳：

- 不使用 Hermes 作为后台服务，不复制其 Python CLI、Gateway 或数据库。
- 不开放未经审核的任意 Python/Node 插件执行；本轮只实现声明式外部清单与项目内置工具能力。

## DeepSeek：Provider 与缓存合同

官方资料：

- Chat Completions: <https://api-docs.deepseek.com/api/create-chat-completion/>
- Context caching: <https://api-docs.deepseek.com/guides/kv_cache/>
- Models: <https://api-docs.deepseek.com/api/list-models/>
- Rate limit and isolation: <https://api-docs.deepseek.com/quick_start/rate_limit/>

采纳：

- 使用 `https://api.deepseek.com` 的 OpenAI 格式边界，但保留 DeepSeek 原生适配器，不把缓存、reasoning 和错误语义抹平。
- 流式请求设置 usage 回传；SSE 文本增量实时展示，最终 usage 记录 input、cache hit、cache miss、output、reasoning 与 total。
- 缓存只依赖从第 0 个 token 开始的稳定公共前缀，因此请求顺序固定为 system -> tool schemas -> project instructions -> enabled skill snapshot -> conversation history -> current turn。
- 模型通过 `/models` 发现，不把已废止的历史模型名作为唯一真源。每个会话使用不含隐私的稳定本地标识作为 Provider 隔离提示；真实键仅在主进程使用。
- SSE keep-alive 注释和空内容不生成 UI 消息；401、402、429、5xx 分层显示，取消由 `AbortSignal` 贯穿。

## DeepSeek Harness：能力组合与高效工具编排

官方资料：

- Repository/README: <https://github.com/deepseek-ai/deepseek-harness>
- Architecture: <https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md>
- Tool pipeline: <https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/tool-execution-pipeline.zh.md>
- License: <https://github.com/deepseek-ai/deepseek-harness/blob/master/LICENSE>

采纳：

- 插件树的能力可组合思想改写成 Viniper 的 `CompositionPlan`：显式声明依赖、冲突、作用域、顺序和 disposer，并给普通用户呈现为能力方案。
- 每个 run 使用统一 `FrozenRunContext` 固定 Provider/model、工具、Skill、扩展、权限、项目指令与缓存身份；运行中更新只影响下一次 run。
- typed lifecycle、steer/inject、Code Mode、窄 LSP、workflow/subagent、append-only event 与投影分离分别融合到现有 Runtime、ToolRegistry、SQLite、CoordinationService 和项目索引。
- Code Mode 的每个 SDK 子调用重新进入统一权限、资源锁、工具流水线和审计；worker 只做故障隔离，不冒充 OS 安全边界。

不采纳：

- 不引入 Cordis 或上游 219 个包作为运行内核，不复制第二 Runtime、第二数据库或第二 Agent loop。
- 不采纳 Creator/Cordis 的运行时自修改；模型只能提出下次运行草案，用户确认前对当前方案和源码零写入。
- 不复制上游 UI、品牌或原始 JSONL 真源；Viniper 保持 Cyan Plotter Rail、SQLite 与自己的 Provider/权限合同。

```text
       -> ModelCatalogService (authoritative refresh/availability)

  -> Electron window/IPC

  -> platform updater/install bridge (target)

```

## 缓存命中规则

1. Provider、模型、system、工具 schema、项目指令、启用 Skill 集形成 `ContextProfile`；只在会话空闲时切换。
2. `ContextProfile` 内容使用确定顺序和稳定序列化；动态时间、随机 ID、Token 统计和当前目录扫描结果不塞入稳定前缀。
3. 会话原始历史只追加并永久保留；上下文压缩由 Runtime 静默执行，但仍形成可审计的摘要事件和新 profile generation，原始轮次不删除。
4. 跨会话协作只把结构化摘要投递给目标，不共享完整私有历史。
5. UI 同时展示本地“预计可复用前缀”和 Provider 最终 `prompt_cache_hit_tokens`；两者名称与数值不混用。

## 2026-08-13 后续目标补充

- ADR-0032 将后续正式数据真源确定为 SQLite 结构化状态 + 受管文件产物；现有 `sessions.json + events.ndjson` 仍是当前实现事实，必须经本次迁移的一次性回滚副本、可重复导入和关联验证后才能切换。
- ADR-0033 与 ADR-0034 把隔离编程交付收敛为“满足条件后一个可读任务提交 -> 独立合并 -> 干净现场回收 -> 七天恢复记录”；共享目录无用户明确要求时不自动提交，任何不确定成果不自动删除。
- ADR-0035 保留本地确定性路由，启用智能分配后默认均衡并可按任务切换质量优先/均衡/轻量优先；能力硬条件始终优先，ADR-0059 禁止价格信号。
- ADR-0036 开放公共市场、公开直链、自定义来源和本地包，不照搬单一厂商的封闭插件目录；获取与发现不执行代码，显式信任和 ADR-0029 的受管进程边界继续生效。
- ADR-0037 为项目/个人记忆增加“可能过时”复核状态；默认 90 天检查、冲突立即标记、暂停自动注入但绝不自动删除，避免缓存稳定性建立在无声过期信息上。
- ADR-0038 要求会话永久保留在主列表直至用户手动删除；大列表依靠 SQLite 摘要索引、搜索/筛选和虚拟滚动，不引入自动归档。
- ADR-0039 明确不提供周期性、滚动或云端自动备份；迁移/schema 重写的一次性回滚副本属于维护事务条件，不是常规恢复服务。
- ADR-0040 在模型上下文接近容量阈值时静默生成摘要检查点，后续请求用摘要替代较早轮次；原始历史保持不变，摘要生成仍计入 usage 并换代缓存身份。
- ADR-0041/0059 只保留 Token/缓存统计与 Provider usage 对账，不维护价格、金额或 Harness 预算提醒线/硬停止线；外部配额及可靠性轮次/并发边界继续生效。
- ADR-0042 允许新 Runtime 所有者从持久化检查点自动恢复，并重放结果未知的 Provider/工具步骤；已确认成功步骤跳过，电脑完全访问失效仍等待重新授权。
- ADR-0043 把应用更新收敛为“官方渠道自动检查/下载 + 用户确认安装重启”，与开放插件市场分离，也不把更新器暴露为 Agent 自修改工具。
- ADR-0044 把数据可携带能力收敛为手动完整非秘密归档 + 会话/项目选择性导出，导入先暂存、验证和预览再合并；它不是自动备份，普通归档不包含凭据。
- ADR-0045 为项目/个人记忆增加可调软容量提醒，只帮助用户查看占用和选择处理；任何阈值都不阻断保存或自动删除。
- ADR-0046 把远程诊断限制为默认关闭的匿名崩溃/性能字段白名单；用户主动开启并可预览真实 payload，usage 账本不因名称相近而自动外传。
- ADR-0047 要求 Skill、MCP 和插件每次更新都由用户确认，纯文本 Skill 也不静默替换；能力变化继续触发重新信任，活动 run 保持版本快照。
- ADR-0048 让 Provider 默认走系统网络，并允许按 profile 覆盖代理与自定义 CA；凭据进入平台 Vault，不提供关闭 TLS 验证，也不把 Provider 代理扩大到更新、市场或诊断流量。
- ADR-0049 把 Gemini 服务端状态默认关闭，本地结构化历史继续是权威真源；只有 profile 显式开启且端点能力已证明时才续接服务端交互，关闭不冒充远程删除。
- ADR-0050 把普通产品收敛为每台设备、每个系统用户一个本地默认身份和数据根，不建立账号、云端或局域网同步；普通数据通过 ADR-0044 手动迁移，portable 秘密通过 ADR-0057 独立密钥包迁移，导入副本各自演进。
- ADR-0051 为每个自动任务保存 IANA 时区，并明确每日/每周墙上时间、间隔经过时长、春季缺口顺延一次、秋季重复时间只执行一次及跨设备未来触发预览。
- ADR-0052 把正式成果、审计和完整工具输出列为用户明确删除前永久保留；只有登记为可再生成的缓存/临时构建物可按默认 30 天周期清理，并允许 7/30/90 天或永不清理。
- ADR-0053 对有权威发现接口的 profile 自动刷新模型目录；只有完整成功列表才能移除模型，消失模型立即退出未来选择但不改活动 run 和历史，刷新失败不清空目录。
- ADR-0054 把完整工具输出流式保存到受管文件，SQLite 只保存摘要、状态和引用；`ToolResultProjector` 向模型提供有界片段与受控续读，界面仍可查看完整证据。
- ADR-0055 使用应用内事件作为权威状态，只把完成、失败、等待处理、委派和自动任务结果投递为系统通知；声音默认关闭、锁屏默认隐藏敏感正文，Runtime 退出后不保留守护进程。
- ADR-0056 只为用户明确项目建立本地增量索引，状态不可靠时退回同一项目内的实时搜索；索引是可再生成产物，不扫描整台电脑或上传全量正文。
- ADR-0057 在普通非秘密归档之外增加独立密码加密密钥包，只允许 portable Vault 秘密，导入先验证和无值预览，错误不改本机凭据。
- ADR-0058 保持云端 API 为默认主路径，同时允许已有兼容端点和用户明确下载的受管本地运行器；主包不带权重，运行器只监听本机，云端失败不自动切本地。
- ADR-0059 彻底取消模型价格、币种、金额、余额和费用估算；usage 只保存 Token、缓存、请求与耗时，智能路由把“节省”改为不承诺价格的“轻量优先”。
- ADR-0060 让每个扩展正常保留 current 与一个 previous，更新与回退都需用户确认，活动 run 的冻结版本优先保留。
- ADR-0061 将本地日志收敛为默认无正文结构化事件和按单次 run 开启的详细诊断；详细日志仍过滤秘密、不复制完整工具输出且不会自动上传。
- ADR-0062 让 `LocalModelSourceRegistry` 同时支持内置已知来源、本地文件和自定义来源，并把来源、许可、体积、格式与兼容信息作为取得前的可见合同；本地导入默认复制到受管模型库且不改原文件。
- ADR-0063 让 `LocalModelVersionManager` 只发现和提醒更新；下载新版本、验证与未来 run 切换分开确认，旧版本保留到用户主动删除。
- ADR-0064 把本地工具能力显式分为原生、实验提示词模拟和无工具；模拟层只产生候选工具请求，真实执行继续经过统一 ToolRegistry、参数校验、权限和审计。
- ADR-0065 在全局 run 并发之外增加共享 `LocalInferenceCapacity`：默认单路，根据本机资源给出建议，用户可提高但桌面与 CLI 仍共用同一 Runtime 名额。
- ADR-0066 为 `ProjectSearchService` 增加按项目可选的完全本地语义索引，词法/路径/符号保持基础真源，混合结果保留可解释来源并在语义层失败时降级。
- ADR-0067 让 `ProjectIndexService` 统一调度基础与语义索引，以低优先级、检查点和资源感知节流运行；前台 Agent、构建和本地推理优先。
- 以上均是产品目标，不是当前 v0.3 执行合同授权，也没有改变现有 Windows/macOS 证据等级。

## 当前边界

- 本轮可以证明本地并行、协作、Token 账本、应用运行时调度、Skill 渐进加载、内置插件能力、加密密钥存取边界和 DeepSeek 适配器的本地假服务合同。
- 在用户通过应用设置重新输入密钥并单独发起连接/生成测试前，真实 DeepSeek 鉴权、模型权限、内容质量和 Provider usage 均为 `UNPROVEN`；Viniper 不查询余额或计算账单。
