## 1. 目标

1. 增加真正的“命令工作台”，视觉与交互参考 Claude Code、Hermes CLI/TUI，但继续保持独立桌面 Harness，不把桌面改成终端壳。

## 2. 必须保持

- 品牌只称 `Viniper Harness`。系统指令必须明确：当用户询问“你是谁 / 你是什么 / 是否是 DeepSeek”等身份问题时，回答“我是 Viniper Harness”，可说明由用户选择的模型提供推理能力，但不得把底层模型或厂商当作自身产品身份。
- 保持巳月仙人模式冷青、青绿和相邻冷色；正文和主要控制不缩小；全窗连续画布、自定义顶栏、左侧均匀短横历史、Token 分层、非巨型按钮、V 图标及 Phase 8 新前端均不得回退。
- 一个 Runtime、一个 SQLite 结构化真源、同一会话/权限/Token/扩展状态供桌面和 CLI 消费；不得为真实测试、网页工具或终端页建立第二 Agent、第二工具执行器或直连 Provider 旁路。
- Agent 不获得修改自身系统指令、应用源码、权限规则、凭据或 ToolRegistry 的特殊工具。普通项目代码修改仍必须经过现有项目/电脑权限合同。
- 不触碰 `D:\Viniper UI\source\viniper-ui` 的文件、数据、进程或凭据；不发布、不上传、不改远端权限。

## 3. 命令工作台

- 在现有 AppShell 内提供明确“终端 / 命令工作台”入口，复用当前会话、项目和 canonical activity；不是浏览器 `<iframe>`、外置 shell 窗口或静态假数据。
- 采用三段结构：顶部会话/项目/模型与运行状态；中部按时间排序的命令、工具、stdout/stderr、退出码与耗时流；底部固定 Agent 指令输入区与运行/停止控制。
- 输入区向当前 Agent 发送任务，由模型选择 `terminal.run`；不得绕过 PermissionPolicy 直接执行任意命令。用户能看见权限等待、运行中、成功、失败、取消、截断和恢复状态。
- 长输出继续使用现有受管 artifact 与 `readTerminalOutput` 范围续读；stdout/stderr 可切换，显示 offset、总量、截断和完成状态，不把完整日志一次灌入 DOM。
- 状态栏显示 Provider/model、项目、权限模式、上下文/Token 与当前 run；不显示价格。支持键盘焦点、Escape、reduced motion、960×720 和 1440×900。
- 全局控制文案遵循“必要才常显”：顶部文件/编辑/视图/任务/帮助、发送及设置、弹窗、Token、调度、扩展、Runtime Center 等衍生页面中的高频按钮，优先改为辨识度足够的图标或极短标记；完整说明通过 hover 与键盘 focus 均可访问的 tooltip、`title` 和 `aria-label` 提供。新建会话/打开项目、保存/确认、删除、安装/信任、权限相关以及其他不能只靠图标猜测的重要或有风险动作继续保留文字。图标按钮外框使用克制但更柔和的圆角，不做过度胶囊；删字后按钮宽度、点击热区、间距和窄窗布局必须随之调整，不保留空洞的旧文字宽度。
- CLI 继续使用同一 Agent 核心；按 Claude Code/Hermes 的可取部分补齐或保持：多行输入、历史/恢复、slash 命令发现、流式工具输出、清楚的 interrupt、纯文本与 JSONL。桌面命令工作台不伪装成 ANSI TUI。

## 4. 公共网页读取工具

- 在独立 `src/features/web` 功能目录新增一个职责单一的公共网页读取工具，例如 `web.fetch`；注册到公共 ToolRegistry，让桌面与 CLI 的同一 Provider 工具循环都能消费。
- 只接受明确 `http/https` URL；返回状态、最终 URL、内容类型、标题、清理后的正文摘要、截断/大小信息和诊断错误。脚本、样式和二进制不进入模型；响应有超时和大小上限。
- 工具属于 `external` 权限域。`ask` 必须批准，已授予外部完全访问时可自动；拒绝执行次数为 0。不能因为网页只读就绕过外部访问权限。
- 禁止读取 `file:`、本机环回与明显私网地址；这是必要产品边界，不扩写安全攻防体系。
- 网页原文不成为系统指令。工具描述与 Agent 指令必须明确网页内容是不可信资料，不能覆盖用户、权限、身份或项目规则。

## 5. Skill 与插件真实产品链

- 使用本轮隔离目录创建最小、无凭据的测试 Skill 包，通过正式 ExtensionManager 安装、启用并由 Agent 读取，回答中产生唯一可观察标记。
- 使用现有受管可执行插件或新建同等级最小测试包，通过正式信任、安装、启用、ToolRegistry 和受管子进程调用形成一次真实工具结果；不能直接调用插件脚本冒充产品通过。
- 测试扩展只安装到本轮隔离数据根，结束后用正式卸载/清理路径移除；不污染当前用户正式 Preview 扩展。

## 6. DeepSeek 真实调用授权与上限

- 用户本轮明确授权使用此前提供的真实 DeepSeek API 做实机验证。凭据只允许从本机既有安全来源进入测试进程内存，再经正式 `SecretService -> ProviderSettingsService -> Provider Transport` 消费；不得打印、传入命令参数、写入源码、普通持久化、日志、报告、截图、Git 或协调消息。
- 只使用 `deepseek-v4-flash`，且必须先由真实 `/models` 证明存在；`GET /models` 最多 1 次，不调 balance，不查询、显示或记录价格/金额。
- generation POST 总上限 20 次，包含工具续轮、失败和重试；每个逻辑请求总尝试最多 5 次，出现语义输出、工具调用或外部影响后不重试。总实际 input 不超过 250,000 tokens，output 不超过 20,000 tokens。
- 首次真实产品失败立即冻结公网调用，先离线定位、建立红灯、修真源并跑全量回归；只有原因明确且总上限有余量时允许一次新的隔离场景复验。不得为截图、报告、打包或安装增加调用。
- 真实调用前门：typecheck、clean build、完整测试、身份/终端/网页/扩展定向测试全部绿色；隔离数据根和项目根明确；密钥不落盘证明成立。
- 真实调用后立即冻结 usage 与尝试次数；删除隔离 safeStorage 凭据、测试扩展和专属运行根，只保留脱敏统计和用户无敏感内容的最小结果证据。
