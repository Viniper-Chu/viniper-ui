# 本机小任务

使用当前 Agent 已提供的文件、终端和技能工具，不调用另一个 Agent 充当后台。已有目标、操作和保留要求足够时直接执行；只在缺少决定性信息时提问。

- 文件：保留用户给出的中文路径和目录层级。只有用户提供或工具返回的完整实际路径才能跳过定位，否则先在指定目录 list/search 确认完整文件名；不能自行删去中文修饰词或目录层级。局部修改只读相关行，用精确替换或补丁。新建直接写入，整文件覆盖须先读全。读结果出现截断时按回执续读，不猜未显示部分。
- 代码：读目标函数及必要调用处，完成最小改动后运行对应检查。零值、空输入、缺省字段等相关边界放在一次验证中；已有通过结果且代码未变时不重复跑。Python 文件名含空格、连字符或不是合法模块名时，用 `runpy.run_path(实际路径)` 取函数执行，不把文件名拼入 import。
- SQLite：先看表结构和目标行，用参数化 SQL 在一个事务内更新；同一次本地执行读回目标与应保持不变的行。工具成功与数据符合要求分别核对。
- Word、PDF、表格：先使用当前环境已有的对应技能或解析工具；不能当 UTF-8 文本覆盖。格式变化需要打开或渲染核对。
- 数学原解：用户要参考已有资料时，优先现有本地检索或指定原件，逐项核对数字、符号、条件和图。保留原解步骤并注明文件出处；检索命中不是模型独立推理的证明。

工具名称与参数以当前环境描述为准。Viniper 的 `file.read` 可传 `startLine`、`lineCount`；截断回执的 `nextOffset` 作为下一次 `offset`。Hermes/Codex 使用各自的分段读取与补丁工具即可。

当前工具列表有 `file.docx.inspect` / `file.docx.replace` 时，处理 DOCX 先用 `file.docx.inspect` 获取段落、样式、表格和 run 位置。段落索引从 0 开始且包含标题，不能直接把正文序号减一；依据 `style_id` 与实际文字定位。普通局部替换优先 `file.docx.replace`，传完整原段落 `expect` 和 `old_text` / `new_text`，由工具保留各片段格式；跨不同格式且非等长、工具明确要求映射时才用高级 `file.docx.edit`。不能把跨多个 run 的整词塞进一个 run。工具已回读的结果无需重复拆包核验；简短报告只说明目标文字和实际结果。没有这些专用工具的 Agent 使用当前环境已有的 DOCX helper JSON stdin 入口，按其真实说明传递参数；不能因为模型显示名为 Viniper 27B 就假定 Agent 提供了 Viniper 工具。

Viniper 的 `file.sqlite.inspect`、`file.sqlite.query`、`file.sqlite.apply` 直接接收结构化参数。apply 的每组 statements 是独立事务，queries 在事务全部结束后读取已提交结果。**要求同一事务内读取并据结果决定提交时，使用普通 sqlite3 脚本，在同一个连接中 BEGIN、修改、查询、COMMIT**。部分事务已提交但回读失败时只修正查询，不能重放已提交事务。Hermes/Codex 通过现有 SQLite helper 或 sqlite3 使用相同语义；传入引号、美元符号、反引号须保留原值，不做 shell 或 SQL 字符串拼接。

完成时给出实际改动、可点击文件入口和验证结果。失败先依据错误修正后再试；未执行的步骤保留待完成，不用增加无关扫描、重复规划或哈希检查替代结果。
